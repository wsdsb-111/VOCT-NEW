# V8.4 Luna 世界线前端实施报告

本轮依据《VOTC V8 总路线（V8.4 起，探索验证后重规划版）》和《VOTC V8.4 正式开发设计文档（模型分工与世界线前端重构版）》实施 Luna 阶段。范围严格限定为前端页面、前端状态模型、Supplemental 编辑器和 Terra IPC 调用预留；不提前实现 Terra 的 CK3 Save Reader、Container Parser、Worker、Gamestate Adapter、Live Probe、Annual Delta Merger 或生产 Prompt/Memory 接入。

## 已交付

- 在现有配置面板增加“世界线”入口，复用当前打包 Renderer 的导航和滚动容器，不创建新的 BrowserWindow。
- 增加年度存档来源区：`autosave.ck3` 路径、选择文件、校验路径、重新加载、打开诊断、文件/容器/日期/解析状态等字段。
- 增加检查点指标区：Game Date、Total Days、Container、File Size、Characters、Titles、Active Wars、Historical Bindings 和解析耗时。
- 增加五个只读展示页签：世界概览、年度变化、世界知识、历史人物身份、诊断。
- 增加 Game Truth / Supplemental / Player Canon 来源标识；未获得 Terra 数据时显示空状态和 `—`，不生成虚假的人物、头衔、战争或历史绑定。
- 增加会话级 Supplemental 编辑器，支持标题、正文、游戏日期、日期区间、实体、可见性、重要性以及添加、更新、隐藏、删除；提交 payload 明确标记 `source=PLAYER_CANON`、`scope=SESSION`、`checkpointScope=CURRENT_CHECKPOINT`。
- 前端只通过可选 `window.worldlineAPI` 调用 Terra 合同方法，包括 settings、autosave 校验、checkpoint、overview、annual delta、world knowledge、historical bindings、diagnostics 和 Supplemental CRUD。
- Terra 方法不存在时，页面安全降级为 Luna 预览；Terra 方法存在但调用失败时不伪造本地成功结果，以刷新后的 Terra 状态为准。
- 新增 `scripts/test-v8.4-luna-worldline-ui.js`，并登记到 `scripts/test-manifest.js`，覆盖入口、页面区块、范围标记、IPC 方法和资源加载关系。

## Terra 接入后的当前可见行为

Terra 已提供 Preload、Main IPC 与 World Services。`worldlineAPI` 现在会真实持久化路径、读取支持的存档、显示 Checkpoint/Delta/Live Probe 状态，并把 Supplemental 保存在当前 Checkpoint 范围内；Terra 调用失败时前端仍不伪造成功结果。详细限制与验证见 [V8.4 Terra 世界线运行时实施报告](v8.4-terra-worldline-runtime-implementation-report.md)。

本轮没有修改 CK3 存档、Workshop Mod 或现有 `WorldlineStore`。Terra 另行以默认关闭的方式加入世界知识 Prompt 基础，不改变默认对话路径。
