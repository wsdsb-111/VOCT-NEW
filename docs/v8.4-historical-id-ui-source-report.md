# V8.4 第二轮：Historical ID UI/Debug 来源报告

状态：已完成静态源审计和现有日志核对；未添加 CK3 probe，不宣称实机脚本输出已验收。

## 已确认的 CK3 UI/引擎接口

基础游戏本地化直接引用 Character 的历史 ID getter：

- `game/localization/simp_chinese/core_l_simp_chinese.yml:78`：`[CHARACTER.GetHistoryId]`
- 同文件 debug tooltip 在第 80 行同时显示 `GetID` 与 `GetHistoryId`。
- 英文 `core_l_english.yml` 也使用相同 getter。

基础游戏本地化还使用 `GetScriptedCharacterByHistoryID('...')` 通过历史 ID 取 Character。`game/common/bookmarks/bookmarks/_bookmarks.info` 对 `history_id` 的说明是“Which historical character ID this bookmark corresponds to”。辛弃疾的 `bookmark_china_1178_xin_qiji` 与相关 portrait 文件进一步把 `han_12371` 标为 History database id。

这说明 UI 的 Historical ID 是 CK3 Character 数据模型暴露的引擎属性，不是 VOTC 从 `first_name` 或 save 文本猜出来的字段。

## 日志实证

当前 `E:\Documents\Paradox Interactive\Crusader Kings III\logs\debug.log` 出现过：

```text
character_window.cpp:1010: Open character '... (Internal ID: 97681 - Historical ID 206656)'
```

该行确认 CK3 Character Window 在打开人物时能同时写出 Runtime/Internal ID 与 Historical ID。另一些人物只输出 Internal ID，表明日志格式会按人物是否具有可输出历史 ID 而变化。

这是 CK3 可执行程序的引擎日志来源，不是可在仓库中编辑的 GUI 脚本；本轮不把该行错误归因到 VOTC。

## VOTC 当前 probe 能力

VOTC 2.0.5 的 `common/scripted_effects/log_character_v2_effect.txt` 当前通过 `[THIS.Char.GetID]` 和其他 Character getter 记录运行时数据；`log_gamedata_v3_effect.txt` 输出人物 ID、姓名、当前日期、位置与 Campaign token。静态检索没有发现 VOTC 已输出 `[THIS.Char.GetHistoryId]` 的路径。

因此：

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| CK3 UI 显示 Historical ID | `CONFIRMED` | 本地化 getter 和 `character_window.cpp` 日志均有直接证据 |
| CK3 通过历史 ID 反查人物 | `CONFIRMED` | 存在 `GetScriptedCharacterByHistoryID` 的基础游戏用例 |
| VOTC 在脚本 debug_log 中读取 Historical ID | `PARTIAL` | getter 名称已被基础游戏使用，但 VOTC 尚未做临时实机 probe |
| 从 save Character record 读取 `historical_id` 字段 | `NOT_FOUND` | `autosave_1.ck3` 人物对象未出现该字段 |
| 仅用 `character_lookup` 覆盖所有人物 | `NOT_FOUND` | 辛弃疾、随机 NPC、玩家子女控制样本均无反向条目 |

## 推荐的下一步临时 probe（不在本轮执行）

在用户明确允许实机探针后，使用 VOTC 当前已有 `log_character_v2` 触发点增加一条临时、debug-only、可回滚的 `[THIS.Char.GetHistoryId]` 输出，至少采集：

1. 一个 bookmark 历史人物；
2. 一个当前存活的 Mod 历史人物；
3. 一个随机 NPC；
4. 一个玩家子女；
5. 一个事件创建人物。

然后将 CK3 日志的 `(Internal ID, Historical ID)` 与同一时间点的 GameState snapshot 对齐。没有这组实机证据前，V8.4 不能把 UI getter 当作稳定的全量 save adapter 输入。
