# V8.5 Luna 玩家语义展示层实施报告

## 实施状态

V8.5 的 Luna 阶段已完成前端玩家语义展示层实现。Terra 已完成 Query Planner、DTO、Ranker、Cache 和 additive `playerView` 接续；本报告保留 Luna 的历史实施范围，不代表 V8.5 整体完成或 Prompt Default On 已开启。

## 本阶段范围

本阶段严格限制在 Renderer 展示边界：

- 新增 `worldline-player-presentation.js`，把来源、检查点新鲜度、身份状态、来源冲突、知识可见性、重要性、年度事件和历史人物映射转换为玩家可读文案。
- 世界线默认页改为玩家语义视图：顶部突出年度存档、存档日期、当前游戏日期、世界线状态和最后读取；完整路径、检查点 ID、容器、文件大小、解析计数等移入高级信息。
- 世界概览、年度变化、世界知识和历史人物页签消费统一的展示 helper，默认视图不再把 `Game Truth`、`Supplemental`、内部状态枚举或 Runtime/Definition/Raw ID 当作玩家文案。
- 诊断页保留摘要优先的默认结构；Resolver、原始匹配、Token Breakdown、缓存和裁剪项继续在高级诊断区域可追溯。
- 保留本地化冲突的全部可读候选，不猜测唯一名称；不确定的战争消失事件继续显示“待核实”，不伪造结束时间或结果。
- `index.html` 先加载展示 helper，再加载既有 Renderer bundle；本阶段没有改动 Terra 的 IPC、Prompt、缓存或 Game Truth 生产逻辑。

## 交接边界

Terra 已在此基础上完成：

- 玩家 DTO 是否稳定提供展示层所需的语义字段，并继续隔离 rawKey、runtimeId、definitionId 和 resolver 实现细节。
- Query/Ranker/Cache/IPC 是否与当前展示 helper 的来源、freshness、identity 和 unknown 语义一致。
- 真实 `autosave_1.ck3` 与 Provider/Cache 运行链路是否不会把高级诊断字段误注入默认 Prompt 或默认 UI，仍待实机确认。

Sol/Astra 阶段仍需独立审查 P0 正确性、跨页合同、回退安全和发布门禁。真实 Electron 视觉 smoke、CK3 存档读取、实时日期、Provider 与缓存行为尚未在本阶段宣称通过。
