# V8.4 Terra 世界线运行时实施报告

本轮把既有“世界线”页面接到真实主进程链路，交付年度 Checkpoint、受限 Save Reader、Worker 解析、GameState 索引、Live Probe、年度 Delta、Supplemental 持久化和可选的对话世界知识基础。

## 已实现

- 仅 `autosave.ck3` 可成为自动监听的年度来源；其它 `.ck3` 文件明确标记为 `NOT_AUTOSAVE`，仍可人工诊断读取。
- 读取 `SAV` header，支持 plain-text 与 unified text ZIP 的 `gamestate`；binary、未知或不受支持容器不按文本猜测解析。
- 存档 I/O 与解析在 Node Worker 中完成；主进程只接收有界 normalized snapshot，不保留完整 GameState AST。
- Snapshot 提供角色、同名候选数组、`character_lookup` 正反向映射、头衔/历史和活跃战争索引。
- Checkpoint 先在 Worker 构建，再原子替换；新读取、稳定性或解析失败时继续保留旧 Checkpoint。
- Delta 规则：死亡、带窗口日期证据的开战、带 title history 的 holder 变更标为 `GAMESTATE`；消失的 active war 与无 history 的 holder 变更提升为 `SUPPLEMENTAL`，不伪造 CK3 事实。
- `VOTC:TEST_CHAR` 从 CK3 `debug.log` 被动读取，用 `Character.GetHistoryId` 对 direct binding 做 live confirmation；空 History ID 保持合法。
- Supplemental/Player Canon 落盘于 `worldline-v8.4`，按当前 Checkpoint 隔离，不能覆盖 Game Truth；真实 Branch Identity 仍标记为未知。
- Preload 和 `worldline:*` IPC 完成 Luna 已使用的全部接口，文件选择在主进程完成。
- 世界知识 Prompt 基础已接入 Conversation/PromptBuilder，但 `promptIntegrationEnabled` 默认 `false`。启用后才生成 stable checkpoint、topic/supplemental 与 current-world 三类块；失败则回退到原 Personal Memory 路径。

## 明确限制

- Historical Definition Catalog 的 base/mod 全量扫描、active playset 覆盖 winner 和 duplicate source rows 仍是独立的前置 Gate；本运行时只将 save 的 `character_lookup` 作为 direct evidence，不以姓名、年龄或出生日期猜测身份。
- split、binary、Ironman 存档保持不支持或不可读状态；不会降级为文本解析。
- 未获得 Save A/B Gate 前，`playthrough_id` 只作为 Campaign candidate，Supplemental 也不承诺跨分支迁移。
- 没有把世界知识 Prompt 开关设为默认开启；正式开启仍需 Sol 对真实 CK3、Provider 与 Cache 行为审查。
