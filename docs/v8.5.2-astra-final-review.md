## 本轮修复

生产改动集中于 `resources/app/out/main/worldline/shared-query-analyzer.js`：

1. 混合查询在存档只索引“思昭”时，会把“赵思昭”中交叉重叠的“赵思”额外识别为历史人物。现在移除跨越 Runtime 姓名区间的历史前缀；另一处独立提及“赵思”仍保留。历史全名与 Runtime 名称同结尾时不因该规则被排除。
2. 历史定义存在、当前存档无角色的逐实体 DTO 曾降级为 `NO_MATCH`；现保留 `DEFINITION_FOUND_RUNTIME_MISSING`。
3. 原生姓名命中时，历史索引未命中曾形成额外 UNKNOWN 实体；现在只去除重复 Domain 实体，保留兼容 `historicalCoverage` 诊断字段及来源不完整告警。没有放宽 Runtime-native 或 Historical 确认条件。

回归位于 `scripts/test-v8.5.2-long-historical-name.js`、`scripts/test-v8.5.2-sol-safety.js` 和已有 Sol safety 文件；最初的复现失败后再修复，完整发布回归最终通过。

## 补充知识：当前已实现什么

已经接通 Renderer → preload → IPC → WorldlineService → 磁盘存储 → 检索 → Prompt 上下文入口，并非仅有界面。

- 新增、编辑、隐藏、删除，以及 `worldline-v8.4/supplemental.json` 原子持久化已实现。
- 当前只展示/召回当前 checkpoint 的条目。磁盘持久化不等于跨年度、跨检查点自动继承。
- 召回需要内容相关、通过日期与预算过滤，TopK=3；只有未隐藏的 `PUBLIC_WORLD` 进入公共召回。其他可见性可存储，但不会因此成为所有 NPC 的知识。
- 时间过滤以 checkpoint 日期为界，不是 Live 日期。
- 三份真实 snapshot 均验证公开召回、隐藏/SECRET 排除、磁盘重新加载、checkpoint 隔离及删除。
- 隔离 Electron 实际 IPC 已验证公开条目创建、诊断命中、隐藏后排除和删除；测试数据只写临时目录。

正式用户配置只读核对结果：`promptIntegrationEnabled=false`，`autoWatchEnabled=true`。没有读取输出 API 密钥，也没有修改这些值。因此当前新增内容不会自动传给正常 NPC 对话；“运行诊断”有专用只读通道，不会开启生产开关。

开关即使启用，仍需有效年度路径、ACTIVE checkpoint、新鲜度、可见性及相关性等门禁。Conversation 的 `worldSupplementalText` 到 PromptBuilder 的入口已存在，但本轮没有启用它或声称实际模型已经遵守补充知识。

按用户提供的 V8.4 起重规划路线：V8.6 是 Character Knowledge、角色主观知情与隐私语义；V8.7 才是长期 Supplemental World Memory / Player Canon 及分支安全编辑。因此当前是检查点内补充知识基础版，不是完整的长期世界设定记忆。
