# V8.5.2 Terra Stage 2：Runtime Identity、差异数据与通用映射实施报告

## 已实现

- `Shared Query Analyzer` 新增 additive `entityResolutions`。每项都含 `identityKind`、`resolutionStatus`、主体名、候选数、历史 Definition / Runtime ID、证据、来源/候选完整性和 `worldlineDifferences`；既有 `identityResolution`、coverage、候选和诊断字段保持兼容。
- 当前存档中无 Historical Definition ID 的唯一全名返回 `RUNTIME_NATIVE / RESOLVED`；同名多 Runtime 返回 `RUNTIME_NATIVE / AMBIGUOUS`，只列候选，不写入 Game Truth。历史绑定的中文姓名仍只能走 Sol Stage 1 的完整身份 Gate。
- 历史身份的年龄、父母、配偶和子女差异仅作为 `AGE_WORLDLINE_SHIFT`、`FATHER_DIFFERENT`、`MOTHER_DIFFERENT`、`SPOUSE_DIFFERENT`、`CHILDREN_DIFFERENT` 的 INFO/NOTICE 诊断，不改变身份结论。静态来源没有可验证基线时不制造差异。
- Historical Definition Index 的姓名构造不再把复姓限定为一字；汉、契丹、女真等可验证姓前文化只要 given name 与 dynasty/house 的简中本地化链均唯一，就构造可搜索全名。未知文化不假定姓前顺序。索引策略版本升至 `v8.5.2-historical-index-4`，已缓存的旧构造会在下次准备时换代。
- Historical Mapping 按“已验证 Index 名称 → 可读 Runtime 名称 → curated alias → 名称未解析”输出；仅被索引、但当前存档未绑定 Runtime 的人物显示为“当前存档未找到”，不泄漏 raw key。
- 保留旧的非 CJK Runtime alias 兼容召回；它不产生 native 身份结论，也不放宽中文历史姓名的 fail-closed Gate。
