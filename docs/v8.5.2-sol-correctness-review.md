# V8.5.2 Sol Stage 3：后端正确性独立审查

## 审查结论

**CODE REVIEW PASS**

Sol 已独立复核 Historical Identity Gate、Runtime-native 分流、Numeric Namespace、来源完整性优先级、Domain DTO 边界和 False Resolution 矩阵。审查发现的 P0/P1 已修复，完整发布回归通过。该结论不等于 `INTERNAL FREEZE`；最终冻结仍由 Astra 在 Stage 6 给出。

## 已修复问题

### P0：诊断 DTO 携带完整检查点

Terra 为计算 `worldlineDifferences`，曾把 `snapshot` 与 `definitionRecords` 临时挂入历史解析结果；兼容字段 `identityResolution` 在人物解析成功时会直接引用该对象。这样会把整份检查点经 IPC 序列化给 Renderer，人物规模较大时可能造成世界线诊断白屏、卡死或长时间无响应。

现已将检查点和 Definition 记录限制在 `historicalEntity()` 内部计算参数中，公开 DTO 只保留合同规定的紧凑字段。回归断言覆盖：

- `identityResolution` 不含 `snapshot` / `definitionRecords`；
- 200 KB 哨兵数据不会出现在诊断结果；
- 单实体诊断序列化体积保持有界；
- `worldlineDifferences` 与 `identityEvidence` 继续分层。

### P1：Runtime 姓名扫描截断仍可能部分注入

Runtime Scanner 命中超过 32 个实体或输入超过 3,000 字符时，旧路径仍可能把前 32 个结果作为完整结果处理。现已将其标记为 `SOURCE_INCOMPLETE / candidateSetComplete=false`，只返回诊断，不写入 resolved characters 或 Game Truth。

### P1：Historical Mapping coverage 不完整

Historical Definition 已找到、但当前检查点没有 Runtime 绑定时，Mapping 现统一返回 `DEFINITION_FOUND_RUNTIME_MISSING`；若来源或候选集合不完整，则 `SOURCE_INCOMPLETE` 保持最高优先级，并同步进入 Player DTO。候选总数使用索引提供的未截断总数，不再被当前页长度覆盖。

### P1：历史姓名展示可能回退到 raw key

Mapping 名称回退现拒绝带 `_`、`:`、`#` 的 CJK raw key，只接受已验证 Index 名称、查询精确命中的已验证名称、唯一已验证名称、可读 Runtime 名称或 curated alias。

## 合同复核

- 年龄、父母、配偶和子女只产生 `INFO / NOTICE` 的 `worldlineDifferences`，不进入 `IDENTITY_CORE`，也不改变 `resolutionStatus`。
- Historical 中文姓名只走完整身份 Gate；Runtime-native 只接受没有任何 Historical Definition 绑定的 Runtime 人物。
- `SOURCE_INCOMPLETE > DEFINITION_FOUND_RUNTIME_MISSING > REJECTED_BY_EVIDENCE > NAME_INDEX_MISS` 已在 Shared Query、Mapping 与 Player DTO 路径保持一致。
- Numeric Runtime Direct 只接受整个明确输入为纯数字或 `#数字`；句中年份不进入 Runtime ID namespace。
- Static Historical Index 与 checkpoint/runtime cache 保持分离；切换检查点不会触发静态历史索引完整重建。
