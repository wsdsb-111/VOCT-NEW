日期：2026-09-27。状态：**核心施工与生产接线完成；后续 [Sol 独立审查](v8.14-a-sol-independent-review.md)发现的 3 项红灯已修并通过本地回归，但 A Gate 尚未验收**。

施工标准为 [Implementation Spec Dual Model](v8.14-memory-engine-4.0-implementation-spec-dual-model.md)，其阶段治理优先于此前 [Revision 3 总体设计](v8.14-memory-engine-4.0-overall-design-revision3.md)。本轮根代理执行核心施工，默认子代理仅做只读链路探索和辅助检查；不得称作 Sol 独立 QA。

## 已实现的确定性基础

- `memory4-contract.js`：独立 schemaVersion 1、Owner/Campaign 门禁、来源片段校验、稳定 Entry ID、六类 Durable 类型、事件时间与对话/获知时间分离。时间只能来自原始可见片段中的确定性时间锚点，或显式 witnessed/game_fact 的当前观察；转述不允许升级成已观察事实。未知时间不自动填成对话日期。
- `memory4-visibility.js`：原始应用层分片输入合同；公开、指定接收者、私人片段与真实在场半开窗口相交。按下述用户确认的策略，逐片段复用可信受众及已有 knownBy 约束，只对未知边界部分回退作者自身视角。partial 允许保存有来源的 Detail 和独立 Known 证据，但零 Detail 不表示整场没有可记内容或双方不认识。
- `memory4-store.js`：在唯一 NPC 摘要目录下，以 Campaign 哈希隔离 sidecar；逐条 JSON 正文、索引与元数据、Known Entity 一起复用现有 summary mutation journal 原子提交。正文先于索引；缺失/损坏索引或正文不静默当成无记录。删除保留 tombstone，标记派生视图 dirty；已提交 finalization 重试不重复写入或复活已删条目。查询按索引筛选后才打开候选正文。
- `conversation.js`：NPC 占位回复和玩家消息新增真实 `speakerCharacterId`，保留既有正文、存储、Prompt 和缓存顺序。
- `memory4-legacy-bridge.js`：只读保留已绑定 Campaign、Owner/knownBy 合法的既有人物摘要，复用双时间索引并保留投影指针/hash；标为 partial / legacy visibility evidence，不强制转成 Detail，不因新 Detail 或空提取而排除旧文档。正式 Recall Planner 接线尚未完成。
- `memory4-coordinator.js`：只在 Narrative commit 后运行逐 Owner Durable 提取；每个 Owner 独立快照、独立失败/重试及已提交幂等。恢复必须匹配当前 Campaign 且确认 Narrative 已提交，不重发 Narrative；清空长期记忆时同步清除未提交 Durable 恢复快照。普通对话允许 `NO_DURABLE_CONTENT`，可确认的共同场景由 Known Entity 独立记录。无 Campaign 则不发起提取。
- `conversation.js`、`memory-engine.js`、`summaries-manager.js`、`main.js`、`provider-service.js`：正式终局、自动恢复和手动重试接入独立的 `memory4_durable` 摘要模型请求，按结构化 JSON 校验；既有 Narrative 成败合同不因 Durable 失败而改写。摘要界面区分 Narrative/Durable 待恢复数量，恢复按钮可用于 Durable-only 失败。MemoryTrace 记录 Owner、状态、Entry 数和可见性完整度，不写正文。
- `test-v8.14-a-durable-core.js`：26 个确定性检查组，已登记到唯一测试清单。涵盖两角色一成功一失败、Campaign 错配、Narrative 门禁、重启后独立恢复、不重复请求已成功 Owner、损坏快照隔离；1000 条夹具查询读取 1 个候选正文；不依赖运行时数据或 API。

Durable 提取**已接入生产终局**，正式 Memory4 Recall **仍关闭**。当前玩家可见 Memory Engine 3.0、Legacy 文件、Recent2/官方追忆/Extra、冻结前缀和预算不变。没有迁移、覆盖或删除真实用户摘要；本轮自动测试未向 Provider 发送请求。真实终局现在会额外调用当前摘要 Provider，按角色提取，可能产生 API 费用。

## 用户已确认的旧数据可见性策略

生产原始消息只有混合文本 `content`；speech/thought/action/recipient 没有可信结构化边界。现有 `summarySegments.visibility` 是摘要模型生成的判断，不是原始消息权限证据。仅靠在场名单会把同一正文中的私密思想暴露给旁观者，不能用这种默认补齐 A 阶段。

用户确认：不能将所有旧消息一刀切为 author-only。优先复用已证明的 knownBy、人物投影、Presence 等确定性证据；仅缺少足够边界证据的部分禁止旁观者生成新 Durable，作者仍可按自身视角提取，不让模型判断旧内容的受众。旧数据保持 partial / legacy visibility evidence，经 Legacy Bridge 保留原召回资格，不强制迁移。Known Entity 独立保留可确认的共同场景和互动。

实现区分：

- 应用层已有明确边界的公开片段继续提供给合法在场者，source/message 的已有 knownBy 只能收窄该授权；明确 known_group 的 knownBy 可作为片段受众，与 Presence 取交集。
- 旧正文作者通过稳定 ID 或唯一精确姓名匹配；同名歧义不猜。只把无边界的部分交给作者本人，标记 self_report / legacy_author_perspective，不能升级成亲历事实。Presence 缺失时不凭全场名单给旁观者正文授权。
- `user_edited_summary` 的实际 `updatedBy=user`、folderOwnerId、knownBy、Campaign、conversation/finalization 对齐后，可作为明确的个人确认投影；不反推原始混合消息全篇公开。普通模型投影的 knownBy 不足以证明原始子片段边界，因此仅保留在 Legacy。没有触发真实用户数据的批量迁移。
- 私密内容/片段缺口不抹除独立的 Presence 共同场景证据；无明确受话对象时不计 directConversation。Known 查询按证据返回 DIRECT_INTERACTION/SHARED_SCENE/MENTION_ONLY，证据不足返回 UNKNOWN/INSUFFICIENT_EVIDENCE，绝不返回“从不认识”。
- partial 的 NO_DURABLE_CONTENT 仅表示本次可授权片段里没有保存 Detail；提交记录保留 completeness、evaluatedFragmentCount、legacyRetained、noDetailIsNotUnknown 等诊断，不宣称整个历史已经完整提取。

生产消息尚无 speech/thought 的可信精细分片来源：无法安全判定的正文仍只交作者自身视角提取，不能凭模型猜测开放给旁观者；这不是对旧消息统一 author-only，因为明确应用分片、手工确认投影和独立 Presence 证据各自保留其合法作用。生产逐人 Provider/恢复已接入；旧数据策略已明确，无需再次请求同一决策。

## 尚未实施／不得宣称完成

1. 原始生产 speech/thought 精细分片缺乏可信结构化来源，实机覆盖和相应分片供给尚待验证；不把整段混合消息默认公开。
2. 完整 Durable 状态更新、来源编辑/删除传播仍未完成；Known Entity 对同一会话来源修订的证据重算已补齐，但不能代表全链路撤销。当前新侧仓 tombstone/dirty 不能代表全链路撤销。
3. Legacy Bridge 部分覆盖映射、删除抑制与现有双时间召回接线属于正式 Recall 阶段，仍未开启。
4. Sol 首轮独立 adversarial/QA 已完成，三项红灯已修；修复后的独立复验及真实 CK3/Provider/打包窗口验证尚未执行，A Gate 不能由实施方本地复测替代。
5. B–E、RC、缓存及 Soak Gate 尚未实施。

当前 tombstone 测试只证明新 sidecar 的提交重试/索引不会复活；尚不能代表 Legacy、对话历史、Year/Life 全链路删除验收。当前 1000 条测试只证明候选正文文件读取有界，不代表完整 Recall Planner 已实现。
