# V8.5 Terra Retrieval 2.0 实施报告

## 实施状态

V8.5 Terra 后端实现已完成，并通过确定性自动化发布门禁。本报告记录已落地的 Query Planner、候选检索与排序、确定性摘要、DTO 隔离和缓存合同；它不等同于 V8.5 实现冻结，不打开 `Prompt Default On`，也不替代真实 CK3、Electron、Provider 或缓存实机验收。

## 本阶段范围

- 新增 `world-query-planner.js`，在一次 Shared Query Analyzer 结果上构造可序列化、确定性的 `WorldQueryPlan`。其意图覆盖人物状态/位置/身份、头衔持有者、领地、战争、近期世界、历史时间点和一般世界查询；显式 `as-of`/区间优先于泛问句分类。
- 新增 `world-retriever.js` 和 `world-ranker.js`。候选与事实严格分离：只有 `RESOLVED` 的人物或头衔可进入 Game Truth；歧义候选只进入诊断。Supplemental 先做 `PUBLIC_WORLD`/hidden 硬过滤，再按查询、实体、时间、重要性和来源确定性排序。
- 年度 Delta 改为 query-aware：实体查询只保留相关 Delta，广义世界查询才允许近期世界变化；省略项具有 `UNRELATED_DELTA`、`VISIBILITY_BLOCKED`、`TEMPORAL_UNSAFE`、`LOW_RANK`、`TOP_K_LIMIT` 或 `TOKEN_BUDGET` 的可审计原因。
- 新增 `world-summary.js`，从已选候选生成确定性世界摘要，不调用模型，也不会把 `WAR_NO_LONGER_ACTIVE` 写成已确认的战争结束时间或结果。
- 新增 `world-presentation.js`，以 additive `playerView` 返回玩家可读的概览、世界知识、年度变化和历史人物展示数据。原有 IPC 名称和 Domain DTO 保持兼容；Prompt DTO 不包含 UI 展示字段。
- Prompt topic cache key 现在包含当前 campaign Delta revision、当前查询相关的 Supplemental revision 和 retrieval policy version，不含 UI 文案。无关 Supplemental 不会使实体主题缓存失效；相关 Supplemental 或当前 campaign Delta 变化会失效。
- Prompt token 预算按查询复杂度限制为简单 350、单实体 550、复杂 900，硬上限 1200；超额时按 Supplemental、Delta、Game Truth 顺序裁剪，并记录原因。

## 未改动边界

- 未改动 Save 容器/Parser、`autosave.ck3` 来源合同、Historical Definition/Runtime ID 权威、Campaign/Branch 协议、Action、Memory 或 Run Command Queue。
- 未改动既有 IPC/preload 方法名；`playerView`、Query Plan 与 retrieval trace 均为 additive 字段。
- `Prompt Default On` 保持关闭。无 Checkpoint、来源错误、STALE 或解析失败仍沿用 fail-open/不注入世界知识的既有边界。
- 未提前实现 V8.6/V8.7 范围，也不以本阶段宣称 V8.5 Full Freeze。

## 前置缺陷修复（2026-09-04，等待 Sol）

- 历史人物映射查询改为后端在完整 Definition→Runtime 索引上做单次有界遍历；无筛选时仍只返回前 500 条，输入历史人物名或状态后返回对应的匹配总数。已知目录中的历史别名随绑定返回可读 `historicalName`，不再因为目标 Definition 排在前 500 条之外而显示 0 条或通用“历史人物”。
- `getHistoricalBindings` 的 IPC/preload 接口以 additive payload 接收 `query/status`，Renderer 使用 150ms 防抖和请求序号丢弃迟到结果；刷新沿用当前筛选条件。历史映射页不再复用诊断页上一次的 `identityResolution`，避免把“赵思昭”的非历史别名结果泄漏成历史页的身份判定。
- Shared Query Analyzer 在已精确解析当前人物/头衔后跳过高成本 Localization reverse lookup；诊断 Trace 标记 `NOT_REQUIRED_ENTITY_MATCH`。Prompt 诊断摘要把已解析的当前存档人物与 `NO_HISTORICAL_ALIAS` 分开，显示可读识别对象、`RESOLVED` 和正确候选数。
- 真实 `autosave.ck3` 复核确认玩家是 Runtime `121091`、显示名 `思昭`；“赵思昭”解析到该人物且 reverse lookup 次数为 0；“岳飞”命中 `nansong_yue_085` 与 `tangyin_yue_014` 两个绑定。此处仅证明主进程/确定性链路，白屏与 Electron 页面仍需 Sol 重启后的实机复测。

新增回归覆盖完整索引目标越过 UI 上限、可读历史名、当前玩家全名查询、reverse lookup 跳过、Prompt 摘要身份语义和 Renderer `useRef` 首屏桩兼容；未改变 Prompt Default On 或旧 IPC 名称。
