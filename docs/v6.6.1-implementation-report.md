# VOTC v6.6.1 动作语义加固报告

> 完成日期：2026-08-20  
> 定位：Bug Fix / Semantic Hardening / Regression Expansion；不进行 `main.js` 模块化重构。

## 修复内容

### Participant Resolver：方向优先，无法确认即跳过

`ActionEngine.resolveEventParticipants()` 不再使用“一个具名角色 + 我”就默认“我为 actor”的兜底。它只接受明确语序：

- 主动句、把字句：`我刺伤张三`、`我把张三关进地牢`；
- 被动句：`我被张三刺伤/杀死/关进地牢`、`我遭张三刺伤`、`我为张三所伤`；
- 两个具名人物：`张三杀死李四`、`国王任命张三为骑士`；
- 唯一对话对象的“你”：`我杀了你`、`我被你刺伤`。

使役句、`他/她/它`、多个候选人物、非唯一“你”和无明确方向均返回 `unresolved`，并产生不含用户正文的诊断原因（例如 `unsupported_causative`、`ambiguous_pronoun`）。

### 参与者绑定不可被模型或旧参数改写

死亡、囚禁、骑士任命与受伤的 Prompt 明确列出已解析的 source/target，并说明 target 已绑定。模型输出的错误 target 会在执行前被覆盖为绑定 target。

`characterIsKilled` 与 `isImprisonedBy` 移除了动作模型可见的 `isPlayerSource` 参数，并在脚本内忽略遗留同名参数，避免旧调用路径把已绑定的受害者/囚犯改为玩家。

### Parser、审批和诊断

- Parser 新增“差点”、计划、后置否定及后续否定分句的拒绝处理；
- 所有 `riskLevel = high` 标准动作均扫描验证，不能被 destructive override 降级；
- 审批 payload 和悬浮详情保留并显示 source、target、risk level；审批后的 `runInvocation()` 继续使用已绑定的 invocation；
- participant resolved/unresolved 结果写入 analytics，但不记录消息正文。

## 已知限制

`他/她/它` 暂不从历史上下文猜测；使役句也暂不判断命令者与实际执行者。这些情况会安全跳过，不会把 CK3 effect 施加到猜测的人物。

CK3 实机与真实模型提供商冒烟仍需在用户的存档和 API 配置中执行，不能由本地 mock 替代。
