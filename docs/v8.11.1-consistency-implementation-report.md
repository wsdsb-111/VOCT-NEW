## 摘要写入安全

- 编辑和 UI 删除使用同步的有日志事务：每个受影响文件首次写入/删除前保存原内容；可见摘要、Memory、Knowledge、Pair Index、Consolidation、Episode、Index 一起提交。
- 临时恢复日志为 `memory/summary-mutation.json`。操作失败立即回滚；进程中断后，MemoryStore 初始化时先恢复原状态，再加载索引。仅接受 Memory 根和摘要根内的文件路径；日志不写入仓库。
- 编辑保持当前 `owner × counterpart` 范围，不自动改写对方视角或其他配对的摘要正文。旧共享记忆对其他知情者继续存在。
- 同 finalization 正在处理或有未提交的恢复快照时拒绝编辑/删除，避免恢复流程覆盖玩家修改；全量遗忘原有 memoryGeneration 防回写机制保留。
- 新增字段为兼容性扩展；没有数据迁移、全库重提取或真实用户数据批处理。

## Prompt 兼容

- 保持 `glm_cache_v2`、现有 Cache Anchor 与 Block ID，不重排四级生命周期。
- `worldline-turn-recall`、战争、行踪和实时社会关系仍位于缓存边界后的 Dynamic Tail。
- 移除 fullName 会使升级后的稳定正文发生一次预期变化；之后同会话头衔变动的 Prefix Invariance 已测。自动化不保证服务端命中率恰好保持文档中约 60% 的实测值。
