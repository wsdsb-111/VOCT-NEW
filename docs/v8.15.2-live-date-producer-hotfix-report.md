## 实机反馈与只读证据

用户确认新的陌生 NPC 不知道先前对话；这是用户本次场景的实机通过反馈，不代表所有隐私场景或长期运行验收。信件仍停在 30 天，当前日期世界记忆拒绝，指定日期可保存。

当前日志有正式 `VOTC:IN/;/init`，但没有 `VOTC:DATE` 或 `VOTC:LOAD_SESSION`。修复前 `readLiveProbe()` 把带头衔玩家姓名读成 gameDate，把日期中的年份读成 totalDays。正式九字段 payload 的日期位于索引 4，总日数位于索引 8；本次只读解析修复后返回 `1086年5月1日`、`396511`。这能直接解释当前日期保存被拒绝；截图中的信件 currentDay 是 PAYLOAD_BOOTSTRAP，不是持续日期跟踪已恢复的证据。本机 `letters.txt` 只读核对为已知 date-only carrier，不是未知 Artifact Effect；本轮没有直接改写它，由正常 App 启动路径安全迁移。

游戏原版 `common/on_action/_on_actions.info` 104–114 行明确禁止同名 on_action 拥有多个 effect，要求通过 on_actions 追加独立子钩子。上轮补丁向 `on_game_start` 和 `on_game_start_after_lobby` 直接添加 effect，存在与原版及其他 Mod 冲突的确定性结构缺口；上轮静态和窗口夹具没有覆盖此合并合同。没有在真实引擎中观测到冲突后的执行顺序，因此不宣称已唯一证明所有信件不投递的原因。

## 最小修复

- `worldline/worldline-service.js` 按正式 init 的固定字段解析九/十字段 payload，不再用跨字段正则猜日期；最新 LOAD_SESSION 以前的 init 和测试日期/人物标记不沿用。
- App 日期载体及 Mod 冷启动输出 `VOTC:DATE/;/<totalDays>/;/<GetStringShort>`。信件仍消费原数字字段，Worldline 读取游戏提供的完整日历字段，持续日期优先于旧 init。旧数字-only DATE 仍兼容信件，但不推算日历日期：CK3 totalDays 不能当作既有 Gregorian serial 直接转换。
- `letter-effect-transport.js` 只迁移精确匹配的旧本地化 date-only carrier，沿用 UTF-8 BOM 临时文件原子替换。未知 Effect 保留并拒绝重启，不覆盖可能已执行的信件。
- 两个 Mod 父钩子仅追加唯一命名子钩子；载入 epoch/LOAD_SESSION 与玩家 after-lobby DATE/延迟一天 `.9998` 分别由子钩子执行。已有 runner 对话暂停合同、官方 Artifact Effect、ACK 去重和接受后摘要门禁不改。
- 独立复核补齐同日同指纹重载的边界检查，仍经既有确认/分支界面授权；新 LOAD 后尚无 live 日期时，Canon 不以旧 checkpoint 日期补写 CURRENT_DATE。未绑定 live 会话的既有离线存档行为保留，指定日期不要求 live 日期。

非法非空 live 日期继续拒绝，不用旧 checkpoint 冒充当前日期。没有修改真实 pending 文件、接受锁、RunFile 队列、存档、日志或摘要，也没有强制重发。App/Mod 方案 B 独立发布，安装目录 Mod 与仓库快照已同步；依赖与指纹见 [外部运行依赖](EXTERNAL_RUNTIME_DEPENDENCIES.md)。
