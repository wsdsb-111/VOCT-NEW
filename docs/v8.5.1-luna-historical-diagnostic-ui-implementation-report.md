# V8.5.1 Luna：历史人物诊断可读性实施报告

日期：2026-09-04。范围：V8.5.1 第 3 步 Luna 前端展示；不含 Sol 最终正确性审查、Electron/CK3 实机验收和 Prompt Default On。

## 实施状态

Luna 阶段已完成。前端现在消费 Terra 提供的 `historicalCoverage`、`historicalIndex` 和 Resolver evidence，将历史人物召回结果拆成玩家摘要、可读依据和开发者追踪三层；事实门禁仍由后端 Shared Query / Historical Identity Resolver 负责。

## 已实现

- 新增 `resources/app/out/renderer/worldline-player-presentation.js` 的历史诊断展示转换：`RESOLVED`、`AMBIGUOUS`、`SOURCE_INCOMPLETE`、`NAME_INDEX_MISS`、`DEFINITION_FOUND_RUNTIME_MISSING`、`REJECTED_BY_EVIDENCE` 和 `VOTC_METADATA_MISSING` 均有稳定的中英文可读文案。
- Prompt 诊断默认先展示查询对象、身份状态、候选数量、结论、存档事实/补充知识命中和 Token；历史人物的来源不完整、定义存在但 Runtime 缺失、候选证据不足等情况不再只显示内部枚举。
- 新增懒展开的“历史人物判定依据”面板。面板只展示有界的候选、评分、可读支持依据、可读冲突、索引状态和来源完整性；候选最多展示 50 条，不在默认摘要或 Game Truth 中制造身份结论。
- 开发者层继续保留 `rawKey`、`definitionId`、`runtimeId`、`matchSource`、原始 coverage 和索引状态，集中在既有 Resolver 高级追踪中；这些字段不会泄漏到玩家默认语义层。
- Terra 的 Shared Query Analyzer 对短中文姓名查询显式透传 `NAME_INDEX_MISS` / `SOURCE_INCOMPLETE` coverage，使“赵思昭”等未命中查询可区分“索引没有这个姓名”和“来源尚未完整读取”。
- 增加历史依据面板样式，沿用现有世界线三主题的卡片、警告和列表样式，不改变主进程 IPC、Prompt 内容、缓存权威或 Game Truth 生产规则。

## 交接给 Sol

Sol 需要独立确认：

1. 未运行 Prompt 诊断时打开世界线页面不会白屏、卡死或读取未定义候选数组。
2. 真实存档查询“岳飞”和“赵思昭”时，`RESOLVED`、`AMBIGUOUS`、`NAME_INDEX_MISS`、`SOURCE_INCOMPLETE` 与 `DEFINITION_FOUND_RUNTIME_MISSING` 的展示与后端证据一致。
3. 历史依据面板展开后仍有界；默认玩家摘要不出现 raw/Definition/Runtime 内部字段，开发者追踪仍可回查原始证据。
4. 三套主题和真实 Electron 进程下没有新的白屏、主进程阻塞或跨页旧诊断串线。

本阶段不打开 Prompt Default On，也不宣称 V8.5.1 implementation freeze。
