# V8.14.2 P0 第三人记忆召回热修报告

日期：2026-10-05  
范围：多人对话当前轮提及、Memory4 实体路由与 Legacy 第三方摘要召回

## 事故与根因

多人对话 A/B/C 中提及第四人 D，B、C 虽在各自摘要目录保存了相关对话，Memory4 仍未能召回。排查确认有连续的两处漏召回：

- `MentionTracker.update()` 只从最新玩家一句提取 `currentTurnMentionedCharacterIds`，忽略同一轮回应者可见的 NPC 发言。玩家没有直接说出 D 时，D 不会进入本轮 Memory4 实体集合。
- `MemoryEngine.retrieveForResponder()` 将 `queryEntityIds` 与 NPC 本轮提及实体作互斥优先选择。即使本轮已有 D，只要玩家问题另有实体，D 仍会被丢弃。
- 补齐实体路由后，Legacy 候选筛选只看 `subjects`/`counterpartIds`；群聊摘要正文中的 D 不一定进入参与者元数据，因此摘要仍可能在排序前被过滤。
- 另外发现短中文别名会误匹配更长人物名中的子串，例如“张三”匹配“张三丰”。

## 修复

- `MentionTracker` 以最后一条玩家消息为当前轮边界，扫描该边界之后回应者可见历史中的明确姓名；之前轮次的人名不触发当前轮记忆。玩家最新问题保留原有代词解析，NPC 发言不借用跨轮代词指代。生产传入历史仍由 `Conversation.getHistoryForCharacter()` 按回应者 Presence 窗口过滤。
- Memory4 将玩家查询实体与当前轮提及实体合并，而非二选一；按 ID 合并当前 GameData 姓名与本轮解析得到的别名。
- 对已通过 Owner Legacy Bridge 门禁的摘要，按本轮已解析实体检查正文。正文匹配复用 `MentionTracker` 的唯一 alias 与最长重叠消歧，不把较短姓名当作更长姓名的命中。
- Owner、Campaign、`knownBy`、删除、未解析绑定、来源覆盖和未来日期门禁未放宽；不读取 D 的私人目录。原有直接摘要去重逻辑不变。
