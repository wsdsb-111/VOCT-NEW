# VOTC v6.6 动作系统收口报告

> 完成日期：2026-08-20  
> 状态：代码、静态回归与可注入运行时 Harness 已完成；CK3 与实际模型提供商手动冒烟待在用户环境执行。  
> 前置审查：[v6.6 Pre-Change Audit](v6.6-pre-change-architecture-audit.md)

## 已完成

### 1. Participant Role Model（P0）

以下 Action Script 已声明 `semantic.participantRoles`：

| 动作 | source slot | target slot |
|---|---|---|
| `characterIsKilled` | victim / patient | killer / actor |
| `isImprisonedBy` | prisoner / patient | jailor / actor |
| `isEmployedAsKnightBy` | appointee / patient | employer / actor |
| `isInjured` | actor | injured patient |

`ActionEngine.resolveEventParticipants()` 在 ActionEvent 的 Positive Evidence 中解析明确姓名与“我”的主动/被动语序。它在进入 `check()`、提示词、审批和 `runInvocation()` 之前固定 Script 所需的 source/target；无法唯一解析时跳过带 `participantRoles` 的动作，记录 `unresolved_action_participants`，不会将 speaker 猜作 source。

覆盖句式：

- 我杀死了张三 / 张三被我杀死；
- 我把张三关进地牢 / 张三把我关进地牢；
- 我任命张三为骑士 / 国王任命我为骑士；
- 我刺伤张三 / 张三刺伤我。

### 2. 统一高风险审批（P0）

`ActionRegistry.getEffectiveRiskLevel()` 成为风险读取入口；`riskLevel = high` 强制视为 destructive。即使已保存的 destructive override 为 `false`，高风险动作也不能在“自动接受非危险操作”模式中降级为自动执行。

这覆盖了先前有 `riskLevel: high`、但没有 `isDestructive: true` 的 `isInjured` 和 `isImprisonedBy`，同时保留中低风险及旧 override 的既有兼容语义。

### 3. Semantic Resolution Mode 与 Legacy 收口（P1）

每个 ActionEvent 现在具有 `resolutionMode`：

| mode | 行为 |
|---|---|
| `resolved` | metadata 基于 Positive Evidence 生成 allowlist |
| `legacy` | 仅显式 `requiresLegacyResolution` 的动作可用；当前为金币方向解析 |
| `unresolved` | 不调用动作模型，不放开 category 候选 |

`getActionIdsForTriggers()` 不再维护中心 `byReason` Action ID 映射；生产候选由 Action Script 的 `triggerCategories` 自注册。关系组合“长久对视后亲吻”及“牵手/亲密接触”已迁移为 metadata `match()`，因此 metadata 成为这两类语义的唯一事实来源。

### 4. Player/NPC 生命周期解耦（P1）

玩家消息提交后立即独立进入 `evaluateForCharacter()` 和审批处理；NPC 回复完成后只评估自己的消息。玩家动作不再保存到 `pendingPlayerActionMessage`，因此 NPC API 请求失败不会阻止玩家动作的解析、审批或执行。

### 5. Gate、Parser 与事件身份（P2）

事件去重键增加了稳定 `message.id`、category 和 evidence span，避免仅依赖每轮清空的集合区分不同消息。

`getActionTriggers(text, { candidateOnly: true })` 现在提供宽松候选模式；`parseActionEvents()` 使用该模式，再独立拒绝疑问、指令/计划、否定、假设、回忆/传闻与失败结果。metadata 可声明 `candidatePatterns` 供新动作自注册候选类别；四个 P0 动作已迁移该字段，避免新增同类动作必须同时修改中心 Gate 映射。

新增语言边界回归覆盖无标点躲避、后置“或许”、原因中的过去时间、转折、否定和同句多事件。

### 6. Mini Conversation Runtime Harness（P1）

新增 `scripts/test-action-v6.6-runtime.js`，直接提取生产 `ActionEngine` 与 `Conversation` 方法，并注入 LLM、设置、Registry、Analytics、ActionSandbox 与 CK3 Effect Writer。

- 死亡：验证 victim/killer 映射、审批 payload，并验证实际 `runInvocation()` 向 effect writer 传入正确 source/target；
- 囚禁、骑士任命、受伤：验证 `check()` 收到的 source 和固定 target；
- 玩家金币与 NPC 战斗：验证不同 message/source 独立处理；
- 模拟 NPC 调度失败：验证玩家动作已在失败前完成 evaluate 与审批处理。

## 新增/更新测试

`scripts/test-action-v6.6.js` 覆盖：

- 八个 actor/patient → source/target 映射；
- 未具名 patient 的 fail-closed；
