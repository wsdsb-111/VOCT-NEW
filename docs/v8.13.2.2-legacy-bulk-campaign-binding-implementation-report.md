# V8.13.2.2 Legacy Bulk Campaign Binding 实施记录

**日期：2026-09-25**  
**基线：V8.13.2.1**  
**范围：旧摘要 Campaign 绑定 UX 与安全迁移；不改变 Memory Engine 3.0 召回合同、Dual Temporal Selector、Recent2、Extra≤3、官方追忆、Provider Cache Anchor 或 Frozen Prefix。**

## 实施结果

- 保留现有逐篇绑定，新增“绑定本对话全部旧摘要”和“绑定此人物全部旧摘要”。对话级只扫描传入 Owner Folder 中的指定对话 JSON；Owner 级只扫描该人物 ID 前缀目录中的 JSON 文件，不提供全局 NPC 绑定。
- 两种批量操作均先 Preview、再由用户确认、最后 Commit。Preview 返回 Campaign Token、文件/摘要计数、待绑定/当前战役/其他战役/官方追忆/身份未决/无效记录统计，以及不含正文的目标 ID、文件清单和 SHA-256 revision。
- 仅填补 `campaignToken == null` 且 `campaignBinding.status !== "bound"` 的普通旧摘要。已有任意 Campaign Token、已绑定记录、官方追忆、无效摘要和无法稳定识别 Counterpart 的记录均不改写。Owner 级只要求 Owner 属于当前 Campaign；历史 Counterpart 以摘要中的稳定数值 ID 识别，不要求处于本场 Scene。
- Commit 在主进程重新验证当前存档、Campaign、Owner（对话级另含 Counterpart）及 Preview revision。revision 覆盖目标范围内文件列表、文件元信息、文件内容哈希和 Legacy target IDs；Preview 后任何变化均以 `legacy_binding_preview_stale` 拒绝，写盘前不改文件。
- Owner 多文件写入复用 `withSummaryMutation` 摘要 journal，一次性预建所有变更后统一提交；事务中途任一写入失败，journal 回滚全部文件。批量来源统一记录为 `user_confirmed_bulk_migration`。
- 成功后失效 Owner 摘要/日期索引缓存、重开自动迁移标记并刷新当前 Conversation Recall；没有重写 `cacheV2FrozenSnapshots.prefixByResponder`。自动 Legacy Campaign 迁移现在也明确跳过官方追忆，避免刷新时将其标记为未决旧摘要。
- 摘要管理器 UI 按 Owner 展示目录文件数、摘要数和未绑定旧摘要数；Owner 与 Conversation 批量按钮仅在存在旧记录时出现。Preview 的结果是确认前唯一权威计数，Renderer 不接收文件路径、不直接写摘要文件。
- 验收修正：新 VOTC 会话的 `GameData` 异步读取期间，批量/单篇绑定现在等待该会话的解析 Promise 完成，再读取 Campaign 和角色；等待期间若会话切换则拒绝。没有活动对话、游戏数据不可用、缺少 Campaign Token 分别给出可操作提示，不回退到旧会话或其他来源的 Token。
