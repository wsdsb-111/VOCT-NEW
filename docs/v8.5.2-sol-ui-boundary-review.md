# V8.5.2 Sol Stage 5：UI / DTO 边界独立审查

日期：2026-09-05  
范围：Luna Stage 4 Renderer、玩家语义 DTO、A/B/C 分层、旧 DTO 兼容与有界诊断  
结论：`SOL STAGE 5 CODE REVIEW = PASS`；下一步 Astra Stage 6；`INTERNAL FREEZE = NOT READY`

## 1. 审查结论

本轮没有发现新的 P0。独立复现并修复两组 P1 边界问题：

- additive `entityResolutions` 已把 Runtime-native 人物判定为 `RESOLVED` 时，玩家摘要仍按旧 `resolvedCharacters / resolvedTitles` 计数，可能同时显示“已确认当前存档角色”和“未找到明确对应对象”，候选数也错误为 0；历史索引 `NAME_INDEX_MISS` 还会覆盖 Runtime-native 成功结果。
- Renderer 语义助手缺失时的降级实现会直接显示 Historical raw key、Runtime ID 和内部状态枚举。正常入口按顺序加载助手，但降级路径不应破坏 A/B/C 层边界。

修复后，新逐实体 DTO 优先决定玩家摘要的已确认数量、候选总数和结论；旧 DTO 在没有 `entityResolutions` 时保持原有回退。`SOURCE_INCOMPLETE` 对大小写和数组顺序不敏感，并继续高于局部成功事实；`REJECTED_BY_CONFLICT` 纳入与证据拒绝相同的可读优先级。

## 2. 修改内容

### 玩家语义适配器

`resources/app/out/renderer/worldline-player-presentation.js`

- 已确认的逐实体结果至少计为一个候选，防止 `RESOLVED + 0 candidates` 的自相矛盾展示。
- 摘要同时读取 additive 逐实体状态和 legacy 聚合字段；新 DTO 存在时使用逐实体候选总数，旧 DTO 不受影响。
- Runtime-native 已确认不再被 Historical `NAME_INDEX_MISS` 覆盖。
- 纯 Runtime-native 查询不再显示不适用的“历史人物判定依据”；混合查询和旧 DTO 仍保留该面板。
- 多实体摘要不再用单个历史 coverage 代表整句；玩家被引导查看每个对象的独立结果。
- coverage 状态先标准化再比较，优先级为 `SOURCE_INCOMPLETE > DEFINITION_FOUND_RUNTIME_MISSING > REJECTED_BY_EVIDENCE / REJECTED_BY_CONFLICT > NAME_INDEX_MISS`。

### Renderer 降级边界

`resources/app/out/renderer/assets/index-Dn3qWlAB.js`

- 语义助手不可用时，Historical Mapping、身份种类、逐实体状态、世界线差异和历史解释统一显示安全的通用文案。
- 降级路径不再把 `figureKey`、`runtimeId`、内部枚举或原因码放入 A/B 玩家层。
- 正常 C 层开发者原始数据、懒展开和每页 50 条限制保持不变。
