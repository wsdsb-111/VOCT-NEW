# V8.6.1 Terra Stage 2 + 3 实施报告

## 结论

Terra Stage 2（Prompt / Budget）与 Stage 3（知情范围 / Supplemental）已合并完成，生产开关仍保持关闭：`subjectiveWorldMode=DIAGNOSTIC`、`promptIntegrationEnabled=false`。本报告只记录代码与确定性回归，不将其表述为 Electron、CK3 或 Provider 实机验收。

## Stage 2：Prompt 与 Context Headroom

- Prompt 固定为：稳定 Memory / Checkpoint Anchor → 既有动态场景与历史 → Current User → Memory Turn Recall → `worldline-turn-recall`。Worldline 动态事实不再出现在 Current User 之前。
- 新增稳定 Checkpoint Anchor 和动态 Turn Recall 两段。后者是唯一 responder-scoped Worldline 注入块，明确标为 `stable: false`。
- Memory Engine 2.5 的 selected IDs、摘要格式、缓存和写入路径未改。先按既有规则构造 Memory Prompt；仅将最终剩余 Context Headroom 分配给 Worldline。
- Worldline 总预算硬上限为 900 token；空间不足时按 Supplemental → Annual Delta → GameState → Game Truth 裁剪，耗尽则省略 Worldline，不删除既有 Memory Turn Recall。
- 在 Conversation 内记录 `worldline_recall` 指标，包含 shared retrieval、policy、format、token、裁剪数与 cache hit；不记录正文。

## Stage 3：最小知情生产者与范围

- Realm Scope 改为缓存的递归 Liege / Top Liege 根索引。缺角色、断链或循环不能证明同 Realm，维持 `null / INCOMPLETE`。
- Direct Observation 只生产“回应者与目标同时在当前对话场景”的 Presence 事实；不会从场景推断行为、信件、秘密或离场期间信息。
- Scoped Supplemental 只把 `entities` 中可验证的 CK3 Runtime ID 当作受众/范围证据。Personal / Secret 没有 Runtime ID 则不生成事实；共享候选池只保存 Secret 元数据，正文在 responder 局部重新授权后才可使用。
- Supplemental 未填游戏日期时锁定为当前 Checkpoint 日期；未来日期保持 temporal unsafe，不能进入 Prompt。
