# VOTC v7.9.2 Final Stable 修复实施报告

## 1. 版本与范围

- Workshop：2.0.4
- VOCT 核心：v7.9.2
- Memory Engine：2.5
- Action Engine：3.0

本轮按 `VOCT-NEW_V7.9.2_问题修复汇总.md` 收口信件链路、Social Consequence Engine 的证据权威与多人语义边界，以及结构化 Schema 用量诊断。没有提高 Social Judge 调用频率，没有改变 Memory Engine 2.5 的存储格式，也没有引入新的持久化社会状态。

## 2. P0：信件链路可靠性

- `LetterManager` 增加从触发、上下文等待、Prompt 构建、回复、摘要、待投递到完成/失败的可观测状态。
- CK3 信件载荷读取改为初次读取加 `100/200/350/600/1000 ms` 五次有界重试，并记录尝试次数、耗时、日志路径、最后解析结果和错误。
- 增强 Prompt 构建或 Memory 读取失败时，自动降级到只包含收发件人、正文和基础角色扮演约束的最小 Prompt；仍继续请求回复、生成摘要并持久化待投递信件。
- 摘要失败与投递失败分别落入独立状态；既有跨重启待投递机制保持不变。

覆盖测试：

- `test-v7.9.2-letter-pipeline-e2e.js`
- `test-v7.9.2-letter-payload-race.js`
- `test-v7.9.2-letter-memory-fallback.js`
- 既有 `test-v7.8.2-letter-delivery.js`

## 3. P0/P1：社会后果安全边界

- 新增本地 `Evidence Policy`。只有本地已确认世界事件或游戏事实可以支持高幅度世界后果；模型给出的 `reason` 或 `reasonCluster` 不能提升证据权威。
- `reasonCluster` 收敛为受控枚举，并兼容旧名称映射；未知分类按 `other` 处理。
- Friend、Best Friend、Lover、Soulmate、Rival、Nemesis 均使用独立关系证据策略。好感值不再直接等价于正式关系；敌对关系不能直接跃迁为朋友；Nemesis 必须基于已有 Rival 和新的独立严重事件。
- 修正敌对关系置信度计算不依赖未定义的友好信号。
- 多人称谓先复用 Action Engine 3.0 的引用解析与参与者绑定；明确称呼可定向，歧义的“你”在多人场景中 fail-closed。
- 可观察且执行成功的事件只向当前在场见证者传播；睡着、暂离、候场、离场和死亡人物不会成为见证者。
- 普通对白冷却使用标准化语义主题；独立已确认事件继续使用事件 ID，避免通过新消息 ID 绕过冷却。

覆盖测试：

- `test-v7.9.2-social-authority-safety.js`
- `test-v7.9.2-social-multiplayer-witness-cooldown.js`
- 既有 Social Context、Consequence、Precision 与 Analytics UI 四组测试
- 既有 Action 引用解析与参与者绑定测试

## 4. P2：结构化 Schema 诊断

- Social Judge 的 Schema 保持为 Provider 请求边界中的独立结构，不再伪装成 Prompt block。
- 用量记录独立保存 `schemaTokenEstimate`、`schemaFingerprint`、`schemaCacheRole`、`providerSerializedOrder` 和估算序列化 Prompt Token。
- DeepSeek 等需要 Provider 层注入 Schema 的实现按实际序列化位置记录，不把 Provider 转换后的结构误报为通用消息前缀。
- 用量报告新增结构化 Schema 请求数、Token、缓存角色和序列化顺序汇总。

覆盖测试：`test-v7.9.2-structured-schema-analytics.js`。

## 6. 人工验收边界

自动化测试使用真实日志解析、真实 LetterManager/Prompt Builder 和真实 Social 规则，但 Provider 调用停在可控测试边界。以下项目仍需在真实运行环境中完成，完成前不把版本标记为已通过全部 Final Stable 实机验收：

1. 启动 `VOTC.exe`，在真实 CK3 中完成信件 A/B/C、延迟载荷、重启后投递和摘要落盘检查。
2. 在 3/4/6 人场景验证明确称呼、歧义代词、睡眠/暂离见证边界和观察者影响。
3. 用真实模型 Provider 核对结构化 Schema 的实际 Token、缓存命中与序列化顺序。
4. 在性能、平衡、精准三种模式核对真实 CK3 好感与关系效果。

因此，当前结论为：代码与自动化发布门禁已收口，可作为 v7.9.2 Final Stable 实机候选；真实 CK3 与 Provider 验收仍待人工完成。
