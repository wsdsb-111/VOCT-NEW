## 事故证据与结论

用户明确：上一场多人对话已经结束，十余游戏日后在另一地点开始与陌生角色 D 的新对话，D 的第一次回复声称听过玩家此前的事情。用户进一步确认，随后提到的商路、货物和语言能力来自 ABC 私聊，不是其向 D 的介绍。对话使用独立 Zhipu Provider，摘要使用 DeepSeek。

本次仅只读检查本机日志、请求指纹、对应人物归档和源代码，没有清空摘要、重放信件、调用真实 API 或修改游戏状态。未将用户的对话、日志、凭据或存档复制到仓库。

- 定位到 D 第一轮请求；唯一注入的记忆块是 D 的官方追忆。以对应已保存官方追忆重新格式化，SHA-256 与该轮记录的块指纹完全相同。该轮没有稳定记忆、时间补召回或 Worldline 记忆块。
- 官方追忆来自 D 自己的 CK3 人生事件，不是上一场 ABC 的对话摘要。D 对话目录的叙事摘要在第一轮之后才生成。
- 新 Conversation 使用独立消息列表及冻结/召回缓存；Zhipu 序列化器发送当前请求消息，不携带前次 response/session ID，默认 `clear_thinking: true`。推理内容不写回可见对话历史。没有找到新会话自动继承 ABC 历史的生产路径。
- 首轮请求诊断为 1 条当前消息、0 段滚动摘要、冷会话基线；Provider reported cached tokens 为 0。不能因此证明服务端没有任何内部问题，但不支持“本轮命中旧私聊缓存”的判断。
- 非回应者 Prompt 视图清理其秘密、人生记忆和对话摘要；个人 Memory4 按当前回应者与 Campaign 选择。历史参考是静态历史资料，不是玩家私聊；普通对话的 `public` 不是全球公开授权。
- 补充核对了用户当前主模板及两个激活的角色描述/示例脚本：目标私聊细节未写入这些文本，主模板也没有枚举对话传记或全局对话历史。人物描述仍按用户既有合同提供后台姓名作为角色绑定标签；模型不能把这些标签伪装成已听过介绍或传闻。未修改用户模板或姓名标识。
- 进一步检查该轮之前的 CK3 角色导出，玩家确实带有贸易头衔与首都地名。激活的人物描述读取这些当前 CK3 字段；这些字段不是 ABC 摘要，能提供回复中身份/地名的候选输入，但不证明过去的商路、货物或语言能力。源码无关键词不代表渲染后的动态资料无关键词；没有保存的完整请求正文，仍不能据此证明具体复述细节的来源。

**用户确认的陌生角色复述属于需要处理的知情边界事故；但现有输入证据尚未证实 ABC 摘要注入或 GLM 缓存串场。** 模型根据后台人物资料或一般知识编造“听说过”的传播渠道，是一种仍需真实 Provider 对照的解释，不是已确认根因。诊断没有保存完整请求正文，不能据此宣称已重建并排除每个动态块，也不能仅凭官方追忆块匹配就宣布此次事故已解决。

## 已复现并修复的越权入口

### 1. 原始记忆授权与知情索引不一致

修复前，`MemoryStore.queryMemories` 和 `getPairMemories` 只检查人物知情索引。合成夹具中，即使原始记忆 `knownBy` 不含 D，D 的错误索引也能让其读到 private / public / world 记录。

现在人物召回必须同时具备知情索引和原始记忆的 `knownBy` 授权。Worldline 的个人记忆适配器也复核原始授权，不能把错误索引包装成 D 的事实。全局维护查询不改为人物召回。

显式转述同时核验转述者的原始授权与索引，避免错误索引经过转述变成合法授权。正常转述仍只授予被转述的那一条记录，不解锁其他私聊。索引登记仍不是独立的授权写入；合法授权由既有 KnowledgeService 更新两份证据。

这是可复现的防御缺口，但未发现本次 D 第一轮存在这类 ABC 索引，不能将其冒充为事故根因。

### 2. 同名人物的摘要兼容字段

`GameData.loadCharactersSummaries` 的旧字段入口按对话对象短名选文件，人物短名可能重复。现在加载后复核准确的玩家 ID、NPC ID 与非空当前 Campaign，拒绝同名异人、其他玩家、其他战役和无绑定记录。

不改摘要路径或存储格式；当前战役且人物对准确匹配的摘要继续可读。未知绑定 fail-closed，不做推测性旧摘要兼容。

### 3. 首都资料绕过非本人知识门禁

当前角色描述脚本通过 `capitalLocation` 输出其他人物的首都，既有 `createTraitProfileView` 没有过滤该字段；这不是私聊摘要，但可以向陌生角色提供用于构造传闻的玩家地点线索。`CAPITAL_LOCATION` 没有独立披露授权，也不能把首都当成 Worldline 的当前 `LOCATION`。

独立红测通过真实 PromptBuilder 最终消息复现：D 会收到玩家的合成首都标记。修复将 `capitalLocation` 加入既有非本人私密字段过滤，当前回应者自身保留完整值，原始 GameData 不修改；未知授权的其他人物首都不注入。姓名仍保留为后台角色绑定标签，已有 Worldline 地点授权不变，不借头衔授权推断地点。

同一原始专项绿测确认：D 最终请求不含玩家首都，D/A 回应时仍各自保留自身首都。这能封堵已确认的地点资料入口，但不单独证明全部复述细节都由它生成。

### 4. 无来源“传闻”生成约束

在现有回应角色身份知识提示中明确：私聊和信件不会自动传播到全世界；同国、同地、亲友、声望或经过时间都不证明听过其他人物的私聊。只能引用当前请求提供给该角色的授权记忆、来源明确的公开事实或当前已听见的对白。无来源时不能借“听说／传闻／有人告诉我”补造玩家往事或后台资料的传播渠道。

这是生成约束，不替代确定性的 ACL；也不保证未经真实 Provider 测试的模型必定遵守。

## 实机 Gate

1. 完全退出并重启 VOTC，使用新对话，确认新规则已加载；无需清空正常摘要。
2. 与 A/B/C 谈一个游戏资料和一般历史知识中不存在的独有细节；结束该场，再与陌生 D 开始新场。D 不得复述该细节或编造获知渠道。
