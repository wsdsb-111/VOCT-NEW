# V8.4 Luna：Live Date 与 Historical ID 实机验证

状态：Luna 阶段已完成可用的实机验证；本报告不宣称 V8.4 已达到最终 Design Freeze。

## 范围与约束

本轮严格按《测试清单3》执行 Luna 项：只验证 CK3 当前运行时日期、`Character.GetHistoryId`、Definition/Runtime/UI/VOTC 日志闭环，以及与 S0/S1 的人物样本对照。没有修改 VOTC Memory、Prompt、Action、Letter、Relationship 或正式 V8.4 运行时，也没有修改、保存或覆盖 CK3 存档。

实机使用用户已启动的 VOTC 与 CK3，临时 Probe 只写入 CK3 `debug.log`：

- `common/scripted_effects/log_gamedata_v3_effect.txt`
- `common/scripted_effects/log_gamedata_v3s_effect.txt`
- `common/scripted_effects/log_gamedata_v3l_effect.txt`
- `common/scripted_effects/log_character_v2_effect.txt`

这些 Workshop Mod 改动是 Luna 验证用的 debug-only 临时改动，不是 VOTC 生产代码；证据采集完成后已从上述 4 个文件清理。

## Test 1：Live Game Date Probe

结果：`PASS`。

VOTC 通过现有 GameData 日志触发点输出 `[GetCurrentDate.GetStringShort]` 与 `[GetCurrentDate.GetDateAsTotalDays]`，并与 CK3 界面日期核对：

| 日志时间 | CK3 日期字符串 | Total Days | 结论 |
| --- | --- | ---: | --- |
| 11:05:21 | 1155年10月31日 | 421879 | 与游戏画面一致 |
| 11:19:58 | 1155年11月8日 | 421887 | 与游戏画面一致 |

该结果证明 Probe 读取的是 CK3 运行时日期，而不是 Windows 时间，也没有依赖轮询或人为日期推断。

## Test 3：Definition ↔ Runtime ↔ UI ↔ VOTC 闭环

岳飞闭环已确认：

1. `character_lookup`：`nansong_yue_085 -> 96896`；
2. CK3 人物界面 debug tooltip：`ID: 96896，历史ID: nansong_yue_085`；
3. VOTC `Character.GetHistoryId` Probe：`runtime=96896/history=nansong_yue_085`；
4. 同一触发记录的运行时日期为 `1155年11月8日`。

因此本轮已证明 getter 不是从姓名或 save 文本猜测出来的字段。`tangyin_yue_014 -> 96895` 的 Definition/Runtime 映射已由 S0/S1 静态数据确认，但由于人物已死亡，仍缺少该实例的 live UI/VOTC 正向 Probe。

## Luna 阶段结论

- Live Date：通过。
- 存活历史人物 Historical ID：岳飞通过。
- 空 History ID 普通角色安全性：玩家与子女通过。
- Definition/Runtime/UI/VOTC 闭环：岳飞通过。
- 早死历史人物、辛弃疾和随机 NPC 的完整 live 样本矩阵：尚未齐备。
- 最终设计冻结：`NO`。Title/War 差分属于 Terra；剩余 live 样本和最终跨阶段复核不得在 Luna 阶段提前宣称完成。
