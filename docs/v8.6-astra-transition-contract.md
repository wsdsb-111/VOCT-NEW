## 3. 必须统一的权威边界

事实真实性、身份确认、知情权限是三个独立条件：

1. 身份/来源确定候选指向谁、来自何处；歧义候选不提供该人物的确定事实。
2. Knowledge Policy 判断当前 responder 是否知道这一字段/经历。
3. 只对已允许的事实做冲突裁决和 Prompt 选择。秘密不因真实性高而绕过权限。

`knowledgeLevel` 固定为 SELF、DIRECT_OBSERVATION、PERSONAL_MEMORY、COURT_PUBLIC、REALM_PUBLIC、PUBLIC_WORLD、SECRET、UNKNOWN。`sourceTier` 独立保留 GAME_TRUTH/LIVE/GAMESTATE/ANNUAL_DELTA/PERSONAL_MEMORY/PLAYER_SUPPLEMENTAL/HISTORICAL_BASELINE 等已映射来源；不得从 sourceTier 自动推出公开权限。

Policy 输出 `decision=ALLOW|DENY|UNKNOWN`、knowledgeLevel、reason、evidenceRefs、asOf/verificationMode；只有 ALLOW 能展开受保护正文并进入主观事实。UNKNOWN 表示证据不足，DENY 表示明确不满足条件，二者都不注入。

| 层级 | 最低允许证据 | 不允许推导 |
| --- | --- | --- |
| SELF | responder 的权威 Runtime ID + 可自知字段白名单 + 可用日期来源 | 人物数据库的每个字段都自知，尤其真实血缘、隐藏状态、他人秘密 |
| DIRECT_OBSERVATION | 本人可见消息/事件及实际 presence 区间；私信还需收件证据 | 同一 conversation 就听见全场，提议/待执行 Action 就已发生 |
| PERSONAL_MEMORY | 受信 owner 定向投影、knownBy、已验证的事件参与或私信接收证据 | 全局 participants 名单、正文提及某人就给该人授权 |
| COURT_PUBLIC | 明确公开类型 + 事实 court scope 与 responder scope 可证明一致 | 同宫廷传播 private/secret |
| REALM_PUBLIC | 明确公开政治/战争类型 + 同 realm 证据 | 全 Realm 私人关系/财富/位置公开 |
| PUBLIC_WORLD | 受审事件类型、公开范围与生效日期，例如公开君主更替/重大战争 | 检索命中、high importance、Gamestate 来源即世界公开 |
| SECRET | explicit knownBy、实际亲历、接收私信或受信定向投影 | SELF/同宫廷/同国/相同 query/玩家可见诊断自动授权 |
| UNKNOWN | 不进入 Known Facts | 低置信度猜测补齐 |

隐藏 Supplemental 总是排除。旧 PERSONAL/COURT_PUBLIC/SECRET 条目缺 owner/knownBy/scope 时保留可编辑数据，Policy 返回 UNKNOWN；不能把 entities 字符串当授权名单。旧 Memory visibility=public/world 也需可核验的公开来源，缺知情字段的旧记录不能默认公开。

SELF 只包含角色合理知道的自身身份、公开职位、已知家庭关系等白名单字段。real_father/real_mother 单独作为受保护事实；当前旧 parents 无法证明来源时，对新 Policy 的血缘事实标 UNKNOWN。后续 additive adapter 可保留社会/生物父母及来源，不破坏原字段格式。

## 4. 身份合同与最先关闭的债务

### Runtime-native

- 名称索引区分 FULL_VERIFIED_NAME、GIVEN_NAME、ALIAS。NFKC/大小写规范化可复用现有策略，不通过查询文字补姓，不由 raw key、文件名或给名长度猜全名。
- FULL_VERIFIED_NAME 必须携带来源：与同一有效 Runtime 绑定的 Live fullName，或可验证 snapshot house/dynasty/localization/culture 全名构造。仅存在任意 `character.fullName` 字符串不等于 provenance 合格；fixture 必须模拟真实来源合同。
- Live 名称只用于当前受信会话/来源范围；无法证明它和旧 snapshot 的 Runtime 属于同一上下文时不能回填。重开存档、换玩家或换来源使该绑定失效。
- 给名只能 CANDIDATE/AMBIGUOUS，即使数量为 1 也不 RESOLVED；别名无独立全名证据也不能晋级。
- 完整全名可以是句中完整实体 span，但不能与更长姓名交叉混用。历史已拒绝、来源不完整或绑定冲突不得绕道 native/非 CJK alias/mentionedEntityIds 再确认。
- 整个输入是数字或 `#RuntimeId` 可走明确 Runtime lookup；这确认存档对象，不证明历史身份、不授予知识。年份句里的数字不走此入口。Memory entity hint 是检索提示，不是身份或授权证据。
- 无可靠全名时允许显示给名候选；当前“赵思昭 → 思昭”结果预期降级，直到 T1 有受信全名来源。

### Historical source variants

- 硬冲突限定 NAME_SOURCE_CONFLICT、GENDER_SOURCE_CONFLICT、DEFINITION_BINDING_CONFLICT/FULL_NAME_PROVENANCE_CONFLICT，以及候选/来源不完整等既有安全条件。
- birth/father/mother/spouse/children 差异移至 sourceVariants/worldlineDifferences，INFO/NOTICE，不计入 identity hard conflicts。未知性别不等于男女冲突。
- dynasty/house/culture 差异若改变可验证全名或使命名来源不可靠，仍是全名来源硬冲突；若只改变背景元数据且全名/绑定证据仍一致，则记录差异。不能简单删除所有 source conflicts。
- 同一 definition 的多个有效来源保留来源与值。没有可靠 load-order 语义时不选择 sourceRows[0] 为唯一历史真值；多版本出生日期只能显示“来源存在差异”。
- 源文件变化仍更新 revision，使差异 UI/缓存刷新；“不阻断身份”不等于“不触发来源更新”。不同 definition 的同名人物仍歧义。

### 索引/Worker/discovery

- `WeakMap<snapshot, Map<runtimeId, definitionIds[]>>` 一次构建，保留 forward/reverse 的原始不一致证据；不可借缓存合并修复冲突。Snapshot 不原地变异；新数据替换对象，旧索引可 GC。
- Realm/court 派生索引在 Worker/有界异步准备阶段构建，查询只读 O(1)。遍历 liege 使用 visited + MAX_LIEGE_DEPTH=64；cycle、missing、错误 namespace 返回 UNKNOWN。无 liege 只有在明确独立统治证据下才以自己为根。字符/头衔命名空间由 adapter 明确转换，不按数字碰巧相同关联。
- 重试状态：失败后 FAILED_TRANSIENT → 1s/5s/30s 最多三次自动重试 → FAILED_STABLE。每个失败 episode 最多三次，短暂 built/READY 后立即再失败不能无限清零；预算只在成功完成一个后续无变化周期 probe，或显式刷新/配置变化后重置。Sol 用 fake clock 覆盖这项约束。
- 同时最多一个 Worker；旧退出/迟到回复不接管新 generation。失败先撤销 sourceComplete、清理 pending/timeout/该来源缓存，再计划重试；dispose、换路径、应用退出取消 timer。FAILED_STABLE 不随 query 重启。
- READY/PARTIAL/UNCONFIGURED 仍保留；更新所有调用方对新失败状态的判断。历史不可用时基本会话继续，身份注入拒绝。
- Base discovery 顺序：显式配置 → Steam library 元数据验证 → 已知游戏可执行路径 → mod inference → 用户手动回退。返回 path/provenance/status，支持零 mod、仅本地 mod、不同 Steam 库。
- 多个安装且无法消歧时返回选择需要，不全盘扫描或悄悄拼接库。discovery 仅启动/目录变化/刷新/恢复触发；周期 probe 只检查已解析来源和小配置/stat。显式 invalid 路径必须可诊断。

## 5. 管线与模块接口

下列新模块/方法是施工接口，当前尚不存在；Terra 可按现有封装调整内部命名，但需维持输入、输出及所有权合同。

```text
query + assistContext + trusted entity hints + source/checkpoint revisions
  → Shared Candidate Retrieval（同一 key single-flight，一次）
  → 有界候选字段/受保护引用池
  → 每 responder：Self + 可见场景 + owner Memory 候选
  → provenance/identity/temporal checks → Knowledge Policy
  → 允许后读取私密正文 → 字段冲突裁决 → 排名/共享预算
  → SubjectiveWorldView → deterministic text → PromptBuilder
```

| 模块/边界 | 职责与禁止事项 |
| --- | --- |
| WorldlineService `getSharedCandidatePool` | 共享 query planning/retrieval；禁止返回已经面向全体 NPC 的最终知识文本作为授权输入 |
| 新 `worldline/character-knowledge-policy.js` | 纯决策 canKnow/classify/arbitrate；不读存档、文件、UI，不请求模型判断权限 |
| 新 `worldline/knowledge-scope-resolver.js` | 消费准备好的 snapshot/live 索引；返回 scope + asOf + verificationMode + completeness |
| 新 `worldline/subjective-world-builder.js` | 聚合候选/记忆，逐 responder policy、裁决、预算和安全 DTO；不为 15 万人物预计算 |
| Memory adapter | 复用 KnowledgeService 与定向目录证据，输出受保护引用及权限元数据；正文内容不批量重写 |
| Conversation | 传 trusted responderId、conversationId、turnEpoch、scene/presence revision、已过滤 history；复用共享候选 |
| PromptBuilder | 消费已授权 View/文本，预览与实际请求使用同一结果；避免渲染原始世界对象绕过 policy |
| preload/IPC/Renderer | additive diagnostics，服务端验证目标/来源，玩家层只给允许事实和过滤数量 |

Candidate 必须按 entity + field 拆分；“整个 character 可知”不能授权 parents/gold/location 等全部字段。引用包含 factId、entityRef（namespace+id）、field、sourceTier、asOf、visibility、provenanceRef；受保护内容只给 opaque contentRef。共享缓存不放 Secret title/body/参与者姓名，也不放预生成 Secret 文本/词向量摘要。

Personal Memory 的自由文本按完整受信定向片段授权。结构化 Current Self 与旧摘要可对齐字段时先选当前值；无结构化映射的旧经历作为带日期的过去叙述，不能靠正则或模型悄悄改写约定。“当前未婚”不能否决过去订下的未来婚约。

共享候选必须在最终 TopK 之前提供足够有界选项，否则前几条不授权会饿死后续可知事实。先按安全元数据检索候选并截断，再逐 NPC policy/rank；不是把当前只允许 PUBLIC_WORLD 的最终 selected 列表当新 Policy 输入。

不同 responder 的当前可见话题/实体范围确实不同，可有不同共享 key；复用不允许把缺席期间的私密 query/实体/assistContext 交给另一 NPC。相同安全 query/context 的 responder 不重跑全表检索。

## 6. 冲突、时间与 Prompt

已授权且有效的事实按以下顺序裁决：Current Direct Game Truth / SELF / DIRECT_OBSERVATION > Personal Memory > Scoped World Knowledge > Supplemental Narrative > Temporal-safe Historical Background。

时间有效性先于排序。同 entity+field 的可比当前事实，当前明确 Live 优先旧 checkpoint；事件历史与未来约定按 eventId/时间区间区分，不当作当前字段冲突。相同优先级、相同有效时间且来源矛盾无从裁决时该字段 UNKNOWN，不拼成猜测结论。

冷启动/日期未知不伪造 live；scope 来自年度检查点须标明截至日期。历史事实、作品/人物知名信息继续通过 Temporal Gate，缺日期证据不将未来命运当背景常识。Worldline Difference 只在诊断。

现有 Worldline stableText 的反向优先级必须在新模式下替换，受影响 block/cache policy 版本更新并记录 README。稳定前缀只保留安全不变的系统/Persona/已授权个人记忆；个人钉住约定和最近三条不被新背景预算挤掉。每 responder 的授权结果即使稳定，也不放进共享的全体角色缓存。

所有到模型的入口列入 Sol Stage 4/6 检查：main template world_context、character/description/state、提及人物、在场关系、game memories、旧 past_summaries/rolling summary、Memory Engine anchor/topic/turn、worldStable/topic/supplemental/current、history 与 suffix/custom placeholders。角色描述/SELF 来源也必须字段级审核，不能仅给新 block 加一句“不知道就别说”。

Historical Context Replacement：

- Phase A：兼容模式保留旧接口，新安全 context 仅用于 diagnostics；明确属于过渡模式，不宣称已达 NPC 不全知 Gate。
- Phase B：仅对准备好的受信数据启用新模式，旧 placeholder 映射到请求局部的安全兼容对象；同一次 Prompt 只能 legacy 或 new 一份历史背景。不要修改全局 GameData 供不同 NPC 复用。
- 新模式不可用：会话保留原有经验证的个人记忆、可见 history 与安全 Self；世界块省略。legacy fallback 必须经过时间/权限检查，不能因异常回灌未过滤 period.context。
- Phase C：真实 CK3/Provider 验收后才废弃旧接口。V8.6 至少交付 Phase A 和可验收的安全主观管线；未在实际新会话验证该管线前不签全版本 FREEZE。
- 旧自定义模板占位符保留。无法提供受限上下文的块应省略并诊断；不以保留旧行为为由泄露系统数据。用户自己写入的静态文本与系统自动注入区分，审计报告标明范围。
- 新功能采用独立模式/开关（默认过渡诊断模式；具体设置键 Terra 实现时登记），不重用或偷偷翻转原 `promptIntegrationEnabled`。Off 回归保持 V8.5.2 行为；Off 不代表 V8.6 安全模式验收通过。

Action/Letter/Run Command/Presence/Finalization transport 不变。新的 DIRECT_OBSERVATION Action 证据必须是实际已执行/ACK 或真实观察，不能取模型 proposal/队列 awaiting_ack。私信正文只给确证收件/发送相关角色；Letter Prompt 数据源也纳入 privacy review。

## 7. Cache、revision 与性能上限

| 层 | Key/内容 | 失效与上限 |
| --- | --- | --- |
| Shared Retrieval | source/session identity + checkpoint + normalized query/assist + entity hints + world/historical/localization/retrieval revisions；安全候选池 | snapshot/source 更换淘汰；进程全局 cap 128，single-flight |
| Responder Knowledge | shared fingerprint + responderId + policyVersion + scopeRevision + relevant owner/pair memoryRevision + conversationId + sceneRevision/presenceRevision + live/freshness revision | global 128，per responder 8，LRU；不同 NPC/场景不能共享私密结果 |
| Subjective Summary | 已授权 view fingerprint + responder/privacy scope + budget + summaryPolicyVersion | global 128；私密文本只能在此 responder scope 内 |

短稳定 hash（SHA-256 前 16 位可沿用工程惯例）用于 key，不拼全 Prompt/Memory 正文。缓存命中仍需校验授权 revision 与 source/checkpoint 身份；同数字 Runtime ID 在换档后不能复用旧视图。不得提前假设完成 Save A/B 分支识别。

同一 query 当前缓存命中前仍可能做 analyzer，Terra 应把共享 key 检查移到适当的安全前置阶段；禁止每 NPC 重建扫描器、解析源文件、扫描所有记忆或遍历 realm。现有 `queryMemories()` 的全表遍历须改为取 owner knowledge IDs + 有界公开候选索引，不仅加更大的缓存掩盖冷路径。

scene/presence revision 从既有加入/离开/暂离/返回事件更新；对话结束、新对话、读取新 checkpoint、scope/knownBy 撤销也必须失效。Memory 按 owner/pair 局部 revision，外部编辑和目录 cache invalidation 同步 bump；旧定向投影保持知识所有权，不能按 finalizationId 合并不同关系正文。

初始硬合同：Policy candidates ≤128，Normal selected ≤24，Developer filtered preview ≤50；normal DTO 目标 ≤100KB，序列化 hard cap ≤500KB。截断标 truncated/candidateSetComplete=false，不能因此确认身份或把未知升为已知；输出 bytes 超限须先裁剪再发 IPC。实际 Secret 内容长度也计入预算。

Current Self/Direct → critical Personal Memory（最近三条、长期事项）→ Subjective World → Supplemental → Historical Background，共用实际 token 总预算。保持现有个人预算下限和 presence 边界；历史背景最先裁剪。不简单叠加五套预算。

性能矩阵：1/3/5/10 NPC × 10/32/64/128 candidates × small/large Memory，覆盖单/多人名、secret/realm/history-heavy 的 cold/warm/hit/miss；用计数断言 shared retrieval 一次、snapshot indexes 一次、无 responder 全表扫描。Policy p95 目标 ≤25ms（候选已准备）；真实端到端与同机同存档 V8.5.2 比较，增幅尽量 ≤30%，超出附 profile。首次构建/IPC/Provider 单独计时。

分别记录 sharedRetrievalMs、knowledgePolicyMs、scopeResolveMs、memoryRecallMs、subjectiveSummaryMs、输入/已知/过滤/secretBlocked 数、ipcBytes 及各层 hit。Provider KV cache 只用真实 usage 核对，不由内部 Map hit 推算。

## 8. Diagnostics 与兼容回滚

`subjectiveWorldView` 至少包含 responderId、checkpointId、knowledgePolicyVersion、asOf/verificationMode、allowed facts、unknown/filtered counts、conflict summary、bounded diagnostics。未知/过滤项不能复制秘密 value/title/参与者姓名。内部原始 candidates/Memory/snapshot 永不挂到 DTO。

Player A/B 层只显示可知事实与“已过滤 N 条未知/私密信息”。Developer C 默认也只返回 opaque id/reason；展开折叠不是授权措施，额外明示查看正文才可经独立有界请求取得。正常多 NPC 对比不把 A 的秘密放进 B 的结果，也不显示可反推秘密的标题。参数由服务端解析，不接受 Renderer 提交 sourceTier/knownBy 作为事实。
