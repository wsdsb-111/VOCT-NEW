# V8.15.2 空闲 RunFile 控制台报错修复

日期：2026-10-10。状态：生产修复、专项及独立 QA、完整发布检查已完成；真实 CK3 结果待重启后验收。

## 原因与改动

Workshop 的 `gui/custom_gui/votc_runtime_bridge.gui` 每两秒执行正式 `run votc.txt`；对话窗口另有消费入口。旧 RunFileManager 在队列空闲或命令确认后留下零字节文件，CK3 运行空 Effect 会显示 `Effect is empty. Check error log`。轮询本身承担正式动作和信件传输，不能直接停掉。

`resources/app/out/main/actions/run-file-manager.js` 在空闲时改写带 UTF-8 BOM 的合法空操作：

```text
if = { limit = { always = no } debug_log = "VOTC:IDLE_NOOP" }
```

恒假条件避免游戏状态变化和重复日志；普通 `run votc.txt` 命令回显仍可能出现。本轮没有降低或停止轮询，不恢复已退役的 `letters.txt` 日期管道。

实时 ACK 和启动 ACK 对账按当前已确认命令 ID 清除自有正文，空闲写入沿用同目录临时文件原子替换。空文件或缺失文件可以初始化，只有完全相同的自有空操作被识别为空闲；其他非空内容保留。独立 QA 发现公开 `clear()` 原先仍可覆盖未知内容，已改为复用同一安全检查。队列意图先持久化、FIFO、未知已执行效果不重放和损坏状态 fail-closed 保持。
