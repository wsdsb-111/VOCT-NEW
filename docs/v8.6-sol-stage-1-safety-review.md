## 1. 范围与验收口径

本阶段只关闭 V8.5.2 遗留的身份安全债务、区分历史来源的身份硬冲突与背景元数据差异，并冻结 Character Knowledge 的 `ALLOW / DENY / UNKNOWN` 规则。没有提前实现 Terra 负责的 Runtime 全名来源构建、Worker 恢复、Base Game discovery、Scope Resolver、Subjective World Builder 或 responder cache。

成功条件：给名、raw alias 和 Memory hint 均不能确认 Runtime-native 身份或注入 Game Truth；出生及家庭来源差异不能单独否决已证明的核心身份；姓名、已知性别、来源完整性和双向绑定冲突仍 fail-closed；未授权 Secret 不保留受保护正文。

## 2. 已关闭问题

### P0：Runtime given-name false resolution

- `nameToCharacterIds` 继续作为旧 snapshot 的给名来源，不再被标记为完整姓名。
- Query 扫描区分 `FULL_VERIFIED_NAME` 与 `GIVEN_NAME`。只有来源明确的 `verifiedFullNameToRuntimeIds` 且唯一命中时可 `RESOLVED`；给名即使只有一个 Runtime 也只产生 `AMBIGUOUS` 候选。
- Historical Definition 已存在、来源不完整或身份被拒绝时，不能经非 CJK alias、raw key 或 `mentionedEntityIds` 绕过历史门禁。
- 纯数字或 `#RuntimeId` 仍可确认存档对象，但不证明其历史人物身份。
- 使用生产 `parseGameState()` 夹具验证“韩世忠 + 世忠”和“赵思昭 + 思昭”均不进入 Game Truth。

Terra Stage 2 必须从受信 Live/full-name 或可验证 house/dynasty/localization/culture 链构建 `verifiedFullNameToRuntimeIds`；在此之前，旧 checkpoint 中只有给名的人物查询预期保守降级。

### P1：Historical source variant 误作身份硬冲突

- Historical Index policy 更新为 `v8.6-historical-index-5`。
- `birthDate`、`father`、`mother` 多来源差异写入 `sourceVariants`，不进入 identity hard conflicts；无可靠 load-order 语义时，对应聚合元数据为 `null`，不选择 `sourceRows[0]`。
- `NAME_SOURCE_CONFLICT`、`GENDER_SOURCE_CONFLICT`、`FULL_NAME_PROVENANCE_CONFLICT` 以及既有 binding/source completeness 条件仍拒绝身份确认。
- Resolver 只消费明确的身份硬冲突码；保留旧 `DEFINITION_SOURCE_CONFLICT` 的 fail-closed 兼容。

## 3. Knowledge Safety 合同

新增纯规则模块 `resources/app/out/main/worldline/character-knowledge-policy.js`，冻结八级知识分类：

`SELF`、`DIRECT_OBSERVATION`、`PERSONAL_MEMORY`、`COURT_PUBLIC`、`REALM_PUBLIC`、`PUBLIC_WORLD`、`SECRET`、`UNKNOWN`。

输出固定包含 `decision`、`knowledgeLevel`、`reason`、`evidenceRefs`、`asOf` 与 `verificationMode`。主要规则如下：

- `SELF` 只允许明确 Runtime 自身的字段白名单；`BIOLOGICAL_FATHER/MOTHER` 缺少本人知情证据时为 `UNKNOWN`。
- Direct Observation、Personal Memory 和 Secret 只接受直接观察者、owner、knownBy、私信收件人或已验证参与证据；旧 participants/同宫廷/同国/同 query/同 checkpoint 不自动授权。
- Court/Realm/Public 必须同时有公开性和对应 scope/时间证据；明确不在 scope 为 `DENY`，证据缺失为 `UNKNOWN`。
- hidden 始终 `DENY`；来源或候选不完整始终 `UNKNOWN`。
- 非 `ALLOW` 结果只保留安全元数据，不回传 Secret title/body 等受保护字段；knownBy 撤销后下一次判断立即撤权。
- 同字段冲突先排除未授权 Secret，再按 Current Self/Direct、Personal Memory、Scoped World 的权限优先级处理；同级矛盾返回 `UNKNOWN`。

该模块在 Stage 1 仅作为 Terra Stage 3 的可执行合同和测试基线，尚未接入 Conversation/Prompt，因此不能据此宣称 Generic NPC 不全知、Secret Prompt 隔离或 Subjective Cache Gate 已完成。
