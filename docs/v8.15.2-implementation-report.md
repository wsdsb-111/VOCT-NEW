# V8.15.2 可观察特质与人物披露实施报告

日期：2026-10-07。基线：`f15c385ddb29504ca4d025805808ddad8d8387e1`（V8.15.1）。本文记录本地代码及自动化结果，不代表真实 CK3、远端 Provider 或长时间运行已验收。

## 实现范围

- 共享 `prompts/trait-visibility-policy.js`，统一 canonical ID、别名、可信可见类别和 UNKNOWN 判断。保留原有 38 个可观察 ID 与 112 个明确不可观察 ID；按用户补充与本机原版定义新增 `scarred`、`clouded_eyes`、`measles`、`weak`，可观察共 42 项。未知且无法可靠分类的 Mod 特质仍隐藏并记录有限诊断，不按整个 Physical/Health 类别公开。
- `conversation/conversation.js` 在首次请求前、实际入场/返回、CK3 数据刷新和 MemoryContext 构建前执行两两观察。开场实际人物使用既有 Presence 窗口记录；候场、缺席、失活及仅被提及的人物不获得现场观察。离场立即撤掉当前观察标记，不伪造对白。
- `memory4-coordinator.js` 与 `memory4-store.js` 保存独立 `DIRECT_OBSERVATION / VISIBLE_TRAIT` 来源，以 Campaign、Owner、Entity、Fact Epoch、Conversation 和观察日期限定。每个日期保留真实证明，同日未变化不反复写入；回退时保留已发生的观察并排除未来证明，不将未来刷新当作当日观察。
- 当前现场观察覆盖已有 `MANUAL_HIDDEN`，UI 标记“当前可直接观察”并取消“设为未知”，后端亦拒绝伪造未知。离场后恢复原手工控制。动态伤势消失后不进入当前 Profile；历史来源保留。删除对白投影只撤销其对白证据，不顺带删除独立的亲眼观察；Orphan Audit 不误判观察为无主对白残留。
- 新观察和当前事实变化刷新角色说明、稳定 Profile、回应者冻结快照及前缀缓存；未变化的重复观察保持缓存。Prompt Block IDs、Cache Anchor、Recall/Forget/Recovery 主结构、Fact Epoch 和 Presence 窗口语义不重构。
- `memory4-disclosure.js` 拒绝“勇敢地/勤勉地”动作修饰及“即将/准备/打算/马上要”等未来身份语句，保留当前肯定自报及合法第三人直接公开。Renderer 来源弹窗的成功、错误、finally 均绑定 context epoch 和列表 request sequence，丢弃刷新后的旧响应。
- 功能标签更新为 V8.15.2；Memory Engine 显示 4.0、协议 `engineVersion: 3.0`、摘要存储 2.5、Electron App 包 2.0.4、主题内部键及既有 IPC 保持。

## Self 与对外认知

白名单只约束观察者对其他人物的自动观察，不限制 NPC 对自己的认知。`getTraitsForSelfProfile()` 保留角色完整 traits；Self 提示词包含可见、性格、秘密和未知 Mod 特质。对外 Profile 则只接受该 Owner 的合法观察、对白/信件、记忆、已知秘密或手工已知来源，不能从后台完整 traits 越过认知门禁。

42 项为原 38 项加四项查漏，不仅外貌或体型；原有 `wheezing`、`incapable` 及可观察疾病也保留。独眼 `one_eyed`、白化病 `albino`、伤疤 `scarred` 均进入首轮观察。“伤疤/瘢痕处处/血肉模糊”归同一 canonical `scarred`；“虚弱”对应独立 `weak`，不是百科中误配的 `physique_bad_1`（原版“纤弱”）。

参考资料为用户提供的 `Crusader_Kings_3_Traits_Encyclopedia.docx` 与本机 `game/common/traits/00_traits.txt`、简中 traits/CE1 本地化。百科是查漏资料，不直接作为 canonical 或数值真值。`lisping/stuttering` 需要听见实际发声，不能仅同场就宣称观察到；本版不扩展听觉采集。怀孕未必显怀、概括性多病、内部疾病、生育和血统继续要求合法披露；不新增病征到诊断的推断。

## 年龄披露事故

用户实机原话：玩家问“你今年多少岁”，NPC 答“今年13岁”；玩家说“我今年16岁比你大三岁”。旧年龄语法只接受完整的第一人称独立整句，省主语回答和比较后缀均会被拒绝。现已接受这两种表达，亦覆盖年龄标签和明确“已活 N 载”等自报；具名第三人年龄仅按明确主体绑定。

省主语回答仅在 Owner 可见的紧邻当前年龄问答中绑定到实际回应 NPC：问句、回答均须通过 spoken/sourceRole/knownBy/同场门禁，第三人插话不能借用旧问句；问答的 message IDs、fragment IDs 与正文哈希共同进入 AGE 证据。引号内真实对白亦走既有 directSpeechSpans 校验。全部数值必须匹配对应 CK3 当前年龄，比较中的“三岁”不记成年龄，也不推算新年龄。没有问句、未听见问句、错误年龄、旁白和不可见来源不授权。后台年龄仍不自动公开，姓名主体绑定和年龄历史显示合同不变。

实现侧 `test-v8.15.2-age-disclosure.js` 与独立 `test-v8.15.2-age-claims-independent-qa.js` 原始命令均通过；独立夹具真实走 Conversation Owner Snapshot → Memory4 保存 → 重启 → SummariesManager 人物认知 DTO，13/16 岁及获知日期保留。没有补写真实用户旧摘要；需用新对话实测。

用户随后明确改为“年龄披露后投射 CK3 真实年龄”：合法 AGE 证明为该 Owner 对该 Entity 授权；`currentKnownAge`、`currentAgeReadDate` 只读匹配 Campaign 的当前 CK3 数据，数据刷新后无需再次自报即可显示新年龄。原 AGE value/factId/日期/proof 不变，不写入伪造的 14 岁新披露；不按经过年数自行推算。无当前游戏上下文的归档只保留历史记录，实时字段为 null。来源被遗忘、未来证明、其他 Owner/战役或无效当前年龄不授权。

人物认知将“当前年龄（CK3/读取日期）”与“披露时年龄（获知日期）”分行显示。对外提示词仅在对应 Owner 具有合法历史 AGE 授权时保留当前年龄；未授权的展示副本将 age 置空并移除可重新推算年龄的直接生日字段，不改原始 GameData 或 NPC Self。冻结 Profile 也重新验证 AGE 来源，已撤销证据不能保留授权；新披露的下一场生效规则不改变。

追加回归：实现侧验证当前年龄 13→14→15、无新的 14 岁 AGE fact、原 proof 与获知日期不变；独立 QA 验证跨到 1165 年后，真实 PromptBuilder/标准 pList 脚本/本地 Provider Input 显示 Other 14 岁及 Self 31 岁，未授权晚加入者不获年龄。真实 Forget 后，冻结 AGE Profile 和 Provider Input 同时撤销当前年龄；归档及缺失当前年龄不提供实时值。两个独立原始命令均通过，追加投射后的完整门禁再次 386/386 通过。
