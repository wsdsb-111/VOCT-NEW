## 官方对照与最小修复

官方 App 2.0.3 的 `main.js:8366-8712` 通过 debug.log DATE 更新 LetterManager，按 payload 日加延迟等待，到期写官方宝物 Effect，接收后恢复日期文件。当前版保留官方宝物/接收合同，并通过 RunFileManager 的持久队列和 ACK 去重投递，不回退为无保护的直接文件覆盖。

世界线日期可由 init 更新，但信件仍等待持续 DATE。此次物理日志根本没有 DATE，不能通过放宽会话校验、沿用旧 checkpoint 或用电脑时间伪造游戏日来解决。没有到期投递，自然也不能提前生成已接收信件摘要。

确定的静态缺口是 `.9999`：它在 immediate 触发 `.9998`，其父 widget 又单独 `ClearWidgets letters_runner_counter`。`.9998` 已负责清理整个 runner 并重建；若父 widget 较晚创建，就会清掉子事件刚建好的唯一计时 hbox。现有日志证明轮询停止，但没有记录 widget 生命周期，具体引擎时序仍待实机验证。

本轮仅移除 `gui/event_window_widgets/event_window_widget_message_clear.gui` 的旧清理 state，保留事件、widget 名称与容器；清理/重建由既有 `votc_invisible_event.gui` 统一负责。已有两秒轮询、对话暂停、LOAD 隔离、RunFile ACK、官方宝物 Effect、接受锁和接收后摘要门禁保持不变。

本机 Workshop `3346777360` 已应用。仓库补丁快照新增修正后的 message_clear 和未改行为的 invisible_event；本机与快照字节哈希一致，见[外部运行依赖](EXTERNAL_RUNTIME_DEPENDENCIES.md)。App/Mod 仍独立发布，未修改 Three-Mod 兼容包或官方 App。
