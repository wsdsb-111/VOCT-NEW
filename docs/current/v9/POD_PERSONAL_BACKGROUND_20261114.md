# 2026-11-14 PoD 个人背景故事与官方追忆

已将人物专属传记接入对应 NPC 的个人官方追忆摘要前，标记为 **个人背景故事**，沿用上层稳定区的 `memory-official-recollection` 块。没有传记的角色保持原行为；只有传记而没有官方追忆的角色也能召回背景，`memoryCount` 仍记录真实追忆数，不把传记算成一条追忆。

## 精确提取和绑定

原生 PoD 传记按钮按角色的 `GetHistoryId` 查找本地化键，历史人物 ID 与当前存档运行时 ID 不要求相同。VOTC 现在从正在导出的同一角色取得两者与当前语言正文，不按名字匹配，也不在应用内读取／打包 PoD 的全人物传记库。

| 原生来源 | 本地化键 |
| --- | --- |
| 黑暗世界人物传记 | `POD_investigate.desc.<historyId>` |
| PoD 原创人物传记 | `POD_persistentpodlore.desc.<historyId>` |
| 民间传记 | `POD_podlore.100.desc.<historyId>` |
| 赞助者传记 | `POD_patronlore.100.desc.<historyId>` |

本地 PoD 源码中核对到这四类共 1,470 个键（978／388／11／93），不等于保证有 1,470 个不同角色。截图中的 Anna_Comnena 对应历史 ID `790004`、正文键 `POD_investigate.desc.790004`，与截图内容一致。静态取自原生源码的完整样例及源文件哈希在 `.build/pod-biography-20261114/anna-static-summary.txt` 和 `native-source-check.json`；其中运行时 ID 是明确标注的合成测试值，不是真实游戏读回。

导出流程只增加 VOTC 自己的 `character_history` 与完整 `character_background` 多行记录。现有角色数组字段不改位、协议／能力声明保持兼容；PoD 未启用、历史 ID 为 0／空、找不到正文或只有未本地化键时跳过，不生成占位故事、不阻止对话。新生角色若没有专属传记自然走这一路径；不会以姓名或“出生后角色”的标签猜测对应人物。

应用在当前 GameData 的私有 WeakMap 中绑定历史证据、运行时人物、campaign、当前玩家和日期快照。历史 ID 冲突、多个角色争用同一历史 ID、键与历史 ID 不符、未完成的多行正文均不能作为传记。普通 `#` 和正文中的分隔符保留，CK3 格式标记与链接控制符清理；多种来源只合并该人物自己的非重复正文。

## 上层稳定区和隐私

`official-recollection-provider.js` 将“个人背景故事”放在该人物的“CK3 官方人物追忆”之前，仍保存到其本人 ID 文件夹下的 `官方追忆摘要.json`。GameData 读取继续校验人物 ID、campaign 和本场 session，并额外核对背景来源指纹。

正文沿现有 `officialRecollectionText` 进入稳定块，按回应人物冻结复用；不作为每轮动态补丁追加。三种布局的合成出站消息验证了稳定标记、单次注入、位于当前人物事实／临时召回／本轮历史之前，以及后续轮次复用相同正文。没有增加或重命名 Prompt 块 ID、缓存锚点或 IPC。

传记属于本人的背景资料，不自动成为听众已知事实，不向其他 NPC、第三人或时间召回目录开放，也不绕过种族遮盖、手动隐藏、秘密及历史对话权限。原设中关于结局的内容不作为本局必然发生的事实，冲突时以当前 CK3 事实为准。

来源实际变化时，指纹使旧摘要／旧召回失效；刷新后重建，不沿用别人的背景。正文计入既有官方追忆与共享上下文预算，完整正文无法容纳时按原有规则停止发送并提示预算，不免费绕过预算，也不静默丢掉。Runtime 仍为 9.7.1，协议 3.0、存储 2.5、VOTC Mod 2.0.5 保持。
