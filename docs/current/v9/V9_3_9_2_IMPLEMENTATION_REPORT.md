# V9.3.9.2 亲属称谓、姓名认知、重新生成与摘要删除修复

本轮以 V9.3.9.1 `beda6e5` 为基线，延续已有亲属／长幼、公开直亲互知、整场上下文条与缓存边界改动，并修复用户追加的姓名遗忘、蓝色重新生成按钮及 Legacy 摘要删除错误。按用户明确要求不运行全量发布门禁；旧版完整 CI 的 PASS 不代表本版验收。

## 问题与实现合同

原始 CK3 导出中玩家 9 岁、哥哥 11 岁时，关系解析能给出哥哥／弟弟；但 Prompt 的人物投影先遮盖年龄，再从投影重算，丢失长幼依据，退化为兄弟。该年龄遮盖路径在 V9.3.7 已存在，回退 V9.3.7 无法解决。修复必须在脱敏前生成可信的两两长幼与双向亲属称谓，把派生结论带入实际 Prompt；不靠向所有人物公开生日和数字年龄解决。资料不足、来源冲突或无法区分同龄者时明确未知，不猜大小。堂表亲不获得直亲特质白名单。

当前可靠公开父母子女、亲兄弟姐妹（含有公开共同父母证据的半亲）互知姓名、头衔／官职及全部特质；UI 与 Prompt 使用同一自动权限。可信公开共同父母证据不要求父母本人也参加对话。私生子（`bastard`／`legitimized_bastard`）与父母之间不因亲子关系获得此白名单；秘密亲生、继亲、配偶、过期／冲突／跨 Campaign 来源不授权。白名单与关系识别分开：已公开的私生子亲子关系仍可显示父母／子女称谓，不因没有白名单而抹除关系。白名单不会开放原始秘密记录、其他人的记忆或扩大 Legacy 召回权限。

上下文主栏采用用户选定的口径：同一场保留各 NPC 最新请求，从中取最大占用，显示对应最紧余量；进入下一轮或换发言人不会清空成较小请求的读数。各 NPC Token 不相加。场次窗口容量固定为该场配置值（用户当前 192,000）；悬浮详情列出每人最新请求、估算／服务商用量及有效 Provider 限额。换场重置、过期事件拒绝和实际请求预算门禁继续有效。

## 缓存证据与边界

用户提供的四人场次可由现有本地用量元数据对应：14 次 Chat 输入 301,422 Token，服务商命中 88,768，约 29.45%。同一 NPC 的 10 次重复请求在实际出站诊断中均为稳定前缀不变、端点与有效参数不变；全局规则块及相应 Recent／事项簿指纹没有变化。其中仍有一次长公共前缀对应服务商零命中。此证据不能证明本地快照重建造成全部缓存下降，也不能据此保证服务商命中率。

“未命中归因”是按有序区块与服务商总命中量估算的断点，并非真实 Prompt 内容变化或服务商缓存断点遥测。新披露仍须及时反映在人物投影中，手动隐藏、Forget、来源修订和发送前复核不能为缓存收益让步。Recent2、成功动态摘要全文冻结、时间 5／5／3 与第三人全场 3、80K／84K／96K 预算合同保持。

## 本轮验证记录

### 追加问题的诊断

- **长幼仍丢失**：除了在场人物两两关系，按“你哥哥是谁”等相对称谓查询场外亲属时，Family Fact 仍从已遮盖年龄的投影图选择目标，导致可靠年长目标也被判为无法确定。候选和关系权限继续由投影图决定；原始当前资料仅用于派生长幼与称谓，不能把数字年龄、生日或未授权关系带入 Prompt。堂表亲与主体比较，伯叔与路径上的父亲比较。
- **赵月彩后来忘记赵文麟姓名**：最近场次的 29 条 Chat 出站诊断中，三个回应者最早可见的历史消息散列均保留在各自末次请求中，且没有滚动压缩段，不能归因为十轮后本地截断。当前定向认知虽生成 NAME 事实，最终 Prompt 没有专门消费它；修复在动态回应者事实中列出本场合法获知的目标姓名。事实仍逐 Campaign／Owner／Target／来源修订核验，姓名不等于交情、认脸或知晓秘密。增加“吾乃”“臣名”等明确自报姓名形式，但未恢复原始自报句，不能断言本次事故由某一种句式造成。
- **蓝色重新生成无反应**：完整合成链路可复现：一位 NPC 已回复、后一位生成失败并暂停队列，再重新生成先前成功回复时，未清除 `isPaused`，队列立即返回。仅在通过现有回合、回应者和动作副作用校验后解除暂停；继续保留逻辑玩家回合边界，不能重复玩家消息或重放动作。
- **重试拒绝没有反馈**：旧回合、已离场回应者或存在动作副作用时原有门禁只打印日志，IPC 却返回成功，Renderer 也忽略结果。现在普通重新生成和错误重试都透传成功／失败结果，并在界面显示拒绝原因；原有权限和副作用门禁不放宽。
- **P0 删除报映射不完整**：截图所示关系的三篇摘要中，前两篇分别关联 6／13 条旧记忆，全部存在且属于合法 Owner／Campaign／Pair。生产提取把 finalization→memory 关联写在 Episode，未逐条写入 Memory 的 finalization；删除校验却强制要求后一字段。修复接受同 Campaign／finalization／Pair 的 Episode 明确列出的记忆关联；非空 finalization 冲突、缺失关联、错战役或错人物仍阻止删除。真实资料只读核验，未替用户删除摘要或重写旧记忆。

独立对抗检查追加收紧两点：可信当前年龄优先，生日仅在两边可信当前年龄相等时打破平局，年龄／生死冲突不能由生日绕过；同 Campaign／finalization 必须对应唯一 Episode，摘要、Episode 与实际候选 Memory 的明确会话身份不能冲突。旧缺失字段保持兼容；候选 Memory 自身出现不同的明确会话身份也拒绝。通过原有严格校验的信件映射保留 letterId 与 job conversationId 的兼容语义。
