# V9.4.2 缓存前缀排查与 Action 修复

日期：2026-10-22。直接在 main 开发；不新增付费请求，不修改用户资料、摘要、队列、存档或原 Workshop Mod。本机仅串行小型测试，完整发布门禁与 EXE 冷启动转隔离 Windows CI。

## 实机证据与根因

截图对应北京时间 2026-10-21 23:41:44 至 2026-10-22 00:05:41 的 19 条 GLM-5.3-Flash 聊天请求：原生输入 200,562 Token，原生缓存命中 54,976 Token，命中率 27.4%。其中 9 次零命中，含三个回应者的初次基线；其余 16 次可比较请求的冻结前缀指纹均未变，最早变化在 Conversation History。截图两次 Stable History and Roleplay Rules“未命中归因”来自按估算块 Token 分摊的游标，不能视为静态规则真的变化，亦不是服务商原生断点。

因此没有为提高指标而把当前世界事实、历史尾部冻结，或移除合法 Recent2、官方追忆、玩家事项簿、时间／第三人摘要。聊天 V813 的固定规则和来源授权边界保持；六次已有稳定前缀但原生零命中的原因，现有遥测仍无法确证，不能承诺本版消除所有服务商零命中。

另在 DeepSeek Action stable-prefix 实际路径查到可复现缺陷：首个所谓稳定块含玩家姓名和当前 NPC 姓名，跨回应者时最前面的文本变化；Available Actions 及 schema 随当前资格与合法目标变化，却排在固定 Examples 前，稳定 Token 统计也包含这些动态块。

## 实现

- 官方 `ActionPromptBuilder` 内容保持不变。在 stable-prefix 开关开启且官方 intro 精确匹配时，把玩家／当前回应者身份拆到新增动态块 `action_turn_identity_v1`。静态 intro 保留 isPlayerSource 等完整动作规则；原身份在动态 system 消息中保留。
- 顺序改为固定 intro、可选状态转换规则、固定 Examples，之后才是身份、当前可用动作和 schema、名册、动作记录、消息及当前指令。新块 ID 和顺序作为 V9.4.2 缓存合同变更记录。关闭优化时原有消息保持；模板不符时保留原消息并明确诊断，不猜测抽取用户模板。
- 稳定前缀 Token 边界改为首个动态块之前；可用动作和 provider schema 不再被算作稳定内容。原生 usage 与本地估算继续分开。
- Action 请求带入真实 conversation／responder 元数据，避免把不同场次及回应者混作一条连续比较序列。可信固定规则后缀仅供进程内匹配，发请求前从诊断 metadata 移除。
- 参数约束、可用动作 check、schema、官方本地校验和实际游戏执行管线保持；未知效果不重放，未回读不宣称成功。

Core／App／UI 为 9.4.2。Workshop 2.0.5、协议 3.0、摘要存储 2.5、Official Action 2.0.3 保持。时间／第三人召回成功使用后仍按回应者在当前对话中冻结复用，来源与 Forget 发送前复核及既有配额不变。
