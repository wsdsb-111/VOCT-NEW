# V8.4.2 Luna UI 前置层实施报告

状态：Luna 阶段完成；Terra P0 与 Sol 审查尚未开始。

## 实施范围

本阶段只修改打包 Renderer、Renderer 样式和现有 Luna 结构回归。目标是先把 V8.4.2 的身份歧义、年度 Delta 和检查点新鲜度合同安全地呈现出来；Terra 尚未提供的字段采用空值兼容，不在前端猜测或生成身份结论。

## 已完成

- **Historical Ambiguity UI**：增加 `identityResolution` 与 `candidates` 的独立展示，包含 Runtime、Definition、Raw、Score、Evidence、Conflict。候选卡不使用 `displayName` 或 alias 作为权威标题。
- **Game Truth 隔离**：Prompt 诊断在 `AMBIGUOUS` 时将候选放入独立候选卡；Game Truth 人物/头衔区域保持未确认状态，避免把多个 Runtime 显示成一个已确认历史人物。
- **Definition Binding 语义**：将“历史人物身份”页签重命名为“历史定义绑定 / Historical Definition Bindings”，明确该区域只表达 Definition → Runtime，不等价于身份解析。保留 bounded IPC 的 `total/truncated`，增加 Definition/Runtime 搜索和状态筛选。
- **Annual Delta 展示**：增加 `WAR_NO_LONGER_ACTIVE` 的中性文案、`DERIVED_GAMESTATE` 来源和“待核实”状态；actor 支持对象化 Runtime/name，并过滤 `0` 与非人物数字，无法证明时显示“未解析”。
- **Freshness 语义**：增加 `LIVE_VERIFIED`、`CHECKPOINT_ONLY`、`STALE` 展示。缺失 Live 日期时显示“检查点有效 / Checkpoint valid”，不再显示容易误解的“新鲜”。

## Terra 交接条件

Terra 接入 `resolvedCharacters`、`candidateCharacters`、`identityResolution`、对象化 actors 和 `verificationMode` 后，现有 UI 会按字段自动展示；缺失字段继续显示未确认/暂无结果。下一步应切换 Terra 执行 V8.4.2 Phase A 的 P0 Identity Safety，再由 Sol 做正确性 Gate。
