# V8.8 Luna Entity & Kinship Inspector 实施报告

## 结论

Luna 阶段已完成 Entity & Kinship Inspector 的只读开发者诊断 UI，并接通现有 Worldline IPC。代码侧 `V8.8 LUNA CODE = PASS`；完整发布门禁为 **264/264**。本阶段不宣称真实 CK3、Provider、打包 Electron 或 Sol 最终 Freeze 已完成。

## 已实现

- 在 `WorldlineView` 的开发者诊断页新增 Entity & Kinship Inspector，按四栏固定区分：身份依据、当前世界状态、亲属关系、历史差异。
- 检查请求以 Responder Runtime ID 和 Target Runtime ID 为边界，复用 Terra 的 `WorldlineService.getEntityKinshipInspector`，通过 `worldline:getEntityKinshipInspector` IPC 和 preload 暴露；Renderer 不读取存档或直接访问文件。
- 展示同名 Runtime 候选、候选证据与冲突；关系歧义只显示可读状态，不把任一候选的私有事实当成结论。
- 展示由 Runtime ID 构成的 Relation Path、关系距离、当前存活状态、性别、年龄、地点/领主/宫廷，以及已故事实提示。
- 未指定目标人物时仍可运行查询；关系称谓的多个候选或性别证据冲突会以专门的关系歧义状态和候选列表显示，不提前把某个候选当成结论。
- 历史人物映射恢复为独立的“历史身份”页签；普通玩家看到语义化状态，Historical Identity、Definition、Runtime、provenance 等 raw 诊断只在开发者模式显示。
- 新增基本 Inspector 样式、窄屏兼容、原始 JSON 的有界滚动和 profiler 区域，显示实体/关系延迟、Binding 缓存数量与 Kinship 缓存作用域，避免长路径/候选/诊断把页面撑爆。

## 回归与修复

- 新增 `scripts/test-v8.8-luna-entity-kinship-inspector.js`：以三代人物夹具验证四栏、祖孙派生路径、Historical Binding scope、已故/状态字段、IPC/preload 接口和 raw enum 隔离。
- 修复历史身份页 raw-data 保护分支缺少外层 `children` 闭合的问题。完整 bundle 的 `node --check` 未能发现该问题，但 V8.4.2 Sol 的局部 `WorldlineView` 初始渲染安全门可以稳定复现；补齐后该安全门恢复通过。
- 已通过：
  - `node scripts/test-v8.8-luna-entity-kinship-inspector.js`
  - `node scripts/test-v8.4.2-sol-safety-gates.js`
  - `node scripts/test-release.js`（264/264）

## 未冻结边界

- Shadow Historical Resolver 的迁移、全链路性别仲裁、Historical/Kinship/Relation 联合 Load Boundary cache 与 Terra Stage 6 profiling/soak 仍按 V8.8 路线保留。
