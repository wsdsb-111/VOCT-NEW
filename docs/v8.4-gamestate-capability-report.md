# V8.4 CK3 GameState 能力勘探报告

## 1. 范围与结论

本报告按《VOTC_V8.4_CK3_Save_Gamestate 前置勘探计划书（Codex 执行版）》执行。完整解析样本只有外部 CK3 存档目录中的 `autosave_1.ck3`；同目录其他 20 个 `.ck3` 仅做头部和 metadata 快照，用于观察轮换，不作为完整 GameState 结论。

本轮目标是确认能力、记录限制和形成 V8.4 设计输入，不实现正式 V8.4 运行时，不接入对话、Prompt、Memory、Action、Letter 或 Worldline 主链。

### 能力状态定义

- `CONFIRMED`：样本或静态源代码有直接证据。
- `PARTIAL`：只覆盖局部字段、局部路径或一个样本。
- `NOT_FOUND`：在本轮样本/源代码范围内未发现所需能力。
- `UNRELIABLE`：存在结果，但不足以作为可靠合同。
- `IRONMAN_BLOCKED`：因 Ironman 加密/不可读边界而无法执行。
- `DERIVED_ONLY`：只能由现有字段推导，存档没有直接字段。
- `UNKNOWN`：证据不足，不能作结论。

## 4. 关键人物与时间边界观察

- 样本当前日期为 `1154.1.1`。辛弃疾记录可被解析，出生日期为 `1146.4.28`；这证明人物的 birth、culture、faith、family、alive/dead、traits 等字段可用于候选证据，但不证明历史身份字段存在。
- `Yuefei_name` 共出现 4 次：1 条 living、2 条 dead_unprunable、1 条 dead_prunable。四条记录的出生、性别、文化/信仰、死亡和家庭字段不同；仅按名字匹配会产生歧义。
- 年龄是由存档日期和 birth 推导的诊断值，不应当被当作存档原生字段或历史人物事实。
- culture、faith 在样本中主要是数值 ID；根对象没有直接的 `cultures` / `faiths` 名称表，名称解析必须依赖游戏/mod localization 或另行建立映射。

## 5. 交付与停止条件

已交付一次性勘探工具 `scripts/explore-v8.4-gamestate.js` 和五个最小脱敏 fixture。工具只读存档，Gamestate 临时复制完成后删除临时文件，不把存档、日志、解析 JSON 或用户数据写入仓库。

本报告与其余五份报告完成后，按计划停止在“勘探报告完成、正式 V8.4 尚未施工”的状态，等待人工复核。进入正式开发前仍需至少补充第二个同 campaign 或 branch 样本、一次真实 live date probe，以及 Save A/B checkpoint reconciliation。
