# V8.15.2 年度与人生记忆获知日期归档热修（2026-10-09）

## 问题与根因审查

用户反馈摘要、详细长期记忆可生成，但年度和人生记忆为空；手动“从长期记忆生成年度与人生记忆”也没有结果。

只读检查当前 `.memory4` 数据：6 个非空 Owner 共 172 条有效长期条目，全部 `eventTime.from/to` 为空、精度为 unknown，且都有对话/获知日期。167 条事件状态为 unknown，5 条为 reported；这些 Owner 没有年度文件，人生文件没有片段。未复制正文、凭据或运行数据到仓库。

`memory4-derived.js` 的来源快照与年度枚举原来仅使用可确定的事件年份。因此上述条目全部被过滤，人生生成也没有年度来源。空生成仍返回 COMPLETE，Renderer 显示“记忆已更新”，掩盖了实际没有归档来源。这同时解释自动生成和手动生成失败，不是按钮未接入 IPC。

另有抽取恢复记录中的无效事件状态等错误，它们属于 Detail 抽取问题；本轮不把它们与已经成功保存的 Detail 无法派生混为一谈。

## 用户确认后的归档合同

- 可确定事件日期时，继续按事件年份归档。
- 事件日期和精度均未知、状态为 unknown/observed/reported，且获知日期有效时，按获知年份归档，固定显示 `【本年获知，事件日期未知；获知日期：…】`。
- 原始 Detail 的事件日期保持未知，不把 conversationDate 或 acquiredDate 写回事件日期；planned 不获得获知年份回退。
- 压缩提示词提供两种日期及来源时间轴，要求保留未知事件标注。删除标注或将事件日期来源和获知日期来源混为一条的响应拒绝发布；最终标注后的文本仍执行原 1000 Token 上限。
- 没有合格来源时界面说明原因，不再把空结果描述为成功生成内容。空任务保留终止状态，避免合法无内容来源在恢复队列中无限重试。

## 精准改动与兼容性

生产改动仅涉及 `resources/app/out/main/memory-system/memory4-derived.js` 与 `resources/app/out/renderer/memory4-manager.js`：年度来源枚举、变脏/重建、压缩标注、召回时间轴及空来源提示。派生条目增加 `timeAxis`，包含未知事件来源的派生快照复核获知日期；已存在的空人生视图会自然变脏，可从原 Detail 重建。

人生记忆沿既有年度来源构建。无事件窗口的概览可召回带标注的内容，原因记录为 acquired 或 mixed；事件窗口不能用获知年份证明未知事件发生在窗口内。来源知情授权、Owner/Campaign、来源正文校验、修订、遗忘、手工覆盖保护继续执行。

不改 IPC 名称、人物记忆显示标签、`engineVersion: 3.0`、摘要 2.5 存储、既有 schema、文件夹、Prompt block IDs 或缓存锚点。派生压缩提示词只描述本轮的新归档语义。没有改写真实 Detail、摘要、恢复记录或 Provider 设置，没有重新抽取、重发信件或调用真实 Provider。
