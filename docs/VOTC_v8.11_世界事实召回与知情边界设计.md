# V8.11 世界事实召回与知情边界设计

## 目标与证据

玩家要求以游戏实际进程为先、历史背景为次：能回答宋金当前战争；游戏中仍存活的人物不受历史死亡结局覆盖；行踪仅向有亲友关系或直接观察证据的回应者提供。

代码审计发现：`world-retriever.js` 未构造活跃战争候选，`world-knowledge-classifier.js` 只接入 CHARACTER/TITLE；战争 Delta 丢失交战方语义；LOCATION 及包含地点的 IDENTITY 被归为 COURT_PUBLIC；召回格式化按人物 ID/字段排序，可能在有限预算内挤掉问题所问事实。上述是代码证据，尚非真实 Provider 输出的因果验收。

## 实施合同

1. 活跃战争从当前 Checkpoint 的 wars 构造 WAR 候选，以实际参战人物和其头衔匹配问题；使用本地化名称呈现攻守双方、状态和数据日期。只回答存档能证明的内容，不从无匹配推断和平，不把战争缺席推断为胜负。
2. 当前人物身份、生死沿共享 Current Truth 读取；历史只可补充截至日期的制度、文化、地理常识，不得用历史传记补齐当前生死、战争、行踪或结局。无法绑定或来源缺失时明确未知。
3. 地点和宫廷归属作为行踪字段，按回应者判权。本人、已验证亲属、当前游戏正式朋友及有对应直接观察证据者可得数据；同国、同宫廷、同名、好感高不能单独授予行踪。亲友权限只允许知道已记录地点及其日期，不能推断旅程或未来目的地。
4. 权限在 Prompt 序列化前执行；身份组合文本不得夹带未授权地点。共享池不保存角色专属授权，回应者缓存包含关系证据版本，切 NPC 或关系变化重新判定。
5. 本轮所问字段在候选选择和预算裁剪中优先。事实使用明确主体、谓语、对象和日期；无获准答案时注入不含隐藏内容的回答边界。诊断记录问题意图、选中事实数、格式化保留/裁剪数及行踪限制数量。
6. 所有新增事实与回答规则在 Worldline 动态尾部，保持 GLM Cache v2 前缀不变；Action 不读写新逻辑。保留 Memory Engine 2.6 可见标签及 2.5 存储合同。

### 数据可读性和隔离边界

- 国号优先采用存档 `title_name_data.name`，例如 `h_china` 在当前局可为“宋”，不能只按通用头衔键解释；支持“宋国/宋朝”这类明确查询。战争标签仅对入选候选的主要双方按需本地化，避免全战争集触发本地化队列。
- 同时命中两国的战争优先于只涉及其中一国的战争。泛问战事时优先在场人物所属领国；参与者集合计入 Topic Cache Key，最终仍逐回应者判权。
- 无来源类型的数字地点不跨 Province/Title 命名空间猜测，输出“位置编号／地名未解析”。V8.11 未实现新的省份地名映射器，不能保证每个存档地点都已有可读地名。
- 具体战争和行踪沿原 `worldline-turn-recall` Block 进入缓存边界后的 `DYNAMIC`，不新增或改名 Prompt Block。历史替代数据保留既有接入口，清空现实史的事件/人物命运列表；失败降级同样不恢复历史结局。

## 验收

- 确定性夹具覆盖：无年度 Delta 仍召回宋金活跃战争；攻守双方所属国 NPC 均可得公开战事；不相关战争、来源缺失、历史时间查询不误报。
- 岳飞存活/死亡/冲突；亲属、朋友、陌生人、同宫廷非朋友、直接观察；关系撤销、同名歧义和缺失地点；未经授权 Prompt 中无地点正文。
- 真实 Service→主观判权→预算→PromptBuilder 覆盖，战争与行踪事实在 900 Token 内保留，GLM Prefix Invariance 通过。
- 专项、完整发布门禁、隔离 Electron 冒烟；真实 CK3/Provider 的宋金、岳飞案例和长时对话由实机证据另行验收。
