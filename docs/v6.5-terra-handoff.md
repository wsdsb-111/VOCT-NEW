## 🔴 已确认的真实架构问题

### A. Stage 2 Full-Text Contamination ⚠️ **极高风险**

**位置**: `ActionEngine.getSemanticActionProfile(fullText, reasons)`

**问题**:
```javascript
// Stage 2 重新用 pattern.test(source) 扫描完整原文
const profile = {
  reasons: [...],
  allowedActionIds: []
};

if (reasons.has("death_or_injury")) {
  if (matches(/(?:杀死|杀了|砍死|...)/i)) {
    allow("characterIsKilled", "明确的死亡结果");
  } else {
    allow("isInjured", "明确的非致死伤害结果");
  }
}
```

**后果**: 
- "我没有杀死他，只是刺伤了他的手臂" → 错误允许 `characterIsKilled`
- "他没有被罢免，反而被任命为骑士" → 错误允许 `isFiredFromCouncilOf`
- "他没有离开，而是进入了王座厅" → 错误允许 `leavesConversation`

**影响范围**: 32 个被 getSemanticActionProfile 硬编码的 Action

**v6.5 修复**:
1. Stage 1 输出 `ActionEvent[]` with `evidence: { text, start, end }`
2. Stage 2 只接收 `Event.evidence`，禁止访问 fullText
3. Semantic Resolver 只在 evidence span 内匹配

### B. Gate False Positive / False Negative ⚠️ **高风险**

#### B1: Hypothetical Death False Positive

**测试**: "如果我杀了他，也许会惹麻烦。"

**当前结果**: 
- Triggers: `[death_or_injury]` ❌
- Allowed: `[characterIsKilled]` ❌

**应有结果**: 
- Triggers: `[]` 或 candidate hint only
- Allowed: `[]`

**根因**: Gate 无法区分假设语境（"如果...也许"）和真实事件

---

#### B2: Gold Gate False Negative

**测试**: "我现在把50金币交给你。"

**当前结果**: 
- Triggers: `[]` ❌

**应有结果**: 
- Triggers: `[gold]`

**根因**: Gate regex 漏判"现在"、"把...交给"组合

### C. pendingPlayerActionMessage 问题 ⚠️ **架构缺陷**

**位置**: `Conversation` class, line ~6777, ~6789

**当前代码**:
```javascript
const actionMessage = this.pendingPlayerActionMessage ?? placeholder;
await ActionEngine.evaluateForCharacter(this, npc, signal, actionMessage);
if (this.pendingPlayerActionMessage === actionMessage) 
  this.pendingPlayerActionMessage = null;
```

**问题**: `??` 操作符导致 Player message 或 NPC reply 的二选一处理

**后果**: 
- Player 有动作时，第一个 NPC 的 reply 使用 Player message
- NPC 自己 reply 中的动作可能未被独立评估

**v6.5 修复**:
```javascript
// Player message evaluation (独立)
if (playerMessage) {
  await ActionEngine.evaluateForCharacter(conv, playerChar, signal, playerMessage);
}

// Each NPC reply evaluation (独立)
for (const npc of npcs) {
  await ActionEngine.evaluateForCharacter(conv, npc, signal, npcReply[npc]);
}
```

### D. Message-Level Semantic 无法表达 Event 边界 ⚠️ **架构限制**

**当前限制**: 一条 message 只能产生一个动作语义判断

**无法表达的场景**:

#### D1: 多 Event 拆分
- **文本**: "我刺伤了卫兵，随后离开大厅。"
- **当前**: 两个 category，但混合 evidence
- **v6.5**: 两个独立 ActionEvent，各自 evidence

#### D2: 同类多个 Event
- **文本**: "我刺伤了第一个卫兵，随后又刺伤了第二个卫兵。"
- **当前**: 单个 death_or_injury category
- **v6.5**: 两个独立 injury Events (不同 target)

#### D3: Event 顺序
- **文本**: "我先拿起酒杯，随后刺伤卫兵，最后离开大厅。"
- **当前**: 无法保证 Event 顺序
- **v6.5**: Event 1 → 2 → 3 严格顺序

#### D4: execution vs result
- **文本**: "我挥剑刺向他，但他及时躲开了。"
- **当前**: 只能通过 allowedActionIds 间接判断
- **v6.5**: `executionStatus: "completed"`, `resultStatus: "failed"`

#### D5: attempted vs executed
- **文本**: "我试图拔剑，但剑卡在剑鞘里。"
- **当前**: 只能通过 allowedActionIds=[] 间接判断
- **v6.5**: `executionStatus: "attempted/failed_before_execution"`
