## 🔴 已知 v6.4 失败案例详情

### Case 1: 否定死亡 + 实际受伤 ⚠️ **核心 v6.5 案例**

**文本**: 
```
我没有杀死他，只是刺伤了他的手臂。
```

**实际结果**:
- Triggers: `[death_or_injury, combat]` ✓
- Allowed: `[characterIsKilled]` ✗

**问题分析**: 
Stage 2 (`getSemanticActionProfile`) 重新扫描完整原文，看到"杀死"后错误允许 `characterIsKilled`，尽管 Stage 1 已经正确识别出这是否定句。

**应有结果**: 
- 只允许 `isInjured`
- 严格禁止 `characterIsKilled`

**v6.5 目标**: 
Positive Evidence 隔离，Stage 2 只处理 Stage 1 提取的"刺伤了他的手臂"，不再访问完整原文中的"杀死"。

- Triggers: `[]` ✗
- Allowed: `[]` ✗

**问题分析**: 
Gate (`getActionTriggers`) 完全漏判关系变化，可能是因为"不是"否定词导致整个句子被排除。

**应有结果**: 
- 识别 `relationship` trigger
- 允许 `becomeFriendsWith`
- 禁止 `becomeLoversWith`

**v6.5 目标**: 
Gate 应该高召回率检测候选，即使存在否定词，只要有关系变化的证据就应该触发。Semantic 层负责精确判断。

## 🎯 当前架构失败矩阵

| Case | Gate | Semantic | 根本原因 |

| 12. 假设 + 当前金币转移 | ✗ | ✗ | Gate 将假设识别为真实事件 |

### 核心问题识别

**主要问题 (3/5 失败案例)**: Stage 2 重新扫描完整原文
- Case 1, 6, 7 都是因为 `getSemanticActionProfile` 重新用 `pattern.test(fullText)` 扫描完整原文
- 即使 Stage 1 已经正确识别否定句/过去时/未来时，Stage 2 仍然看到完整文本中的否定词
- **根本原因**: Stage 2 接收的是 `string[]` categories 而非 `ActionEvent[]` with evidence spans

**次要问题 (2/5 失败案例)**: Gate 判定问题
- Case 5: Gate 过度谨慎，因否定词而完全排除关系变化
- Case 12: Gate 无法区分假设语境和真实事件

### 修复优先级

1. **P0 - 必须立即修复**: Stage 2 重新扫描问题
   - 影响范围: 27 个被 semantic 硬编码的 Action
   - 风险等级: 极高（可能导致高风险 Action 如 characterIsKilled 被错误执行）
   - 解决方案: Event-based 架构 + Positive Evidence 隔离

2. **P1 - 重要改进**: Gate 召回率优化
   - 影响范围: 所有 Action
   - 风险等级: 中等（漏判导致功能缺失，但不会误执行）
   - 解决方案: 降低 Gate 阈值，提高召回率，容忍适量误报
