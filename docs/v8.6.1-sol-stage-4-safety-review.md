# V8.6.1 Sol Stage 4 安全与兼容性审查

## 结论

Terra Stage 2/3 经独立代码审查和确定性回归后，`SOL STAGE 4 CODE REVIEW = PASS FOR LUNA STAGE 5`。本轮没有遗留 P0；发现的三项 P1 与若干诊断/确定性缺口均已修复。V8.6.1 总冻结仍为 `NOT READY`，因为 Luna UI、真实 CK3 与 Provider A/B 尚未完成。

## 修复项

### P1：Context Pressure 可能先删除 Memory

原实现会在 Worldline 构建前沿用“剩余不足 192 Token”规则删除 Memory Turn Recall，释放出的空间随后可能被 Worldline 使用。这违反“Worldline 先裁剪、Memory 最后处理”的合同。

现改为：

- Production Worldline 开启时，保留仍能放入硬 Context Limit 的 Memory Turn Recall；Worldline 只消费剩余 Headroom。
- Stable World Anchor 本身放不下时，Stable 与 Dynamic Worldline 一并省略。
- 只有 Memory-only Prompt 已超过硬 Context Limit 时，才在 Worldline 已为零的状态下最后删除 Memory Turn Recall；释放空间不再重新分配给 Worldline。
- 非 Production 路径继续保留原有 192 Token Memory-only 行为。

### P1：Personal Supplemental 共享缓存携带 ACL

Secret 共享候选已经去除正文和 ACL，但 Personal Supplemental 仍可能留下 `knownBy/ownerId`。现 Personal 与 Secret 使用相同的共享缓存最小元数据结构，只保留 opaque fact/content reference、来源、级别和时间安全字段；正文与授权只在 responder 局部重新水合。

### P1：Current Game Truth 未真正高于结构化旧 Memory

旧冲突算法仅按 Knowledge Level 排序，可能让 `PERSONAL_MEMORY` 高于 `COURT_PUBLIC` 的当前 Game Truth。现冲突仲裁显式实现：当前 `GAME_TRUTH/GAMESTATE` > Self > Direct Observation > Personal Memory > Scoped World/Supplemental。不同 `MEMORY` narrative key 的历史经历继续保留，不因当前状态更新而删除。

### P2：确定性与观测

- Worldline formatter 对相同事实集合按来源、实体、字段、fact ID 和内容稳定排序，输入数组顺序不再改变 Prompt fingerprint。
- Direct Observation cache key 同时包含稳定排序的 fact ID、正文和 as-of，避免同 ID 内容变化复用旧主观视图。
- `hardMax=0` 现在被正确视为关闭 Worldline，而不是回退到 900。
- Provider usage 元数据持久化 Memory/Worldline token、Stable Prefix/Dynamic Suffix、World retrieval/policy/format、Memory recall、Prompt build 耗时和两级 Worldline cache hit；不记录正文或 ACL。
