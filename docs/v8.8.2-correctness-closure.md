# V8.8.2 亲属关系正确性闭环实施报告

日期：2026-09-10  
状态：代码与自动化门禁通过；真实 CK3 / Provider 验收待执行

## 实施范围

本轮在 V8.8.1 的 Responder / Relation Anchor / Target 三实体结构上做定向修复，不改 Worldline、Canon、Memory、Prompt 默认开关、UI 或缓存总体架构。

## 已修复问题

- 兄长、弟弟、姐姐、妹妹改为候选出生日与关系主体出生日比较；主体或候选缺失出生日时返回歧义，不再按候选排序或 Runtime ID 猜测。
- 长子、次子、三子、幼子及“最近得的子女”遇到缺失或并列出生日时 fail-closed；子女 alias 也只在同一性别组出生日全部可靠且唯一时生成长幼称谓。
- `RELATION_GENDER_CONFLICT` 使用独立权威约束。玩家称谓中的性别仅作为查询条件，不能覆盖 CK3 / Canonical 性别冲突，也不会输出“必须作为男性亲属处理”。
- 新增按关系类型限定的 `relationBetweenOfTypes(from, to, allowedTypes)`。同一人物同时是配偶与堂亲等多重角色时，配偶问题只使用配偶关系，不被无关关系冲突阻断。
- Anchor 或 Target 未解析时统一禁止注入具体姓名、年龄、地点、生死、头衔、配偶和私人事实，并禁止 Memory、历史常识或模型代选人物。
- “配偶”改为无性别查询；“丈夫”“妻子”继续保留明确性别约束。
- Historical Definition 到 Runtime 绑定要求双向真正一对一，缓存键纳入 Runtime 的全部反向 Definition，映射变化不会复用旧成功结果。
- Targeted Kinship Graph 在刚好达到节点上限时检查尚未展开的邻居；即使队列为空，只要仍有未访问关系端点就标记 `scopeTruncated`。
- `FamilyEntityFactBundle.sourceComplete` 仅在图未截断、目标不是 partial 且关系无诊断时为真；来源不完整会进入家庭事实说明。
