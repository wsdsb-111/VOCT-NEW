# V8.4.1 Terra-4/5 实施报告：中文查询与 Checkpoint Freshness

## 结论

Terra-4 Shared Query Analyzer 与 Terra-5 Checkpoint Freshness/as-of 分层已实现。世界线 Prompt 仍为 opt-in；ACTIVE、来源匹配且未 STALE 的 `autosave.ck3` Checkpoint 才可进入 Prompt。任何旧 Checkpoint 都带明确 as-of 日期，Live 日期只描述 Live Probe 直接提供的事实。

## Terra-4：Shared Query Analyzer

- 新增 `shared-query-analyzer.js`，将 query 与 assist context 解析为 Latin token、CJK 2–4 gram、runtime ID、Historical Definition ID、角色原始名、title key 和本地化显示名。
- “岳飞现在在哪里”会分解出“岳飞”等实体 term，并通过本地化反查命中 runtime character；整句不会作为唯一 term。
- Localized character/title 名的反查使用按实体类型按需构建的 reverse index；后续同类查询复用索引，不会对每个 CJK gram 重扫相同本地化文件。
- 已由 Personal Memory 识别的 out-of-scene `mentionedCharacterIds` 单向交给 Worldline，并写入 query cache key；Worldline 不重做该轮已确认的实体识别。
- Historical Definition ID、runtime ID、raw key 与显示名称始终分离。override conflict、动态文本或不完整 source scan 不产生反向别名。

## Terra-5：Freshness / as-of

`getCheckpointStatus()`、Overview、Diagnostics 与 Prompt Context 现都输出：

- `pipelineState`
- `checkpointAsOf`
- `liveDate`
- `ageDays`
- `freshnessStatus`
- `freshnessReason`

原设计没有规定具体阈值，本实现采用保守且可测试的规则：同日为 `FRESH`，Live 比 Checkpoint 新 1–365 天为 `AGING`，相差至少 366 天、pipeline 非 `ACTIVE`、Live 日期无效或早于 Checkpoint 时为 `STALE`。没有 Live Probe 时，ACTIVE Checkpoint 可保持可用，但 `ageDays` 为未知且 Prompt 明确写出“Live Probe 未提供”。

`STALE` 或 wrong-source Checkpoint 直接返回 `null`，不进入生产 Prompt。topic cache key 已包含 Live 日期、total days、freshness 和 shared mentioned IDs，因此 Live 更新不会复用旧的当前世界投影。

## Prompt 边界

Prompt 现在固定说明：

```text
Checkpoint 世界事实截至：…
Live 当前日期：…
只有 Live Probe 直接提供的信息可表述为 Live 当前日期的实时状态；
未被 Live Probe 更新的可变事实仍仅截至 Checkpoint 日期。
```

这替代了“缺失实时信息时仅可使用 Checkpoint”可能造成的实时误读；Game Truth、Supplemental 与 current world block 的原有排序未改变。
