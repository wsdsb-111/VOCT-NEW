# V8.14.2 姓名、关系上下文与人物披露热修

日期：2026-10-05。功能版本 V8.14.2，App 包版本 2.0.4。

## 用户验收与本次范围

- 用户确认详细长期记忆已经能够正常生成，记为该问题的实机 PASS；不扩展为所有 Memory4、Disclosure 或 Soak Gate 已通过。
- 玩家名字以当前存档的赵太初为准；张道素的归档不应将技术字段 Owner 翻译为“主人”。第三人能够唯一确认时用姓名，如“师父张道正”；不能仅凭泛称猜人物。
- 按用户要求接入已有关系系统，不新建关系推断器；加入“披露时年龄 + 获知日期”。本轮实现和独立 QA 子代理均为 GPT-6 Luna Max，根模型由客户端选择。

## 根因与修复

### 姓名与关系上下文

只读核对确认张道素的已保存 Detail 确有“主人”“天师（师父）”等泛称。原 Durable Prompt 只有数字实体 ID，缺少可核验姓名映射和既有关系上下文，且没有说明 Owner 是记忆持有人。原话具名人物还可能在改写摘要时丢失。

`conversation/conversation.js` 的 Finalization context 复用 `memory4-profile.currentRelationship()`，从现有 `relationsToCharacters`、`relationsToPlayer` 等回读合同生成最小 Owner/Entity、Campaign、关系类型与游戏日期证据。`memory4-entity-context.js` 按 Owner 和片段可见性投影，不将 B 与 C 的关系直接授权给不知情的玩家。仅当前片段说话者/收件人的直接关系，或原文唯一具名人物的关系，进入抽取上下文；晚于来源日期或错误战役的关系拒绝。

姓名来自持有人自身、可验证原文的唯一姓名命中、或已确认直接关系；同名拒绝，短名不擅自扩成全名。assistant 原文只从配对对白引号内授予第三人姓名，混合来源不授名。旁白不能变成身份披露；作者自己的旧 Legacy 文本仍保留，不作为其他人物的知情证据。

Coordinator 在每个抽取片段中提供 `entityNames` / `relationships`，明确 Owner 不是主人，归档用有证据的姓名，角色称谓仅作为有证据的修饰。当前关系只帮助区分人物，不制造历史关系变化、CK3 效果确认或第三人私密知识。恢复快照保存原始相关人物与关系证据，重试不重新借用未来状态。

### 人物认知中的披露

只读核对确认相关人物 `disclosedFacts` 为空，并非仅前端漏显示。原链路扫描 Finalization 摘要，要求摘要整段与原话逐字相同；正常摘要改写会使 `sourceTextVerified` 不成立，真实明确披露也被拒。

对原生 `finalizationVisibilityV1` 链路增加 `finalization_source_paragraph`：原始换行段仍需经过现有 speaker、Presence、可见性和来源校验。已有 annotation 的消息不扩展未标注空隙，私密/小组摘要使相邻未标注段保守保密，消息 ID 0 保留。精确已有来源去重；改写摘要与独立原话可同时保留，不替换 Narrative 原文。

Disclosure 只扫描可验证 spoken 原话；伪造摘要不能提供事实，assistant 第三人称旁白不能当成本人披露。头衔/特质继续匹配当时结构化候选，否定、传闻、假设、问句和歧义拒绝。没有 native flag 的旧上下文保持原来的 withheld/shared-scene 合同，不追认旧未标注消息为公开发言。写入仍在合法 Finalization/Letter Gate 后，归档只读与手动覆盖优先级不变。

### 年龄

新增兼容事实类型 `AGE`，键为 `age_n`、值为数值字符串。仅明确本人当前年龄陈述且与当时 CK3 年龄一致时记录；“我今年23岁”“我二十三岁”可识别，过去/未来/条件/否定/错龄不作为已校验年龄。缺失或空年龄不能变为 0。

候选在 `facts` 最小投影中可合法往返：有效顶层 age 优先；字段缺失/null 才接受唯一合法 AGE，显式空字符串和冲突拒绝。此修复由真实 Conversation → Context → Owner Snapshot → Store 链路用例覆盖。

人物认知展示“披露时年龄：23岁”、获知日期和历史记录标记。AGE 始终 `current:false`，以后 CK3 年龄变化不重算旧值；有效来源及时间门禁仍重验。年龄不提供手工当前事实按钮，不修改实时人物年龄或聊天画像。
