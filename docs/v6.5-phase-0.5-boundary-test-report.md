## 🔴 关键发现：pendingPlayerActionMessage 二选一问题

### TESTABILITY_GAP: Player/NPC Runtime 独立性

**当前架构**:
```javascript
// In Conversation class (line ~6777, ~6789)
const actionMessage = this.pendingPlayerActionMessage ?? placeholder;
```

**问题分析**:
- `??` 操作符导致 Player message 或 NPC reply 的二选一处理
- 当 Player 有动作时，第一个 NPC 的 reply 使用 Player message 作为 actionMessage
- Player 的动作语义污染 NPC 的动作判定

**测试环境限制**:
- 无法在当前测试框架中构造完整 Conversation context
- 无法直接调用 `shouldEvaluateForMessage` 和 `evaluateForCharacter` 的独立组合
- 需要最小化的 Conversation mock 或独立测试 harness

**v6.5 要求**:
```javascript
// Player message evaluation (独立)
evaluateForCharacter(conv, playerCharacter, signal, playerMessage);

// Each NPC reply evaluation (独立)
for (const npc of npcs) {
  evaluateForCharacter(conv, npc, signal, npcReply[npc]);
}
```

## 🎯 v6.5 关键架构要求总结

### P0 - 必须立即修复

#### 1. Player/NPC 独立动作评估 ⚠️ **TESTABILITY_GAP 暴露**

**当前问题**:
```javascript
const actionMessage = this.pendingPlayerActionMessage ?? placeholder;
```

**修复要求**:
- Player message 必须独立评估（对 Player character）
- 每个 NPC reply 必须独立评估（对各自 NPC character）
- 禁止 `playerMessage ?? npcMessage` 二选一逻辑

**影响范围**: 所有多人对话场景

---

#### 2. 假设语境识别 ⚠️ **3/14 测试失败根因**

**当前问题**: Gate 无法区分：
- "如果我杀了他" (假设)
- "我杀了他" (真实)

**修复要求**:
- Gate 可以高召回率触发 hint
- 但 Positive Executed Event 必须排除假设句
- Event Parser 必须识别假设标记词（如果、也许、可能）

**影响案例**: Case H, J

---

### P1 - 重要改进

#### 3. Gold Gate 覆盖率 ⚠️ **1/14 测试失败**

**当前问题**: "我现在把50金币交给你" 未触发 `gold` category

**修复要求**:
- 提高 gold 相关关键词召回率
- 考虑添加"现在"、"把"、"交给"等组合模式

---

#### 4. Event-based 输出架构

**当前**: `string[]` categories

**v6.5 要求**: `ActionEvent[]` 结构
```javascript
{
  eventId: string,
  category: string,
  evidence: { text, start, end },
  executionStatus: "completed" | "attempted" | "planned",
  resultStatus: "succeeded" | "failed" | null
}
```

---

#### 5. 多 Event 边界和顺序

**要求**:
- 一条消息可以包含多个独立 Events
- Event 必须保持文本出现顺序
- Event identity 不能只由 category 决定
- Event-level dedupe 必须考虑: speaker + category + evidence + target

## 🎯 建议的 v6.5 Phase 1 重点

基于 Phase 0 + Phase 0.5 的发现，建议 Phase 1 优先解决：

### Phase 1.A: Event-based Parser + Positive Evidence 隔离 ⭐⭐⭐

**解决问题**:
- Phase 0 的 5 个 KNOWN_V6.4_FAILURE (Stage 2 重新扫描)
- Phase 0.5 的 2 个假设语境失败

**关键变化**:
1. Stage 1 输出 `ActionEvent[]` 而非 `string[]` categories
2. 每个 Event 包含 Positive Evidence span
3. Stage 2 只处理 Event.evidence，禁止访问完整原文
4. Event Parser 识别假设、回忆、传闻标记

---

### Phase 1.B: Player/NPC 独立评估 ⭐⭐

**解决问题**:
- Phase 0.5 的 TESTABILITY_GAP
- pendingPlayerActionMessage 二选一架构缺陷

**关键变化**:
```javascript
// Player
await ActionEngine.evaluateForCharacter(conv, playerChar, signal, playerMessage);

// Each NPC independently
for (const npc of conv.npcQueue) {
  await ActionEngine.evaluateForCharacter(conv, npc, signal, npcReply[npc.id]);
}
```

---

### Phase 1.C: Gold Gate 覆盖率改进 ⭐

**解决问题**:
- Phase 0.5 的 1 个 GOLD_GATE_COVERAGE_FAILURE
