# VOTC v7.9.2 Social Consequence Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a scene-scoped Social Consequence Engine that turns verified dialogue and confirmed CK3 events into bounded Opinion and relationship actions without regressing Action API usage, Chat cache stability, Memory Engine 2.5 recall, or the v7.9.1 Hotfix.

**Architecture:** A post-action social pipeline builds immutable evidence through `social-context-provider.js`, resolves locally in Performance or through one gated structured Judge in Precision, validates knowledge and relationship transitions locally, then emits synthetic `social:` ActionEvents into the existing Action Engine validation, approval, and executor path. Balanced bypasses the pipeline, Memory recall is reused rather than repeated, and all cooldown state remains on the current Conversation.

**Tech Stack:** Bundled Electron main process, CommonJS JavaScript, Node built-in `assert`, existing Action Engine 3.0, Memory Engine 2.5, structured Action Provider requests.

**Spec:** `docs/VOTC_v7.9.2_Social_Consequence_Engine_设计规格.md`

## Global Constraints

- Core version becomes `7.9.2`; Action Engine remains `3.0`; Memory Engine remains `2.5`; Electron package version remains `2.0.4`.
- Balanced preserves v7.8.3-compatible behavior and never enters the Social Consequence Engine.
- Performance never sends a Social Provider request.
- Precision calls Social Judge only after a positive Social Gate and never sends individual Judge results through Stage B.
- Social cooldown, dedupe, and temporary evidence are Conversation-scoped and never persisted.
- Social Engine reuses the recall already built for the current NPC response and must not call Memory Engine retrieval APIs.
- Dynamic Social Prompt data follows the immutable `VOTC_SOCIAL_CONSEQUENCE_V1` prefix and stable schema.
- Per message limits are 2 direct Opinion, 2 observer Opinion, and 1 relationship transition.
- Existing uncommitted v7.9.1 Hotfix and UI changes are the implementation baseline and must not be reverted or overwritten.
- Use `apply_patch` for source edits; do not rebundle or broadly reformat packaged files.
- Every production behavior starts with a failing deterministic test and a verified RED result.
