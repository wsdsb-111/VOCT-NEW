## 陌生人身份修复

- `resources/app/out/main/prompts/prompt-builder.js` 在现有动态 `responder-game-facts` 中增加玩家身份知情边界。人物描述、在场表、场景和说话者前缀中的姓名、全名、家族、头衔与官职属于后台标签，不能单独证明 NPC 已知身份。
- 当前回合开始交谈、同场、SHARED_SCENE、本次相遇的直接交谈次数及高好感不授予身份知识。明确的当前关系、实际血亲、本角色获准记忆、获准公开事实及正文介绍仍可使用；每个来源只支持明确给出的那项姓名或身份，化名不能解锁后台真名或整包资料。缺少记录也不等于从未见过。
- 独立 QA 发现关系源中的“陌生人”“无明确关系”“好感：90”和 `No relationship` 等描述也被当作相识证据；修复只收紧本轮 Prompt 门禁。正式关系须为精确的已知中英文关系标签，中文亲属复用现有 Relation Intent 的精确词项，不从否定或任意描述中取关键词授权。
- 没有改变 Action 人物绑定、Cache Anchor、布局版本、Prompt Block ID、用户模板或旧存储格式。V5/V6/V7、GLM Cache v2、V8.13 和自定义模板均保留动态门禁；旧缓存中的后台标签也服从当前边界。

## D 派生生命周期

- 新增 `resources/app/out/main/memory-system/memory4-derived.js`，由 Coordinator 接入。Year 按已知事件年份组织，Life 按时期保留可追溯片段；均是 Campaign × Owner 下的可重建视图，不替代 Detail 事实原本。`planned` 或未知事件时间不借用交谈日期生成事件年度事实。
- 派生文件保留 `sourceRevisionSet`、来源 hash、revision、dirty 与手工模式。Canonical Detail 的编辑、删除、状态和来源版本变化传播失效；dirty 或无法重验来源的 Year/Life 不进入当前有效召回，旧 Profile 指针和已保留动态历史也需重新核验。
- 每个 Owner 的后台构建串行处理并支持取消；发布前再次比较当前 Canonical、派生文件及来源版本，异步旧结果不能覆盖更新的 Detail 或手工编辑。任务使用所属战役和 Provider 快照，失败状态保留诊断，不能伪装成新鲜视图。
- 已提交 Finalization 可凭持久化的私有 scope/commit proof 后台构建原所属战役，不依赖当前活动战役；UI 和 Lazy 任务仍要求当前 Campaign，Renderer 不能伪造此后台权限。诊断仅记派生状态、数量、版本与耗时，不记录原文、Query 或 Provider 配置。
- 不超预算的内容直接由已验证来源组装；需要压缩时使用摘要模型，要求结构化返回、来源 ID 完整且不重复，并保留承诺条件、否定与传闻限定。Year 上限 1000 Token；失败、截断或来源不匹配不发布替代视图。真实 Provider 质量与成本尚待验证。
- 手工编辑进入 `manual_override`。底层变化后保留手工文本并提示冲突；“保留手工版本”不把失效来源变成有效来源，自动任务不能静默覆盖。显式覆盖重建仍须匹配 expected revision。
- Recall 只选择与当前实体、话题和时间窗相关的 Year/Life 片段，继续服从 C 的多实体共用 Overview≤1、Detail≤2、整包预算、Owner/Knowledge、获得时间及 V8.13 动态边界。交谈年份概览与磁盘事件年度视图区分，精确日期查询不使用模糊概览补位。

## E 管理与迁移

- `resources/app/out/renderer/memory4-manager.js` / `memory4-manager.css` 接入原摘要页，分为人物认知、官方追忆、人生记忆、年度记忆、详细长期记忆及 Legacy 对话摘要。Official 保持只读；旧摘要搜索与既有绑定入口继续使用原路径。
- `summaries/summaries-manager.js`、`ipc/register-ipc.js` 与 `preload/preload.js` 提供 Owner 数据、单条 Detail、来源和受限变更入口。主进程验证当前会话、Campaign、Owner 和 expected revision；切换战役、过期版本或来源变化拒绝旧页面操作。
- Known Entity / Detail 导航按元数据分页，正文与来源按需打开。Detail 编辑/删除经 Canonical Store 处理，再失效 Year/Life 与动态召回；冻结 Recent2、官方追忆及会话前缀继续保持原合同。
- Year/Life 支持折叠、来源、手工编辑和重新生成。dirty/manual 状态单独显示，模型生成和覆盖操作显式确认；可取消当前派生任务。三主题内部键仍为 `parchment`、`knight`、`ink`，玩家名称为“游牧”“骑士”“水墨”；新面板三主题及窄窗口隔离打包交互已通过，不代替玩家配置实测。
- Legacy 重压缩按玩家选择的单篇来源执行，复核 source hash 后沿既有可见来源提取与部分覆盖规则转换。成功回复保留的实际 Legacy 注入引用也可排入 Lazy 转换，不能凭候选列表触发。原摘要保留，来源证据不足继续走 Legacy；不进行全量强制迁移，不用一次部分转换屏蔽整篇旧叙事。Bulk Binding 仍沿已有 Preview→确认→revision 校验路径，真实存档 Gate 未完成。
- Lazy 每批最多 8 个获准事实，部分覆盖可续进，墓碑保留已覆盖事实的抑制且不再次转换删除项。时间提取仅接受可重验的 Legacy 精确片段 ID/hash，相对时间以原来源获得日期为基准，不伪造旧聊天 message ID；旧 2.5 的通用 temporal normalize 默认合同不变。
