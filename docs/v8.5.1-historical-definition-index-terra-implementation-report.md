# V8.5.1 Terra：Historical Definition Index 实施报告

日期：2026-09-04。范围：V8.5.1 第 2 步后端施工；不含 Luna 可视化和 Sol 最终审查。

## 已实现

- 新增 `resources/app/out/main/worldline/historical-definition-index.js`。它只扫描当前 CK3 用户目录的 `dlc_load.json` 所启用 Mod 和可推导的 Base Game；人物、dynasty 与简中 localization 在 Worker 内读取。完整中文名只会由可验证的单字姓本地化链和给名组合生成，原始 Definition ID、文件名和注释不会变成姓名。
- Worker 仅把 generation metadata 和按查询命中的有界候选返回主进程；整份索引不跨线程传输。冷启动/未完成查询返回不完整状态，既有对话不会等待扫描。
- revision 包含历史人物、dynasty、localization 源内容及 alias policy。多来源同 Definition 字段不同会保留冲突；无完整来源、无 Runtime、或冲突均不可确认身份。
- `historical-identity-resolver.js` 允许索引提供 Definition metadata 作通用候选证据；现有阈值不变。它交叉 `definitionToRuntime` 与 `runtimeToDefinitions`，并将不互相印证的绑定作为硬冲突。
- `shared-query-analyzer.js` 将 Manual catalog 作为别名/候选补充而非人物白名单，并将通用索引候选与同一 alias 合并。只有 `RESOLVED` 进入 Game Truth；`SOURCE_INCOMPLETE`、`DEFINITION_FOUND_RUNTIME_MISSING`、`REJECTED_BY_EVIDENCE` 与 `AMBIGUOUS` 保留为 coverage/诊断数据。
- `worldline-service.js` 在异步诊断前有界准备查询词，复用一次 Shared Query Analysis；topic cache 加入 index revision，诊断增量暴露 index 状态和 coverage。默认 Prompt、存档、Supplemental、Memory 和 CK3 文件均未写入。

## 明确边界

- 100 条是隔离 fixture 矩阵，不是用户当前 Playset/存档的实机统计；15 人真实 Checkpoint、完整来源覆盖率和 Electron/CK3 UI 验收仍交 Luna/Sol。
- 当前实现没有猜测 CK3 Mod 覆盖赢家，也不会把 source comment、raw key 或局部名升级为完整历史姓名。
- 本轮不新增 Prompt Default On，不修改 Renderer，也不宣称 V8.5.1 INTERNAL FREEZE。
