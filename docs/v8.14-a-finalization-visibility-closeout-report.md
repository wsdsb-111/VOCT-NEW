## 范围与合同

- 撤回前一次未完成施工对实时 Prompt/逐片段 Sidecar 的改造；`Conversation` 的实时生成、V8.13 冻结前缀、Recent2、Legacy/Temporal Recall 均不增加新协议。仅在 Finalization context 设置 `finalizationVisibilityV1`，旧快照/旧摘要无此标记时继续原有兼容路径。
- Final Summary Extractor 对新终局要求 `source`、messageIds、speakerIds、participants 与 visibility；公开/私密混合、耳语、未察觉行为要求拆段。`finalization-visibility.js` 按原始消息、发言者、Presence、明示耳语对象及转述信号验证；不能确认共享边界时拒绝并重试，仍不满足则留在恢复队列，不能冒充成功。
- `KnowledgeService` 在新合同下忽略模型提供的 `knownBy`，按校验后的受众重算；private 仅作者，participants 仅合法参与者与在场交集，known_group 需要明确对象。旧数据由 Legacy Bridge 保留，不强制转成旁观者的 Memory4 Detail。
- Narrative commit 后 Memory4 仅接纳已提交 Episode 中带校验版本的段落，再逐 Owner 核对 `knownBy`、来源消息与 Presence；错误记为 `EXTRACTION_FAILED`，不降为 `NO_DURABLE_CONTENT`。旧消息仍保守保留作者视角。Known Entity 的共同场景来自 Presence；直接互动只由明确指向该人物的可见言语支持，不能由一般发言或同场推断。Memory4 正式 Recall 仍关闭。
- `memory4-contract.js` 记录每个可信段落的完整来源 messageIds，保留 spoken/reported/rumor 来源；言语转述不能被模型提升为观察到的 CK3 事实。新终局 Narrative 的转述/传闻知情状态标为 told。没有新增 Prompt cache anchor、实时标签、玩家输入分类器或迁移作业。

## 实机失败后的定向修复

- 用户二人对话的真实恢复快照（仅只读核对元数据/错误码，不复制对话内容）显示：10 条消息、2 个在场窗口，失败为 `visibility_shared_audience_unverified` 与 3 次 `summary_segment_crosses_visibility_boundary`。两条 NPC 消息在前段出现“心里”，其后仍有多段内容。旧校验只接受私密词之前的原文，误拒后续公开段落；模型只列发言者为事件参与者时也被误判为摘要失败。
- 现在允许共享段引用源消息中**不含私密/耳语线索的完整原文段落**，不再把合法的作者单人 `participants` 段直接判为质量失败；它仍只授予作者知情，不扩给旁观者。遇到模型将跨可见性段落改写成不可核验的共享段时，终局层按原消息的换行段落做保守替换：含私密词的段落仅归发言者，明示且可核验的耳语仅归发言者与对象，其余原文段落依据在场窗口共享；同时丢弃该消息中无法核验的模型 Durable 候选。没有明确段落边界/对象时仍拒绝，不猜测知情者。
- 失败恢复不再因 visibility 质量错误强制切为分块摘要；三人以上的分块 Presence 标记补齐本地 `game_fact` 来源。补充二人、三人完整终局提交、二人失败快照重试、三人分块 Presence 用例。上述修复仍未做新的 CK3/Provider 实机复测，A Gate 保持未验收。
