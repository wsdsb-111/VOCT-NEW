# V8.6 Sol Stage 4：Subjective Backend Safety Review

日期：2026-09-06  
阶段结论：`SOL STAGE 4 CODE REVIEW = PASS FOR LUNA STAGE 5`  
版本结论：`V8.6 FREEZE = NOT READY`

## 审查结论

本阶段独立复核 Terra Stage 3 的共享候选、Character Knowledge、Scope、Memory 和逐 responder Subjective World View。审查发现并修复共享缓存上下文串用、主观缓存撤权失效、秘密正文进入共享对象、DTO 携带访问控制元数据、未知 responder 可进入构建流程等 P0/P1 风险。修复后，Phase A 后端可以作为 Luna Stage 5 的只读安全数据源，但尚未接入生产 Prompt。

## 已修复问题

- 共享候选缓存键现在覆盖 Checkpoint/source/settings/build revision、Supplemental/Localization/Historical revision、retrieval policy、查询、assist context、mentioned entity 和 Live 状态；完全相同的安全上下文才复用结果，并保持一次共享检索。
- responder 缓存键现在覆盖 conversation、turn、scene、presence、direct observation、Memory 内容/授权、逐实体 Scope 和 policy version。`knownBy` 撤权、在场变化或观察事实变化都会失效旧 View。
- 未出现在当前 Snapshot 的 responder 在读取 Memory 前即被拒绝，不再构造伪造主体的主观世界。
- 共享候选对 Hidden、SELF、DIRECT_OBSERVATION、PERSONAL_MEMORY 和 SECRET 正文进行脱敏；缓存写入和返回均深拷贝，调用方不能修改后续命中结果。
- Subjective DTO 改为字段白名单，移除 `knownBy`、参与者 ID/姓名、观察者和 ACL 元数据；字符串和数组均有界，24 条超长中文事实保持在 100 KB 目标内，并保留 500 KB 硬上限。
- 每个 responder 最多保留 8 个主观缓存条目，全局缓存仍有界；诊断只返回 fact ID、decision 和 reason。
- Scope 改为逐事实实体解析；`subjectId=null` 不再误当作 responder，自身、同 Court、同 Realm 依据当前 Snapshot 判定。只有 Live 日期不足以证明 Live Scope，仍按 `CHECKPOINT` 处理。
- 冲突裁决不再允许不可见 Secret 压制更高权威的当前 SELF；旧个人状态不会覆盖当前 SELF，不同 Memory/事件事实也不会仅因类型相同而相互吞并。
- 指标补齐共享检索、Policy、Scope、Memory、汇总、缓存层、候选数、输出字节与总耗时，供 Luna 只读展示和后续 Sol 性能 Gate 使用。

## Prompt 与入口审查

| 入口 | 当前状态 | Stage 4 结论 |
| --- | --- | --- |
| `Conversation -> getPromptContext` | 仍在生产对话中使用 | 旧兼容路径保持不变 |
| Historical / World / Supplemental / Character / Relationship / Memory / Rolling Summary | 仍由旧 PromptBuilder 路径注入 | 本阶段未重复注入，也未改变现有开关 |
| `getSubjectiveWorldView` | 仅后端服务与自动化测试可调用 | 尚未进入 Conversation 或 Prompt |
| Subjective IPC / preload / renderer | 尚未接入 | 交由 Luna Stage 5 按下述合同实施 |

因此，Phase A 没有意外启用新 Prompt，也没有发生新旧世界上下文重复注入；但旧 Prompt 路径尚未接受 Character Knowledge Policy 过滤。V8.6 的“NPC 非全知”生产目标尚不能签发，最终 Prompt 切换必须在 Luna UI 后由 Sol Stage 6 单独审查。

## Luna Stage 5 安全交接合同

1. 只允许后端验证当前 Snapshot 中真实存在的 responder；Renderer 传入的主体、在场、观察和授权信息不能直接成为事实。
2. IPC 只能返回安全的 Subjective World DTO，禁止返回共享候选池、旧 `getPromptContext` 结果、原始 Memory 记录或访问控制字段。
3. A/B 对照只展示计数、命中层和 opaque fact ID；默认玩家层不得显示被过滤事实的标题、正文、参与者或 secret metadata。
4. 列表必须分页或懒展开，并保留后端 24 条候选、100 KB 目标和 500 KB 硬上限；Renderer 不得重新拼装未过滤对象。
5. Stage 5 只接诊断 UI，不得顺带切换生产 Prompt、`promptIntegrationEnabled` 或用户持久化格式。
