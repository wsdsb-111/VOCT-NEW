# V8.12 Part 3：Memory Engine 3.0 施工记录

状态：**代码与自动化回归已接入；Part 3 实机 Gate 尚未签发。** 用户已确认 Part 3 前置验收通过并要求以 **64 块**为唯一摘要分块上限。这里记录实际代码边界，不把自动化结果冒充 CK3 / Provider 验收。

## 已接入

- `memory-engine.js` 将摘要分块硬上限统一为 64；`version.js` 将 `MEMORY_ENGINE_VERSION` 设为 `3.0`，继续读取旧 2.3/2.4/2.5 人物摘要。底层 `schemaVersion: 2`、人物目录、写入路径与迁移边界不改。容量上限不保证 64 块都能在任意 Provider 的输出预算内完成，超限仍显式失败并保留恢复快照。
- 回应者自己的 `owner × counterpart` 最近两篇摘要在会话内冻结；日期索引按游戏日期和 `totalDays` 检索，当前问题触发的 Temporal / Topic / Important 共用最多 3 篇动态 Extra，与冻结摘要去重。没有可信当前游戏日期时，不凭电脑时间推断模糊时间。保留 2.x 召回路由回退开关。
- `character_memory_manager.database` 与角色 `alive_data.memories` 联合构建只读持有人映射。官方追忆只允许所属 NPC 的有效 Save Memory；按日期排序、完整条目预算裁剪，最多 1000 Token。已安全确定的常见类型可生成可读文本；未可靠解析的类型或动态本地化暂记 `UNRESOLVED_CK3_MEMORY`，不以原始键或历史传记臆造事实。读取默认 Shadow，正式 Prompt 注入默认关闭，可在世界书开发者区诊断与切换。
- GLM Cache v2 的既有稳定块 ID/锚点保留，稳定结构化记忆、Recent2 与场外快照随 Responder 冻结；Temporal Extra 和按轮 Worldline 仍在当前用户消息之后的动态尾部。旧 `past_summaries` 块对 3.0 也跳过，避免重复注入。
- Historical Retrieval 在正式对话及异步开发者诊断路径使用 Worker，完成 Index/Projection 读取、校验、解压、Timeline Diff 和 Top-K；同步服务方法保留给兼容调用与测试。无人物 RANGE 纳入战争，Realm Pair 战争优先，历史 LOCATION 不再因同宫廷自动放行；超长 RANGE 保留边界和可识别变化点后有界采样。

## 合同与开关

世界书设置新增 `v812MemoryEngine3Enabled`（默认 true）、`v812TemporalSummaryRecallEnabled`（默认 true）、`v812OfficialRecollectionEnabled`（默认 true，仅只读 Shadow）与 `v812OfficialRecollectionPromptEnabled`（默认 false）。关闭正式注入不会删除已读取的 Save Memory；旧摘要文件不迁移、不重写。官方追忆与历史时间线均不得覆盖当前 CK3 状态。`worldline:getOfficialRecollection` 只读且要求有效当前检查点和数字回应者 ID。
