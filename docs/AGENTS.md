# 文档目录维护规则

## 目录职责

- `docs/README.md` 是文档分类和推荐阅读顺序的唯一入口。
- 根目录 `CHANGELOG.md` 只维护版本顺序、用户可见摘要和详细文档链接，不复制完整实现记录。
- `docs/V6阶段优化记录.md` 和 `docs/V7阶段优化记录.md` 分别是 V6/V6.x、V7/V7.x 的连续阶段记录。
- 版本设计、实施报告和 UI 资源提示词均放在 `docs/`，根目录只保留项目入口 `README.md`。

## 编写规则

- 只记录仓库中实际存在、已经实现或明确标注为限制的内容，不创建指向不存在文件的链接。
- 既有版本文档保留历史结论；修订应追加实施结果、验证边界和迁移说明。
- 新版本文档采用 `VOTC_vX.Y_主题.md`；实施报告采用 `vX.Y-implementation-report.md`；不要在根目录新增版本散文档。
- 文档中的路径使用仓库相对路径，中文文件名保持现有命名，不为整理而重命名历史阶段记录。

## 验证

修改文档后，从仓库根目录检查链接和状态：

```powershell
rg -n "\.md\)|\.hbs`|\.js`" README.md docs --glob '*.md'
git status --short
```

确认新增或移动的文档存在，且没有引用已经删除或不存在的模板、源码和构建产物。文档整理不需要运行 Electron 或 CK3；如果同时修改代码，仍须遵守根目录及相应子目录的测试要求。
