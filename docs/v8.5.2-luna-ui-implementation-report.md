## 1. 交付结论

本阶段只修改前端展示层，不改变 Sol 已冻结的身份门禁、Terra Domain DTO、Worker 生命周期、Cache authority、Prompt 或 Game Truth。V8.5.2 additive `entityResolutions` 现在可以在世界线诊断页逐实体展示，身份结论与世界线差异保持分层。

已实现：

- `HISTORICAL + RESOLVED` 显示“已确认历史人物”。
- `RUNTIME_NATIVE + RESOLVED` 显示“已确认当前存档角色”。
- `RUNTIME_NATIVE + AMBIGUOUS` 显示“当前存档存在多个同名角色”。
- `SOURCE_INCOMPLETE`、`DEFINITION_FOUND_RUNTIME_MISSING`、`REJECTED_BY_EVIDENCE` 和 `REJECTED_BY_CONFLICT` 使用可读的 fail-closed 文案。
- 年龄、父母、兄弟、婚姻和子女差异只显示在懒展开的“逐实体身份与世界线差异”面板，出生偏移使用：`当前角色出生时间与历史基准存在偏移，不影响已确认的历史身份。`。
- 多实体诊断不再以 `coverageItems[0]` 代表整句查询；每个 `entityResolutions` 都保留自己的身份状态、候选数量、来源完整性和差异列表。
- Historical Mapping 的常规玩家行只显示验证后的历史名、当前角色名、语义状态、置信度和说明；`Fei_name11`、`nansong_yue_085`、Runtime ID、Definition ID 等值仅留在明确标识为“开发者原始数据”的 C 层。
- Prompt 诊断继续保持 A（玩家摘要）→ B（可读判定依据 / Worldline Difference）→ C（开发者原始追踪）的三层结构。候选和裁剪列表继续懒渲染并限制为每页 50 条。

## 4. 安全与交接边界

- Luna 不参与 Identity Gate、Runtime/Definition binding、Numeric namespace、Worker generation、缓存失效或 Game Truth 注入。
- Worldline Difference 不改变 `resolutionStatus`，当前存档事实仍由后端优先提供。
- `SIBLING_DIFFERENT` 在 UI 侧支持合同代码，但 Terra 尚未冻结可验证兄弟关系来源；没有数据就不显示差异，不制造事实。
- 大型真实存档的 DTO 有界性由 Sol Stage 3 保证；Luna 只按现有分页/懒渲染消费，不恢复完整 checkpoint 或 Definition records。
- 本报告完成后应切换 **Sol**，执行 Stage 5 UI/DTO boundary review，重点检查 A/B/C 层 raw 值泄漏、旧 DTO 兼容、SOURCE_INCOMPLETE 展示优先级和九组合视觉脚本的实际运行结果。
