# V8.3 前置修复实施报告

日期：2026-08-31  
应用基线：V8.1（`VOTC_CORE_VERSION = 8.1.0`）

## 范围

本轮只处理进入 Historical Figure Resolver 前可以由仓库代码完成的 Gate A–C：Windows EOL 测试兼容、GameData 实例级 Dynamic History 状态，以及 Shadow metadata 的非枚举和幂等加固。Memory、Conversation、Action、Letter、Run Command Queue、Date Producer、Prompt Stable Prefix、Relationship 和 Kinship 语义保持冻结。

## 已修复

### P1-01：Windows EOL 静态测试假失败

`scripts/test-v7.10-rc2-action-config.js` 现在统一将读取的 `main.js`、Renderer、ActionEngine、SettingsRepository 和 ProviderService 源码从 CRLF 归一化为 LF，再执行原有静态合同断言。正式 DeepSeek Action 配置、Provider 参数和 Action Prompt 未修改。

全仓 `scripts/test-*.js` 扫描确认，其他包含换行字面量的源码检查已经自行归一化，或检查的是测试运行时由 Node 生成的临时文件，不依赖 Git checkout EOL。

### P1-03：Global last-writer state

`DynamicHistoryService` 不再保存全局 `this.worldlineState`。每次处理结果绑定到对应 GameData 的隐藏 `dynamicHistory` 容器：

```js
gameData.dynamicHistory = {
  campaignId,
  campaignIdentity,
  worldlineState,
  persistenceStatus
};
```

`getWorldlineState(gameData)` 只读取传入实例；不传 GameData 时返回 `null`。连续处理 Campaign A、Campaign B 后，A 的状态仍从 A 自身读取，不会被 B 覆盖。

### P2-01 / P2-02：Shadow metadata 加固

`dynamicHistory` 和兼容入口 `historicalCampaignIdentity` 均为 non-enumerable、non-configurable，只读引用，因此不会进入 `Object.keys()`、对象展开或 `JSON.stringify()`。同一 GameData 再次执行 `updateFromGameData()` 会更新既有隐藏容器，不再触发不可配置属性重定义异常。
