## 证据与修复

### 隐私补充审计

- 真实默认模板红测：`GameData.currentEmperorTitle` 绕过已过滤人物的头衔，`locationController` 保留第三人的带头衔全名。`trait-profile-selector.js` 现在按唯一源角色的投影重建这两个别名；无源或歧义时清空。已披露头衔、姓名标识和 NPC 自身完整资料保留，原始 GameData 不改。
- 真实 LetterPromptBuilder、`letter.hbs` 与 `pListLetter.js` 红测：远程收件人会直接获得发送方当前现场地点。信件专用投影清空 `gameData.location/locationController`；正文中明确写出的地点仍保留，收件角色仍知晓自己的全部特质。
- 补充真实 builder 红测：日志 `playerName/aiName` 使用带头衔 Getter，自定义模板可绕过人物 Profile。现在按 ID 重映射到同一份角色投影，非本人安全姓名与本人完整名称分别保留；无法绑定角色时清空。Conversation 在场/暂离名单仅使用个人姓名，不再发送裸 fullName，UI 名单不改，已授权头衔仍由 Profile 提供。原始日志和 GameData 不改。
- 多人迟到加入的真实 Conversation 方法与分段摘要未复现额外泄漏；默认脚本、模板及自定义上下文的别名哨兵通过。不修改 GLM 配置、Block IDs 或 Cache Anchor。
- 玛蒂尔达复述 ABC 私聊的实机事故仍不能仅凭这些合成漏洞定案。前轮首个请求记忆指纹只匹配她自身官方追忆，缺少完整请求正文；本轮新增确定性防护不等于已证明全部私聊细节的实际来源。

### 信件停在 30 天

只读运行数据：待发信基准日未获 DATE 推进，状态仍为 `pending_delivery`，摘要 `not_started`；多次 `date_producer_rearm` 已到期隔离，未找到它们的游戏 ACK。日志最后更新时间早于这些请求，不能据此区分游戏未运行、错误加载配置或 runner 缺失。

已确认的静态缺口及最小修复：

1. runner 在 `talk_scene` 时销毁自身，重启命令又依赖 runner 执行，形成无法自举的路径。Mod 保留两秒状态循环，对话时仅暂停文件执行。
2. 原启动逻辑在 `on_game_start` 内使用 `every_player`。原版明确将需要玩家作用域的初始化放在 `on_game_start_after_lobby`；现保留原载入标记，把 runner 自举放到该 hook，一天后启动既有 `.9998`，并直接记录一次 DATE。
3. LetterManager 原扫描可使用最新载入边界之前的 DATE。现以日志身份和 LOAD_SESSION 物理字节偏移绑定日期；重复 epoch 的新载入也清旧日，只有同一物理标记重复交付才幂等。tail 漏过的新边界可扫描恢复；旧偏移、日志替换和截断不得沿用旧日。扫描单 FD，未变化日志使用 identity/size/mtime 缓存。
4. 独立红测复现扫描已换会话、迟到旧 DATE callback 仍可推进到期投递。tail 现要求当前物理会话确有匹配 DATE；已有绑定时不可读、缺 LOAD、旧 token/旧偏移都不能退回 legacy 或更新 freshness。冷启动也先识别物理会话；仅从未绑定且无 LOAD 的旧日志保留既有行为。拒绝路径不修改待发信或接受锁。

没有修改真实 pending 文件、接受锁或 RunFile 队列；没有盲目重发。官方 Artifact Effect、ACK 去重与接收后摘要门禁保持。未接收信件不生成“已经发生”的摘要；DATE 恢复后仍需游戏实际执行投递和接受才进入原摘要链。

App/Mod 按方案 B 独立发布。本机 Workshop `3346777360` 已应用两个文件，仓库原样快照、最新 SHA-256 与部署要求见 [外部运行依赖](EXTERNAL_RUNTIME_DEPENDENCIES.md) 和 [补丁说明](../compatibility-patches/v8.15.2-letter-runner/README.md)。Steam 更新可能覆盖，完全重启 CK3 才能加载本轮 GUI/on_action。

### 世界记忆当前日期与范围

- 真实隔离窗口经 Renderer、Preload、IPC 和 Canon Worker，五种范围均可用 CURRENT_DATE 保存：PUBLIC_WORLD、COURT_PUBLIC、REALM_PUBLIC、PERSONAL、SECRET。宫廷/领地保留 scopeEntityId，个人/秘密保留 knownBy，不降级为全球公开。
- 已复现界面缺陷：非法当前日期的错误位于编辑器顶部，提交位置视口看不到。保存按钮所在操作区现在显示可访问的错误或成功状态；日期不合法、缺范围人物或知情人明确拒绝，未成功不会显示已保存。
- 已复现检索缺口：人物选择器忽略经过校验的全名索引。现在允许同 scope 已验证全名查询，并提供“选择当前玩家”；玩家始终绑定当前 Checkpoint，不能因 live 玩家不同而换存档。无查询候选只读取前 50 个角色资料，报告总数，不物化全部角色。
- 有效 live 日期优先于 Checkpoint；非空非法 live 日期仍拒绝，不偷偷使用旧存档日期。当前本机只读档案的日期和 playerId 一致，玩家仅有 firstName、没有 fullName，离线日志没有有效 live 日期。因此不能宣称已复现用户所有保存失败的具体后台原因；本轮修复可见反馈和已验证的姓名检索问题。
