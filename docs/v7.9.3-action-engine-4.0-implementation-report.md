# VOTC v7.9.3 / Action Engine 4.0 实施报告

## 版本与范围

- 核心版本：v7.9.3
- Action Engine：4.0
- Memory Engine：2.5
- 外挂 UI：2.0.4
- CK3 Workshop：2.0.4

本轮按《VOTC v7.9.3 Action Engine 4.0 正式实施规格书》的七阶段路线实施。AE3 文件作为冻结 Legacy 保留，只能通过显式 Engine Version 3 整体回滚；AE4 当前消息失败不会逐消息回退到 AE3。

## 已实现

1. `action-system/action-engine.js` 仅负责版本路由，AE4 位于 `action-system/v4/`；Balanced、空值和非法模式持久迁移为 Performance。
2. C2 Catalog 只执行角色、目标、资源、关系和 `Action.check()` 等状态合法性预筛，不解释当前对白语义；目标合法性统一读取 `targetPolicy`，未声明默认 `other_only`，未知值 fail-closed。
3. Precision 对每条有效 RP 对白恰好调用一次 Q2 Selector；稳定前缀包含 AE4 规则、Master Dictionary 与 Q2 Schema，动态后缀只包含 Available Actions、参与者、相关状态、最近四轮、Pending 和当前消息。
4. Performance 使用 ExecutionFormGuard、确定性 Fast Resolver、recall-biased Hint 与最多一次 Compact Selector；Hint 没有动作选择或执行权限。
5. Precision 与 Performance 在 Proposal 后汇入同一确定性管线；缺失参数、非法 Target、不可用 Action、关系非法和游戏状态变化均拒绝，不猜值、不替换相似动作、不 Clamp；Executor 明确区分 `pre_send_failure`、`confirmed_failure`、`post_send_unknown` 与 `confirmed_success`。
6. Explicit Consent Pending 带独立 schemaVersion，默认 TTL 10 轮；重大双方关系和联盟必须先 Pending，再由正确目标接受后重新校验与执行。模式切换不清空 Pending。
7. Batch 默认独立；同一角色对的友好/敌对关系冲突双方均抑制；依赖只读取元数据；单轮最多三个 Decision。
8. Direct Opinion 仅允许 `-3/-2/-1/+1/+2/+3`，并使用同因去重、100%→40%→0% 冷却、Direct ±5 与全部 Social ±10 上限。Precision 直接社会语义不再并行调用 Social Judge。
9. M2 Runtime Funnel 和 Selector Cache 字段已写入本地用量记录；用量页显示 AE4 的双模式、Funnel、Selector 调用和缓存命中率。
10. Master Compact Action Dictionary 已升级为稳定 Action Contract，Precision 与 Compact Selector 共用 `shortDescription`、`sourceRole`、`targetRole`、`executionMode`、`targetPolicy`、参数、关系迁移和风险字段；动态 Catalog 只补充本轮合法角色、目标与参数，不重复发送长 description。
11. `pending_response` 在查找 Pending、检查 TTL 和响应者身份之前，必须提供非空且全部属于近期 Dialogue 的 `evidenceMessageIds`，并包含当前消息 ID；旧证据、未知 ID 和第三人代答均拒绝。
12. Performance ExecutionFormGuard 已改为 `ALLOW / BLOCK / MAYBE`：纯假设、纯过去报告和纯否定命令阻断；同时包含 blocker 与当前完成态或命令态信号的混合句进入最多一次 Compact Selector，不由 Guard 代替模型作复杂语义判断。
13. Direct Opinion Topic Identity 使用轻量 `reasonCluster + target + polarity` 归一化；聪明、智慧、才智等同因措辞共享 100%→40%→0% 冷却，无法稳定归类时回退到规范化原文，不恢复 AE3 Judge。
14. `scripts/fixtures/action-engine-v4-benchmark.json` 已扩展为 172 条 Ground Truth，并加入 3/4/6 人、角色名、代词、被动语态、上下文省略、旁观者和第三人插话。Calculator 分别计算 Detection、Action、Source、Target、Argument、Pending 与 Execution Match；Wrong Action 不再计入 Recall，Core/Overall 使用独立口径，Per-Action Recall 纳入 Gate。
15. 原 `multi_turn` 历史重放样例已全部改为 `multi_turn_completion` 当前完成态；另增支付与杀害的 `historical_completed_no_replay` 负例。`historical_replay`、`participant_override_mismatch` 和 `injury_victim_mismatch` 均进入 Stop-the-Line。
16. Precision 与 Compact Selector 使用同一 Action Timing：Immediate 只选择当前可执行动作；新的明确 `consent_required` 提议必须输出 `action_call` 创建 Pending；既有 Pending 的接受、拒绝或延后只能输出 `pending_response`。
17. AE4 Dynamic Catalog 不再重复稳定 Action Contract 字段，并隐藏 `isPlayerSource`；Validator 对该参数返回 `rejected_participant_override`，Executor 边界返回 `participant_override_mismatch`。AE3 共享 Action 定义中的兼容分支保持不变，但 AE4 无法再通过参数改写已绑定 Source。

## 自动化验证与限制

Phase 1–6 的专项测试覆盖 Router、Legacy 回滚、模式迁移、人工 Proposal 执行、Precision 单次调用、Malformed Q2、Consent 生命周期、Performance 单次 fallback、Opinion 冷却和 Direct/Derived Social 分离。Errata-001 永久回归另行覆盖 `setEmotion` / `isUndressed` 自身目标、支付/囚禁/伤害/杀害/重大关系默认拒绝自身目标、普通异目标、自然语言自身动作、Safe Default 与未知策略失败关闭。Phase 7 的 Benchmark 结构与指标计算器已完成，但真实 Selector 输出、Provider 缓存命中 Token、CK3 目标绑定及实际效果仍必须实机采集后再计算发布指标。

`node scripts/test-release.js` 已通过 72/72 个发布组；清单覆盖 105 个测试文件。`node --check resources/app/out/main/main.js`、动作聚合回归、AE4 七阶段专项、Errata-001 专项、实机前修复专项和 manifest 覆盖检查均通过。

因此，本仓库当前只能视为“v7.9.3 自动化候选”。在真实 Precision/Performance Benchmark 与 CK3 验收未满足规格阈值前，不标记为 Stable Candidate。

按 J2 Hard Phase Gates 口径，Phase 1–2 的自动化 Gate 已通过；Phase 3 的真实 Recall / Trigger Accuracy Gate、Phase 5 的真实 Performance 指标 Gate 和 Phase 7 实机 Gate 尚未放行。Phase 4–6 的实现与专项回归已经就绪，但不能据此宣称后续 Phase 已获得正式晋级或发布资格。

## Errata-001 冲突修正

原 C2 全局 `source != target` 已由 [AE4 Spec Errata-001](AE4_Spec_Errata-001_Self-Target目标约束冲突修正.md) 正式替换。全仓等价限制完成分类：支付、囚禁、伤害、杀害、关系、社会好感等动作自身的异目标业务约束保留；AE4 Catalog 和 Proposal Validator 的全局排斥已改为 metadata 驱动；Executor 未新增重复解释。

官方 2.0.3 的 `setEmotion` 与 `isUndressed` 原始合同均返回全部角色 ID，且明确允许自身或其他角色，因此两者声明 `targetPolicy: "self_or_other"`。`changeLocation` 声明 `none`；其余未声明动作按 Safe Default 使用 `other_only`。旧 `isInjured` 等动作中与默认策略不一致的 `check()` 已同步为异目标合同。Fast Resolver 对“他笑了起来”“她脱下了自己的衣服”只在 Catalog 元数据允许自身目标时绑定当前 NPC，不存在 Validator/Catalog 中的动作名称例外。

## 最终实机前合同裁定

[AE4 最终实机前修复清单](VOCT-NEW_v7.9.3_AE4_最终实机前修复清单_含Injury裁定.md)已裁定 `isInjured` 保持 `source=attacker / target=victim`。Selector Contract、Proposal、Validator 和 CK3 `targetCharacter` 效果方向现保持一致；主动语态、被动语态、代词和六人场景均有永久回归。

该方向是 VOCT-NEW AE4 为明确因果参与者绑定采用的项目级语义扩展，不再表述为“官方 2.0.3 明确规定 source=attacker”。官方原始动作更接近“target 受到一般性伤害、source 不特指攻击者”，但同样将效果施加给 `targetCharacter`。v7.9.3 对无明确攻击者的事故或环境伤害不猜测 Source，也不临时增加语义层。

最终收口未重新引入 Candidate Gate、Event Parser、Semantic Resolver、Semantic Rescue、Precision Judge、第二次 LLM 修复调用或逐消息 AE3 fallback。
