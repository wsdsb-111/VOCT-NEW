# V8.14.1 改进与收口实施报告

实施日期：2026-10-03；最终本地复核：2026-10-04。Trait、Presence、信件知识和 Memory4 收口专项完成；`node scripts/test-release.js` 全部 344 个发布组通过，manifest 为 413 个测试文件、344 个发布组、68 个历史归档。承诺绑定 P1 的窄修复已通过生产链负例及独立 QA；P2 空/缺失来源的旧 Known Entity 已保留为 `legacy_partial`。本地离线门禁通过不等于实机验收或 Freeze Candidate。真实 CK3、Provider、完整信件流程和 Soak 仍需用户实机验证。

## 收口内容

### 开场在场边界

- Frozen Worldline 开场预取仍逐个回应者建立，但 `activeParticipantIds` 和 Runtime Context 仅采用真实 `presentCharacterIds`；不再把已选择的候场人物塞进在场或提及实体。当前用户确实提及的人仍走原请求级路径。
- 候场 NPC 入场后可出现在动态尾部；仍候场者继续隐藏，开场冻结基线不被中途重写。V8.13 冻结前缀保持一致。

### Memory4 生产链与承诺状态

- Owner `counterpartIds` 只从有效可见片段中直接说话者与合法收件人的交换推导；共处场景或被提及的人不会自动成为对话对象。终局可见文本中的字面人物提及可以建立 `MENTION_ONLY` 证据，但不会授予 Presence 或 direct counterpart。
- 已验证的原生 Presence、Visibility 和 Finalization 可以形成完整 Known Entity 证据；已有旧贡献仍保留可解释的部分状态。Owner 侧车目录以 Owner ID 定址；重命名后旧目录仍可读取，多个冲突 Legacy 侧车 fail-closed。
- 空或缺失完整来源的旧 Known Entity 记录标记为 `legacy_partial`，不被误写成从未认识或不可见的 `UNKNOWN`，并保留原有 recognition 计数。生产链专项包含该回归。
- Commitment 仅允许有来源证据的 `active` → `fulfilled` / `cancelled` / `superseded` 转换。履行、取消和替代都要绑定具体原承诺及可见原文、来源、日期和 revision；沉默、否定、疑问、计划、传闻、错误说话者、重复承诺或模糊绑定不改变状态。失败事务回滚正文与状态，状态证据变化会撤销旧召回引用并使 Year/Life 视图变脏。多年未提不会自动完成承诺；履行陈述保留其 `reported` / `witnessed` 来源标签，但不等于 CK3 Effect 已确认。
- Production Pipeline QA 沿 Conversation、Presence、Finalization、Owner Snapshot、Memory4 Store、Recall Planner 和 Prompt Builder 走真实生产组件；Seen 仅在成功回复和实际注入验证后提交。

### 信件知情边界

- 信件 Prompt 使用收信者自己的 Campaign、Owner、`knownBy`、可见性、来源与获得时间范围；未来、未知获得时间、错误战役、未解决绑定及过期知识索引均 fail-closed。
- 不把发件者私人记忆、发件者目录镜像或原始摘要灌入收件者 Prompt。缺少 Memory Engine 时不退回原始摘要；收信件只读，不更改 Mention Tracker、知识索引、Recall Seen 或 Memory Store。收信者自己的合法原生 Memory 保持可用。
- 本地回归证明 Provider 输入组装合同，不覆盖玩家 CK3 中发信、收信、回信、重载、服务商失败与取消的完整人工流程。

### Self / Observed / Known Traits

- 运行时 `character.traits` 原值不被修改。Self Profile 保留回应者全部真实 Trait 与自我画像；投影使用每请求拷贝，保留 Map/对象原型并覆盖主 Prompt、旧布局、自定义 Handlebars、描述脚本、嵌套家属数据及信件模板。
- Observed Profile 为封闭 V1 白名单：仅已登记的 CK3 canonical Trait ID 与本地化标签可作为可观察人物描写；性格、生活方式、活动、统兵、压力应对等私密类别整体屏蔽。未知 Mod Trait 默认不向陌生观察者展示。新增 Trait 的可观察分类须先有直接可见性证据，再登记到该白名单。
- Known Profile 可依据具体合法知识证据恢复某个非可观察或未知 Mod Trait；这不会把它列为陌生人可观察项。Memory4 证据必须匹配当前 Owner、Campaign、目标实体、当前游戏日期、获得日期、知情名单、允许的可见性、`witnessed` / `game_fact` 来源、`observed` 认知状态及可校验源引用，并在原文中有目标姓名和 Trait 的具体正向断言。旧引用只接受能校验的 `legacyRefs`，不伪造 chat/message ID。
- 否定、撤回、不属实、后置假设、未来、谣言、听闻、转述、自称、引用、玩笑与虚构内容均保留原记忆叙事，但不解锁后台 Trait。当前回应者自己的 CK3 `knownSecrets` 仅能映射为其实际知道的对应秘密 Trait。
- 玩家身份输入门禁继续有效。旧身份描述缓存测试现要求新鲜门禁；非运行时画像的描述缓存使用 `v8.14.1` 命名空间及其他角色 Trait scope fingerprint，避免命中旧未过滤画像。此改动不调整 GLM 缓存算法、Cache Anchor、Prompt Block ID 或 V8.13 布局。
- 投影性能夹具含 1,000 个角色与 7,000 个 Trait，序列化约 592,680 bytes；15 次测量 median 7.23 ms、max 14.78 ms，输入对象未修改。这是本机确定性夹具结果，不是生产延迟承诺。

## 最终复核发现

独立 GPT-6 Luna Max 复核曾发现：当仍有效承诺为“把玉印封入国库”时，完成话语“已归还玉印”即使引用原义务完整核心文本，也会因宽泛语义匹配而错误履约。保守修复要求证据中的履行标记绑定到完整承诺核心及每项条件；仅同一短名词、同物件但不同动作、重述旧义务或完成后明确否认均不能履约，原承诺保持 `active`。修复后的生产链 QA 为 16 PASS / 0 FAIL，独立 QA 确认；Memory closeout 18/18，包含 P2 旧 Known Entity 缺失/空来源继续保留 `legacy_partial` 且不丢识别计数。完整发布门禁 344/344 组通过。履行陈述仍保留 `reported` / `witnessed` 来源标签，不等于 CK3 Effect 已确认。

旧 D/E 文档的 339/339 是当时冻结快照，不回写成后续版本结果。更早实现提交的模型归属按对应历史记录保留；本文记载当前 Luna Max 独立复核的新发现。
