# V8.15.2 修复1：未来披露与多人年龄旁听

日期：2026-10-07。目标基线：`3b894e78e66d2e46f5b51446eaf4a9ad343a0b5d`（V8.15.2）。开始时工作区干净。按用户提供的 `v8.15.2-修复1.md` 实施；本文区分离线、隔离窗口和待用户实机结果。

## 原因与修复

1. `memory4-disclosure.js` 的 FUTURE_INTENT 漏掉“将成为／将任／将担任／会成为／会是／以后会／之后会／届时会／将会／未来会”。新增测试先复现“我将成为皇帝”错误授权当前皇帝，再补齐专门 Future Guard，仍位于当前谓词之前。玩家、NPC 自报和具名第三人同样受限，后台碰巧一致不授予知识；当前身份及特质肯定正例保持。“我目前是宰相”的 NPC 自报入口亦补齐，避免文档要求的当前正例漏记。
2. `latestAgeQuestion()` 原先固定 `question.speakerId === ownerId` 且仅识别裸“你……”问句，三人旁听具名问答返回空披露。现先唯一绑定具名被问者，再验证回答者一致、CK3 年龄相符、Owner 听见问题和回答、回答者听见问题、提问者及双方实际 Presence，沿用紧邻有效 spoken 消息边界。NPC 问句中的直接引语使用既有 directSpeechSpans 归属校验，不接受他人的转述。
3. 同一问句多个不同目标或同名歧义拒绝。双人“你今年多少岁”仍按唯一另一在场者绑定；多人无明确姓名且没有可靠当轮目标信息时拒绝猜测。代码核对确认 recipientIds 在部分路径是听众 ACL，不作为可靠 addressed-responder attribution。
4. 继续沿用现有 Question + Answer message IDs、fragment IDs、正文哈希以及 `knownBy=[Owner]`。没有跨 Owner 合并证明；删除来源继续走既有持久 Forget。合法历史年龄授权读取当前 CK3 年龄，原历史值、获知日期和 proof 不被改写；归档不显示实时年龄。
