# V8.5.1 摘要 P0 / 多人入场 P2 事故审查

日期：2026-09-04。范围：结束对话、终局队列、摘要 Provider、结构化抽取、在场投影、人物文件、恢复与入场初始化。未修改用户 Provider 配置、Token 上限、游戏存档或历史身份规则。

## 结论与证据

“近期完全没有摘要”并非所有请求都没发出。真实恢复目录有 request 阶段的 `truncated_final_summary_response`，也有已生成完整内容但停在 persist 的 `missing_directed_summary_projection`。截断样本确实达到配置的 4096 completion tokens；另一类样本的缺失 owner 正好是当前存档玩家，而非旧会话参与者。

这证明存在多个链路故障，不能仅凭时间接近就归因于昨日人物背景/世界线修复。更早的恢复快照也存在投影缺失错误；本轮不宣称已确定最初引入这些缺陷的版本。

## 根因与修复

| 环节 | 故障 | 修复 |
| --- | --- | --- |
| 人物文件持久化 | `resolveSummaryParticipants` 自动加入 `gameData.playerID`，恢复旧会话时产生未生成的投影方向 | 结构化定向摘要只使用传入的历史参与者集合；不关闭投影缺失校验 |
| 日期 | 恢复回调用当前 GameData 日期而非原会话日期 | 回调传入 context.date / totalDays，持久化优先使用冻结值 |
| 恢复资料 | 当前 profile 覆盖快照历史资料 | 同 ID 的恢复资料以原快照字段为优先，不加入额外当前人物 |
| 终局 Provider | 整场过长/在场边界拒绝后再次整场生成，仍截断；只有最后错误留下 | 整场仍最多两次；失败后按入离场边界及消息数拆输入，最多 12 片、每片两次；已知截断/质量失败的恢复直接分片。合并后保留完整校验与同一 finalizationId |
| 在场安全 | 只按长度切片仍允许模型把临时缺席前后合为一段 | 分片先按所有 joinedAt/leftAt 边界切开，长区间再切；不裁掉来源 ID、不放宽私密/共同在场门禁 |
| 仅有系统标记的片段 | 模型为单独的入场/离场标记编造对话、引用不存在的消息 ID | 仅由程序生成的 presence 标记构成的片段直接保留原始标记及单条来源，不调用 Provider；普通片段采用 Source-ID contract v2，列出准确的消息/人物 ID 白名单，禁止重编号 |
| 入场控制 | initializeGameData 等待所有恢复网络请求后才激活会话并刷新 | 首先完成 presence 初始化、激活和通知，再后台恢复；Engine 层 single-flight 合并并发恢复 |
| 关闭游戏场景 | Run Command 关闭指令抛错可以提前终止摘要 | 记录关闭错误但继续终局摘要；不自动重发游戏指令 |
| 诊断 | MemoryTrace 白名单丢弃 error/success/attempt/durationMs | 保留这些字段，失败不再只剩没有原因的阶段名称 |

分片是正常单请求路径失败后的补救，不改变平时的单场单次提取原则。每次 Provider 请求仍受原配置上限约束，但失败恢复可能增加请求数和总费用。最多 12 片防止无限请求；超过上限或任一片失败时保留原始快照，禁止提交部分摘要。

## 2026-09-05 追加：摘要存在但约定没有进入召回（已修复，实机待验收）

本轮仅修复读取与召回，不再次生成、迁移或改写用户摘要。

### 根因与证据

- `MemoryStore` 原来按 owner + finalizationId 合并整个会话，却直接保留第一个关系文件的正文。同场的不同 `owner × counterpart` 投影本来就可能不同，后读到的完整双人内容因此消失。真实记录中双方的 7 月 14 日关系摘要分别长 5479 / 5748 字符，旧召回读到的却是 2659 字符的另一关系投影。
- `MemoryRanker` 超预算仅从正文开头截取，恰好丢掉投影末尾 `【需要长期记住的事项】`。恢复后的长叙事使这个已有缺陷更加明显。
- 原直接通道只有两轮最近记录基线；第三条依靠剩余预算追加。真实两名角色在 800 Token 的直接通道隔离重放中只选两条，2400 Token 虽选到第三条，但输出仍未含“入宫”。这不是摘要没有保存。

### 修复

- 同一会话仅合并正文完全相同的副本；不同关系投影保留不同内存记录与路由键。相同副本合并时保留 pinned/open 信息。
- 每条直接关系最近 3 条优先；预算内为更早的钉住记录留槽位，单对象额外最多 1 条，多对象共最多 2 条。不增加总预算。
- 需要裁剪时仅重排召回副本，将长期事项放到前面；正常长度摘要原样读取。磁盘正文、知情投影、在场门禁和全局 Cache Anchor 均未改动。
- 冻结记忆仍整场复用；不因每句聊天重新排序。极长长期事项列表仍受预算限制，不承诺每条旧记忆无限进入 Prompt。
