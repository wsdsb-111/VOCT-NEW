## Action 执行链定位

生产路径已经确认：

```text
Action Definition
→ ActionEffectWriter（按 mcc_characters_list_v2 顺序绑定 source/target）
→ RunFileManager
→ <CK3 用户目录>/run/votc.txt
→ CK3 Effect
→ 双方 log_income 实时回读
→ VOTC:RUN_ACK/ACTION_EFFECT/<commandId>
→ debug.log Tail ACK
→ GameData 重读与金额核对
```

CK3 基础游戏脚本确认 `add_gold` 与 `remove_short_term_gold` 均为有效 Character Effect；Workshop 的 `log_income` 会输出 Runtime ID、当前金币与收入信息。`mcc_event_v2.9003` 只在命令末尾清理 `votc_action_source/target`，不会提前破坏 Effect scope。

审查发现并修复三处闭环缺口：

- 金币 Effect 原先没有输出动作后的当前金币；仅重读旧 debug.log 无法证明动作结果。两个金币动作现在都在各自变更后执行 `log_income = yes`，且 ACK 位于双方回读之后。
- 命令记录缺失原先会被当作 ACK 路径处理；现在只有同 command ID 的 `acknowledged` 状态才允许进入 Runtime 验证，终止状态直接保持未确认。
- `playerPaysGoldTo` 的 RunFile source 与诊断来源现在绑定玩家 Runtime ID，不再沿用负责回复的 NPC ID。

只有来源金币精确减少、目标金币精确增加且 revision 前进时，状态才进入 `CONFIRMED`。写文件、进入队列、收到 ACK 均不能单独产生成功。

## 参数一致性

系统从最新玩家消息中提取显式阿拉伯数字金币金额，记录 `requestedByUser / selectedArgs / effectiveArgs / confirmedStateChange`。当 Action 模型选择金额与玩家明确金额不同时：

- 记录 `ACTION_ARGUMENT_DRIFT`；
- 实际执行使用玩家明确金额；
- NPC 叙事不能静默把 100 改成 30。

## Relationship Current Truth

在场关系、Family Fact 与 Mentioned Character 现在共用同一轮 `currentFactRegistry` 和 `Relationship Current Truth` DTO。优先级固定为：

```text
当前 CK3 canonical Runtime
→ 当前 Runtime 亲属结构 / Kinship Graph
→ unknown（中性称谓）
```

Memory、历史身份、姓名风格、配偶性别与单条 relation-side pronoun 均不能决定当前性别。canonical 与 relation-side 冲突时保留诊断但 canonical 胜出；canonical 自身冲突或缺失时使用“手足/父母/子女/配偶”等中性称谓。原始 `siblings[]` 兼容路径也统一进入此 DTO，并由 canonical 性别裁定称谓。
