# V8.15.2 修复2：未来事实与年龄问答边界收口

日期：2026-10-07。按用户提供的 `v8.15.2-修复2.md` 实施。基线为 `025a25010da9d41918cc57f5c6e008e569d4b633`（V8.15.2 修复1），开始时工作区干净。主代理沿用客户端模型，独立 QA 为 GPT-6 Luna Max。

## 三项原因与修复

1. Future Guard 只覆盖部分未来动词，漏掉“将是／将为／会任／会担任”及日期型表达。红例确认“我将是皇帝”在后台同为皇帝时错误授权。现拆成 FUTURE_MODAL 与 FUTURE_TIME，在当前谓词之前否决；检查完整待判定句，覆盖“明天我是皇帝”这类时间词位于主体之前的表达。玩家原话、NPC 自报及直接引语中的未来头衔/特质均拒绝。补齐“我已经是皇帝”的 NPC 自报入口；文档要求的当前肯定正例保持。
2. 年龄裸回答被 `sourceRole === assistant` 拦截。真实 `role=user`、`speakerCharacterId=playerId` 的 NPC 问玩家/玩家答“16岁”在旧实现返回 NO_DISCLOSURE，现允许 user/assistant 两种实际发言角色，仍核对唯一目标、真实回答者、CK3 年龄、Owner 听见双方、回答者听见问题、Presence 和问答邻接。没有把玩家消息伪装为 assistant，也不允许 mixed/system 角色获得裸回答授权。
3. 只扫描 Owner 可见片段会越过隐藏插话。真实投影复现：question 0 和 answer 2 可见、known_group spoken 1 不可见，withheldMessageIds 为空，旧扫描仍错误披露。文档建议仅用 withheld 不足以修复：完整标注的私密片段会被 ACL 过滤，已验证 Finalization 分类还会清除 withheld。

为第三项补充最小 ID-only `spokenMessageIds`：`memory4-visibility.js` 在听众过滤前收集应用注解的有效非流式 user/assistant spoken 消息 ID；`memory4-coordinator.js` 对已经通过 validateSourceItem 的 spoken 段补入真实来源 message IDs，避免分类清理后丢失边界。集合去重排序并纳入 sourceRevision。`latestAgeQuestion()` 拒绝问题与回答之间的 spoken 或 withheld ID，不返回隐藏正文、说话内容或扩大听众。system/internal trace 以及完整注解的 witnessed/game_fact 不进入 spoken 集合，不误打断。完整“我今年16岁”不依赖旧问题，仍可以独立披露。
