# V6 阶段优化记录

本文档集中记录 V6 系列第一至第十阶段的优化内容。后续 V6/V6.x 阶段只在本文档中追加或更新，README 仅保留索引。

## API 用量统计（v6.2 第一阶段）

应用会在每次对话、行动判定、摘要或信件请求完成后，将匿名化用量写入：

`%APPDATA%\VOTC\votc_data\usage-analytics.json`

记录包含请求类型、服务商、模型、输入/输出 token、DeepSeek 缓存命中与未命中 token，以及对话提示词各区块的估算 token；不会保存提示词正文、模型回复或 API Key。主进程同时暴露 `usageAPI.getReport()` 和 `usageAPI.clear()`，便于后续设置页或调试工具读取与清空统计。

第三阶段开始，统计报告还会返回：

- `missAttribution`：根据服务商返回的命中/未命中 Token，估算缓存前缀首次断开的区块。
- `changesSincePrevious`：使用区块 SHA-256 短指纹，判断相邻同类请求中最早发生变化的位置。
- `cacheAttribution`：在最近记录中区分冷启动、首个断点区块和断点之后的连带未命中。

归因属于基于服务商聚合 Token 的有序前缀估算；DeepSeek 不提供精确的内部缓存断点，因此报告不会把估算结果伪装成绝对因果。旧记录没有指纹，但仍可以进行 Token 边界估算。

## 缓存前缀优化（v6.2 第二阶段）

对话请求现在会在动态角色卡、历史摘要和对话历史之前加入固定的 `VOTC_CACHE_ANCHOR_v1` 系统消息。它不包含日期、角色名或游戏状态，因此不会因切换角色或推进日期而变化；原有记忆摘要、历史系统和角色扮演区块仍按原逻辑生成。缓存命中率应以实际 API 返回的 `prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens` 为准。

动作模型第二阶段引入固定的 `VOTC_ACTION_CACHE_ANCHOR_v1`，第三阶段完成提示词重排后升级为 `v2`，第五阶段加入精确候选消息和类别约束后升级为 `v3`，扩展计谋与 RP 状态后升级为 `v4`，第六阶段完成门控与缓存优化后升级为 `v5`，第七阶段加入两段式语义判定后升级为 `VOTC_ACTION_CACHE_ANCHOR_v6`。更重要的是，只有最近对话明确叙述了会改变 CK3 状态的动作时才会调用动作模型，例如付款、囚禁、伤害或处决、建立或解除关系、任免与雇佣、改宗或臣属关系、离开对话或移动、脱衣或发生亲密行为。普通交谈、威胁、愿望、假设、诗词与历史讨论不会触发动作请求；唯一的意图例外是明确开始执行的 CK3 人物计谋。同一段动作叙述只会处理一次，避免多名 NPC 连续回复时重复扣费或重复执行。

## 阶段优化记录（第一至第十阶段）

### 第一阶段：统计与定位

第一阶段建立了 `UsageAnalytics` 用量统计，统一记录普通聊天、动作、滚动摘要、最终摘要、离场摘要和信件摘要请求。统计内容包括请求类型、模型、角色、输入/输出 Token、缓存命中/未命中 Token、动作跳过原因和提示词区块大小。统计文件只保留最近 2000 条记录，不保存正文和密钥。

通过第一阶段数据确认，主要未命中来源是重复发送的动态人物资料、摘要、历史内容、动作清单和每轮变化的提示词尾部；普通对话中无条件调用动作模型也会产生大量低价值请求。

### 第二阶段：稳定前缀与动作门控

第二阶段在普通聊天和动作请求开头加入独立的固定缓存锚点，并将动态日期、角色名、游戏数值和最近对话放在锚点之后。历史系统仍以 CK3 当前年份为边界，角色不能预知尚未出现的人物、作品、诗词、事件或后世评价。

动作模型改为只接收当前候选消息，并且只有明确表示动作已经发生时才调用。计划、威胁、愿望、假设和未来安排不会触发；同一轮同一动作类别只处理一次。动作关键词覆盖支付、囚禁、战斗、饮茶饮酒、关系变化、离开场景以及明确的亲密行为等类别。

### 第三阶段：动态摘要、关系上下文与动作提示词重排

第三阶段在不重写原有摘要和历史数据结构的前提下，完成了以下改进：

1. **摘要缓存分层**
   - 当前角色与玩家的既有摘要作为相对稳定区块保留在前面。
   - 提及的第三方角色记忆、关系资料和游戏关系作为动态区块，靠近当前历史插入。
   - 第三方角色变化不会再使整段长期摘要前缀失效。

2. **多人摘要完整保存**
   - 实际参与者由玩家和本轮真正发言的 NPC 计算，而不是只使用固定的 AI 角色。
   - 不再限制同时对话者人数；当前会话中的全部实际发言者都会参与摘要保存。
   - 一次多人对话生成一份共享摘要，并写入每一对参与者的双向摘要文件，例如 A↔B、A↔C、B↔C，确保 NPC 之间的互动也能被各自记住。
   - 已有摘要文件会保留，重复的同日同内容摘要不会重复写入。

3. **动态人物关系恢复**
   - 从最近的玩家消息中识别被提及的第三方角色，即使该角色没有自己的对话摘要文件，也会加载 CK3 游戏关系。
   - 当前对话者、玩家和被提及角色之间使用双向关系解析。
   - CK3 只提供 `brother`/`sister` 等笼统关系时，优先比较出生日期，缺少出生日期时再用年龄判断长幼。
   - 亲属资料只作为上下文加载，不会自动把被提及者加入发言队列或动作目标。

4. **动作提示词重排**
   - 固定锚点、规则、JSON 示例和会话人物名单前移。
   - 可用动作与结构化 JSON Schema 放在同一层，因为两者同步变化。
   - 当前 NPC、最近动作和最近对话放到尾部，减少它们对稳定缓存前缀的影响。
   - DeepSeek 的动作 Schema 定点附加在 `Available Actions` 区块，而不是附加到固定示例之后。

5. **主提示词缓存分段**
   - `default.hbs` 按“固定全局规则 → 固定历史/RP 规则 → 人物基础资料 → 世界与历史背景 → 当前数值、关系与场景”拆成五个有序系统区块；构建提示词时会把易变的世界/场景区块延后到对话历史之前。
   - 人物描述脚本中稳定的角色资料、示例和既有摘要会先进入缓存前缀；日期、地点与场景尾部独立放在动态区块。日期推进不再使整段人物资料失效，财富、好感或场景变化只影响后方动态状态及其后内容。
   - 历史参考、人物资料、关系、场景、记忆摘要和最近对话字段全部保留；统计文件会以 `main_segment` 分别记录五个区块，便于定位真实缓存断点。
   - 没有 `VOTC_SEGMENT` 标记的自定义模板仍按原来的单块方式运行。旧版原始默认模板会自动迁移，经过玩家修改的模板与文件不会被覆盖。

### 第四阶段：摘要模型缓存化

摘要请求正在使用独立的 `VOTC_SUMMARY_CACHE_ANCHOR_v1`，并将滚动摘要、最终摘要、信件摘要和离场摘要拆分为稳定规则、参与者信息、既有摘要、对话正文和最终生成请求。摘要内容和保存逻辑保持不变，后续将结合新的 `usage-analytics.json` 继续观察摘要请求的缓存命中率。

### 第五阶段：动作准确率与输出 Token 治理

第五阶段针对“门控已命中，但动作模型输出很多 Token 后仍未执行”的问题重构了动作判定链路，不改变动态历史、记忆摘要和人物关系系统：

- 门控会返回同一句话中的全部动作类别，不再只保留第一个命中；支付、囚禁、伤亡、关系、任免、臣属、移动、饮酒、战斗、宽衣、已完成亲密行为、可见姿态、计谋意图、RP 状态、派系承诺和囚犯处置均有独立类别，并补充了更细的中英文动作表达。
- 动作模型会收到触发门控的原始消息、真实发言者和触发类别；最近对话只用于消解代词、金额和目标，不能再用 NPC 的后续情绪替代原动作。
- 候选动作按类别裁剪。例如支付只提供金币动作，宽衣只提供 `isUndressed`，已完成亲密行为只提供 `intercourse`；`noOp` 和无关的 `setEmotion` 不再进入候选 Schema。
- 玩家与 NPC 的支付动作会根据候选消息的真实发言者进一步二选一；饮酒动作的姿态仅允许 `drinking`/`toast`，显式表情与姿态也限制在对应的可见姿态集合。
- 删除了会诱导模型无条件选择 `changeOpinionOf` 和 `setEmotion` 的旧示例，结构化输出限制为每个触发类别最多一个动作，并在执行前去除完全重复的调用。
- 动作请求固定使用低温度、512 输出 Token，并对 DeepSeek V4 显式关闭思考模式，避免空响应仍耗尽 4096 隐藏推理 Token。
- `usage-analytics.json` 新增 `action_outcome` 事件，记录候选类别、模型所选动作、已执行动作、等待批准动作、失败动作、空响应和 Schema 错误；`usageAPI.getReport()` 新增 `actionOutcomes` 汇总，可直接计算动作选择率和实际执行成功率。统计事件不计入 API 请求次数或 Token 总量。

第五阶段后续扩展增加了三个由动作注册表元数据驱动的场景脚本：

- `performDailyAction`：识别走、跑、拿取、触摸、提起、携带、穿戴、进食和观察等日常动作；物品或方向作为可选短参数保存。
- `performCombatAction`：识别打、劈、砍、推、踢、撞、刺、斩等即时攻击。它只记录攻击尝试，不会自行施加伤势或死亡；原文明确出现受伤或死亡结果时，才允许同时选择原有结果脚本。
- `performIntimateAction`：识别抚摸、舔舐、亲吻、挑逗、吮吸、顶入、插入、研磨和摩擦等亲密接触。脚本对双方执行 16 岁成年校验，只记录当前接触，不会据此推断性交完成、怀孕、受伤、同意或关系变化。

三个场景脚本通过 `triggerCategories` 自行声明门控类别，ActionEngine 会从统一注册表读取映射。新增动作不需要再把 actionId 重复写入多个候选表；场景中连续出现多个细分动作时，单条消息最多可返回四个去重后的动作。未来式、否定句和失败结果仍会被拦截，高影响结果继续使用原有 CK3 状态脚本。

第五阶段的政治与 RP 扩展继续增加五个元数据驱动脚本：

- `startPersonalScheme` / `startHostileScheme`：友好计谋支持拉拢、交友、勾引和追求，敌对计谋支持谋杀、绑架和制造把柄。拆分后只有敌对计谋被标为破坏性动作；生成的 CK3 效果先调用原生 `can_start_scheme`，只有游戏认可前置条件时才执行 `start_scheme`。普通威胁、愿望和假设不会启动计谋，勾引与追求仍保留双方成年校验。当前 v6.4 已覆盖常见计划、未来、回忆和传闻表达，但部分混合语义、
假设语境与特殊语序仍存在边界误判；这些问题已进入 v6.5 回归测试与架构重构范围。
- `setRoleplayStatus`：支持醉酒、暴怒、受辱、蒙羞、感激、惊恐、疑心、亲爱和疲惫，写入带期限的角色 flag 并同步 talk pose，不擅自修改健康、关系或好感。
- `recordFactionCommitment`：记录加入、退出、支持宣称者或反对派系的已接受政治承诺。当前日志没有导出 faction ID/scope，因此该动作保存角色 flag 与关联人物，但不会虚报 CK3 派系成员关系已经改变。
- `resolvePrisoner`：支持释放和放逐，使用 CK3 原生 `release_from_prison` / `banish` 效果；无效的囚犯状态仍由游戏原生条件决定。

门控同步补充了口语未来式（例如“我会杀了你”）、假设继承和失败动作过滤。回归测试覆盖即时动作、未来计划、威胁、假设、计谋意图、RP 状态、派系承诺和囚犯处置。

第五阶段的 UI 收尾优化：

- 三套主题（羊皮卷、骑士纹章、水墨画卷）的摘要列表分别保留独立的背景、边框和控件风格，同时补齐摘要人物名、角色 ID、角色数量、摘要数量、日期和正文的主题色阶。
- 摘要中的玩家名与 NPC 名统一使用高亮银白色，并增加墨色多层阴影，确保在羊皮纸、黑钢皮革和宣纸背景上均可辨认。
- 水墨主题的摘要箭头和日期保留朱砂色强调；摘要计数与角色 ID 使用高对比辅助色，避免浅色宣纸背景下的低对比度问题。
- 新增 `ui-theme-preview.html` 作为本地主题预览页，主题素材及生成提示词记录在 `UI_ASSET_PROMPTS_2.0.3.md`。

### 第六阶段：动作门控、多人记忆与聊天缓存优化（v6.3）

第六阶段在保留动态历史、角色关系、摘要和动作执行能力的前提下，针对实际游玩数据继续优化：

- **动作门控降误触发**：问句、请求、命令、计划和未来式不再被当作已发生动作；日常动作不再因“看着、望向、注视”等普通描写调用动作模型，只保留明确拿取、穿戴、进食、移动和战斗等实际行为。
- **动作请求降本**：动作结构化输出默认使用紧凑 Schema，并继续通过本地严格校验；减少重复的动作候选 Schema 输入，降低动作请求的缓存未命中与无效输出。
- **兄弟姐妹长幼关系修复**：当前回应角色会注入与玩家及其全部同胞之间、根据出生日期或年龄解析出的“哥哥、弟弟、姐姐、妹妹”关系；同胞 NPC 彼此对话时也不再只看到 CK3 模糊的 `brother`/`sister` 标签。
- **摘要记忆扩展**：当前双方主对话摘要由最近 3 篇增加到 5 篇；每名被提到的第三方角色动态摘要由 2 篇增加到 5 篇。
- **多人对话解除人数上限**：移除玩家最多同时与 4 名 NPC 对话的限制；当前会话中的全部 NPC 都可以进入队列，多人摘要也会为全部实际参与者保存逐对记录。
- **聊天缓存前缀重排**：将稳定的人物资料、示例、既有摘要和双方关系放在日期与场景状态之前；人物描述中的日期、地点和场景尾部独立成为动态区块，推进日期或改变场景时不再连带使整段人物资料失效。

第六阶段的缓存优化不会删除任何角色数据或对话上下文。首次启动新版本后的请求可能出现一次冷启动，后续应结合 `usage-analytics.json` 观察 `Character Description (Stable Profile)`、动态场景和历史区块的实际命中率。

### 第七阶段：动作模型优化（v6.4）

本阶段在保留旧动作脚本、场景动作脚本和 CK3 原生条件校验的前提下，为全部动作类别加入统一的“两段式语义判定”：

- **第一段：已发生动作门控**。先判断句子是否明确描述正在发生或已经完成的动作，继续排除提问、请求、命令、未来计划、威胁、假设、失败尝试、回忆、传闻和单纯讨论。中文“将他押送入牢”中的处置介词“将”不再被误判为将来时，只有“将要/将会”才作为未来标记。
- **第二段：语义证据组合**。将同一句中的多个描述线索组合为动作意图，再把候选脚本收窄到语义成立的范围。动作模型只负责在该范围内解析实际发言者、目标角色、金额、地点和枚举参数，不能跨类别猜测或用情绪动作替代状态变化。
- **描述句关系判定**：支持“对视许久后吻住嘴唇”“牵手并亲吻”“互诉心意”“冰释前嫌”“宣誓效忠”等叙述组合。长时间对视加明确亲吻会进入 `becomeSoulmatesWith` 候选；一般亲密接触进入 `becomeLoversWith` 候选；明确说出挚友、义兄弟、宿敌、停战或同盟时，只保留对应关系脚本。
- **结果类型精确分流**：明确死亡词只保留 `characterIsKilled`，非致死伤害只保留 `isInjured`；任免会按撤职、骑士、议会、宫廷职位和普通雇佣分流；改宗与成为封臣、离开对话与移动地点、个人计谋与敌对计谋分别收窄到对应脚本。
- **全动作类别统一处理**：金钱、囚禁、伤亡、关系、好感、职位、信仰/封臣、地点、饮酒、日常动作、战斗、衣物、亲密接触、完成性交、可见姿态、RP 状态、派系承诺、囚犯处置和计谋启动均使用同一语义候选机制；动作注册表中的元数据脚本仍可按 `triggerCategories` 自动接入。
- **候选与缓存同步**：动作提示词加入语义证据和允许脚本清单，缓存锚点升级为 `VOTC_ACTION_CACHE_ANCHOR_v6`。候选清单缩小后，动作模型更少看到无关脚本，降低误触发、空响应和无效 JSON，同时保留动作反馈、审批和 CK3 原生 `check` 条件。

第七阶段新增回归测试，覆盖描述性关系组合、死亡与受伤分流、拘押、任职、封臣、地点、囚犯处置、个人/敌对计谋，以及提问、计划、失败、回忆和讨论等非执行句。示例“我与她对视许久，随后吻住了她的唇”现在会先识别亲密接触，再将关系候选收敛为灵魂伴侣脚本，而不会直接开放全部关系动作。

### 第八阶段：ActionEvent 动作系统重构（v6.5）

- 动作门控仍作为低成本候选召回；`parseActionEvents()` 成为是否执行的唯一依据，按文本位置输出独立事件、Positive Evidence span、执行状态和结果状态。假设、回忆/传闻与失败尝试会作为拒绝候选记录，不能进入动作模型。
- 语义解析只读取每个事件的证据片段。受伤、死亡、关系、职位、地点等互斥动作使用注册表 metadata 的类别、证据模式和优先级裁剪；金币支付仍保留发言者方向的兼容解析，避免把“谁付给谁”错误合并。
- 玩家消息和每条 NPC 回复分别进入评估计划；同一轮不再由 `pendingPlayerActionMessage ?? placeholder` 二选一。事件去重键包含事件 ID、发言者和 evidence span，因此同类的连续动作可以分别处理。
- 标准动作脚本均声明 `triggerCategories` 与 `semantic` metadata；注册表加载时校验 metadata 的结构、正则模式、优先级和风险等级。高风险脚本保持本地 `check()` 与 CK3 原生前置条件校验。
- 回归覆盖 58 个基础/混合语义断言、14 个事件边界断言和 5 个运行路径/metadata 断言；均为静态或隔离逻辑验证，尚未替代 CK3 实机与模型提供商的手动冒烟测试。

### 第九阶段：v6.6 首轮动作系统收口

- **参与者角色映射**：死亡、囚禁、骑士任命和伤害动作在 metadata 中声明 actor/patient 对应的 Script source/target；未能从 Positive Evidence 解析出明确人物时安全跳过，避免将发言者错误当成受害者、囚犯或被任命者。
- **统一高风险审批**：`riskLevel = high` 现在强制进入危险动作策略；`isInjured`、`isImprisonedBy` 等不会因缺少旧 `isDestructive` 标记而在“自动接受非危险操作”模式中静默执行。
- **运行时与解析器收口**：新增生产 `ActionEngine` / `Conversation` 可注入 Harness，覆盖 CK3 effect scope、玩家/NPC 独立调度与 NPC 调度失败；Gate 的候选模式已与 Event Parser 的事实判断分离，并补充无标点、因果、后置语气、否定和复合事件回归。
- **语义与生命周期收口**：metadata 未匹配的状态事件标记为 `unresolved` 并跳过动作模型；只有金币方向保留显式 Legacy 兼容解析。玩家动作在消息提交后立即评估，不再依赖任何 NPC 回复或 API 成功。

### 第十阶段：v6.6.1 动作人物方向修复

- **明确语序才执行**：Participant Resolver 支持主动/被动、把/被字句、`遭`/`为…所…`、两个具名人物及唯一对话对象“你”；删除“一个名字 + 我”的危险默认方向。使役、他/她/它、多人歧义和非唯一“你”一律 fail-closed。
- **绑定不可篡改**：死亡、囚禁、骑士任命和受伤动作将 source/target 固定写入 Prompt、审批 payload 与 invocation；模型的错误 target 不能覆盖绑定人物。死亡与囚禁动作不再接受可将受害者/囚犯改为玩家的 `isPlayerSource` 模型参数。
- **安全可见性与回归**：审批悬浮详情显示 risk level；所有 high-risk metadata 经统一审批策略扫描。新增 `test-action-participants.js`，并扩展 Runtime Harness 验证四个核心动作的正反方向、approval 到 CK3 effect scope、复杂失败/计划/后置否定和多事件边界。

### 第十一阶段：v6.7 动作运行时模块化与会话级人物解析

- **独立运行时模块**：新增 `action-system/`，抽离 `ConversationReferenceContext`、`ReferenceResolver`、`ParticipantResolver`、`ParticipantBinding`、Risk Policy、Invocation Validator、Action Executor 与事件标识工具。`ActionEngine` 保持原有静态接口，生产调用通过兼容 façade 接入新模块。
- **“你我他”短窗口解析**：`我/本人/我自己` 固定为当前消息发言者；多人会话中的“你/您/对方”只在显式呼语、`primaryAddresseeId` 或唯一对话对象成立时解析；“他/她”只接受最近四条消息、最多十二个明确提及中的唯一可证明候选；“它”、使役句和任何歧义继续 fail-closed；“自己”按当前主语解析。
- **不可变人物绑定与模型权限收缩**：已解析的 actor/patient 会映射为冻结的 `ParticipantBinding`。绑定目标会从 JSON/Zod/紧凑 Schema 的模型选择空间移除；Invocation Validator 仍会忽略遗留模型输出中的错误 target，审批和 CK3 effect writer 始终使用绑定后的 source/target。
- **可观测性与回归**：新增 `reference_resolution`、`participant_binding` 无正文统计事件，并加入 v6.7 baseline、模块边界、引用解析、人物绑定、运行时和 RP 文本 fuzz 回归。动作缓存锚点升级为 `VOTC_ACTION_CACHE_ANCHOR_v7`，反映目标字段已不再由模型选择。

### 第十二阶段：v6.7 Gate / Parser / Semantic 与可用动作服务收口

- **兼容 façade 模块化**：`ActionEngine` 的公开 `getActionTriggers()`、`parseActionEvents()`、`resolveSemanticEvent()` 现经由 `candidate-gate`、`event-parser`、`semantic-resolver` 模块转发；既有确定性 Gate、Parser 与 Legacy 语义规则保留为兼容实现，避免在真实 CK3 冒烟前改变动作判定结果。
- **纯模块边界**：metadata positive-evidence shortlist 已移入 `semantic-resolver`，按注册表与依赖注入读取动作定义；事件去重键由 `event-tracker` 统一使用 message/event identity，`availability-service` 负责将 `check()` 结果、人物绑定与本地化参数封装为可选动作。
- **迁移状态**：ActionEngine 继续作为单一 orchestrator 和兼容 façade；旧 Gate/Parser 细节暂留为受测的 compatibility implementation，待 CK3 实机与模型提供商冒烟通过后再按 v6.7 Phase 9 删除，期间不会存在双路径执行或行为漂移。

### 第十三阶段：v6.7.1 Scene Action 退休与伤亡语义修复

- **Scene Action 退休**：移除 `performCombatAction`、`performDailyAction` 与 `performIntimateAction` 三个没有 CK3 / VOCT 持久状态效果的标准动作。`combat`、`daily_movement`、`daily_object_interaction` 与 `intimate_contact` 仍保留为 Event Parser 的叙事事件，但不再成为可执行 Action。
- **运行时边界收紧**：删除 Scene Action 的候选特殊分支和 Scene Category 的 `maxActions` 扩张；当语义解析后不存在可执行状态动作时，运行时记录 `no_available_action` 并在请求 Action LLM 前停止。
- **安全迁移**：`seedDefaults()` 只在用户 `actions/standard/` 删除三个精确的退休文件，绝不触及 `custom/`；标准目录中意外残留的退休 signature 也会在加载时跳过。
- **伤亡结果分流**：`characterIsKilled` 新增断头、斩首和枭首等“动作 + 致命部位”证据；`isInjured` 扩展“刺中 / 刺入 / 刺进 / 捅伤 / 扎伤”等明确命中身体的证据，并继续保留断肢 Injury。死亡命中以 `physical_outcome` 的更高优先级排除 Injury。
- **回归覆盖**：新增 Scene Action retirement（含标准目录迁移、custom 保护、无状态不请求模型）和 physical outcome（死亡 / 受伤互斥、人物绑定）测试；原有 v6.5–v6.7 测试继续保留 Scene Event 解析断言。
