# V8.4 Live Probe 与 Delta Hook 可行性报告

## 1. 静态审计范围

本轮检查了 Workshop mod 中与 VOTC GameData/debug 输出有关的文件：

```text
common/scripted_effects/log_gamedata_v3_effect.txt
common/scripted_effects/log_gamedata_v3s_effect.txt
common/scripted_effects/log_gamedata_v3l_effect.txt
common/scripted_effects/log_character_v2_effect.txt
events/message_events.txt
events/mcc_events_v2.txt
```

目录中未发现可直接作为“全局年度/月份 GameState 变更流”的 `common/on_action` 路径。现有路径是交互/消息事件调用 scripted effect，再通过 `debug_log` 输出选定 actor、recipient、相邻角色和相关资料。

## 2. 已确认的 live probe 能力

- `log_gamedata_v3`、`v3s`、`v3l` 会输出 `VOTC:IN` 和 `VOTC:CAMPAIGN`，并调用 `log_character_v2`。
- `log_character_v2` 聚合了 memory、secret、modifier、income、treasury、troops、title laws、relatives、persona numbers 等日志效果。
- `v3` 会先记录 recipient 和同地点 pinned character，再将 player 追加到有序列表；`v3s`、`v3l` 的参与者集合不同，不能把三种日志格式当作同一 record。
- 选定 companion `debug.log` 中有辛弃疾的 relatives 行和 CK3 character window 的 internal ID 行，证明当前安装环境可以通过既有 VOTC/CK3 日志观察到目标人物。
- 同一日志没有可靠的 CK3 游戏日期行；墙钟时间如 `[23:13:49]` 只能作为 log ordering，不能作为游戏日期。

## 3. 能力状态

| 目标 | 状态 | 结论 |
| --- | --- | --- |
| 交互触发的 player/recipient probe | `CONFIRMED` | 现有 scripted effects 与实际 debug.log 有证据。 |
| 选定人物的 relatives/memory/部分经济与军力 | `CONFIRMED` | `log_character_v2` 明确列出对应效果，实际日志也有输出。 |
| 通用当前 title holder/realm ruler | `PARTIAL` | 某些 title/law 或 location 可随 probe 输出，未形成全局快照合同。 |
| 通用 current gold/war state | `PARTIAL` | 有 log effect 名称，但没有证明每次世界变化都会触发、格式稳定且完整。 |
| live CK3 game date | `NOT_FOUND` | debug.log 证据不足；不能从墙钟时间推断。 |
| 全局年度/月度变更 hook | `NOT_FOUND` | 本轮 Workshop mod 静态树未发现可依赖的统一 hook。 |
| 每次人物/头衔/战争变化的 delta stream | `NOT_FOUND` | 没有事件覆盖和去重/顺序合同。 |
| debug.log tail 作为补充 probe | `PARTIAL` | 可读取已写出的 VOTC 行，但覆盖取决于实际触发的 interaction/event。 |
| Save A/B checkpoint reconcile | `UNKNOWN` | 用户只指定了一个存档，未执行。 |

## 4. 推荐组合方案

在没有全局 delta hook 前，正式设计应采用：

```text
Live Probe（按需、交互触发）
  -> append-only raw log cursor
  -> 结构化日志解析与去重
  -> bounded live overlay
  -> 下次 checkpoint 与 CK3 save reconcile
```

Live probe 只能作为“观测到的当前局部状态”，不能覆盖或修正 save snapshot。Save 是时间锚；live log 没有可验证游戏日期时，所有跨时间合并都应降级为 `UNKNOWN`。任何 probe 行都必须保留来源、墙钟时间、触发类型和字段缺失诊断。

## 5. 未执行的实机动作

计划书要求的 S0/S1 实机动作、游戏内触发变化、重新读取 debug.log、保存第二个 checkpoint 和 Save A/B 对照，本轮没有伪造完成。原因是用户只授权以 `autosave_1.ck3` 作为测试样本；静态日志审计不能替代 CK3 实机操作。

## 6. 冻结边界

本轮不增加 on_action、不修改 Workshop mod、不新增 live polling、不让 debug.log 直接写入 Prompt/Memory/Worldline，也不实现 delta merger。该报告完成后停止，等待人工确认是否提供第二存档并授权进入 V8.4 正式施工。
