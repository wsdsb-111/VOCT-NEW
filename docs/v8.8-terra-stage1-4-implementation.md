# V8.8 Terra Stage 1—4：Runtime / Historical / Kinship 实施报告

日期：2026-09-09  
状态：代码完成，等待 Luna Stage 5 与后续 Sol 审查

## 本轮收口

- 修复 `S0-P0-01`：`alive=true` 与任意死亡日期/死亡总天数证据同时出现时，统一生成 `RELATION_LIFE_STATUS_CONFLICT`。Canonical Profile 的 `alive`、死亡字段与年龄结论一并清空；Family Prompt 只显示“生死状态存在冲突，未输出结论”。
- 已故人物只有 `birth -> death` 可验证时才输出 `ageAtDeath`；仅有 raw `age` 时返回 `AGE_AT_DEATH_UNAVAILABLE`，不会伪造终年。
- Runtime Mention 增加安全上下文消歧：验证全名唯一可解析；仅名同名默认 `AMBIGUOUS`；只有当前会话 active participant 集合唯一命中时才以 `RESOLVED_CONTEXTUALLY` 解析。历史 Definition 已绑定的角色仍不走 Runtime Native 旁路。
- 新增 Historical Entity Binding 合同，键包含 campaign、branch、checkpoint、historical dataset revision；Definition ID 缺失、多个候选、双向 binding 不一致、Runtime 缺失、性别冲突均 fail-closed。年龄、婚姻、子女等世界线差异不影响身份绑定。
- 新增 `RelationMentionResolver` 和 `FamilyEntityFactBundle`：称谓以回应 NPC 为锚点解析到 Runtime ID；单一候选可输出，多个候选返回 `RELATION_AMBIGUOUS` 且不注入任何候选私有事实；关系路径输出结构化 `{type, from, to}`。
- PromptBuilder 改为把最新用户问题传给 Family Fact 投影。没有亲属称谓时不再倾倒完整家谱；保留不带 query 参数的旧调用兼容，以避免影响已有诊断/回归。

## 留待后续阶段

- Dynamic History 的旧 Shadow Historical Resolver 仍只用于诊断，但其年龄/家庭身份打分尚未迁移到 V8.8 Historical Binding 合同。
- 性别冲突已在 Relation Mention/Family Bundle 结论层 fail-closed；全链路 profile 优先级冲突统一与玩家化诊断留给后续 Sol 审查。
- Historical、Kinship 与 Relation Mention 的联合 Load Boundary cache 仍需建立完整失效合同；当前 Historical Binding cache 已限定 256 条并以 branch/checkpoint/dataset scope 隔离。
