# V8.4.1 Sol-3 Prompt Source Boundary Review

## 结论

`V8.4.1 SOL-3 PROMPT SOURCE BOUNDARY = PASS`。

生产 Prompt 继续默认关闭。审查确认只有来源匹配、状态 `ACTIVE`、文件名为 `autosave.ck3` 且 Freshness 非 `STALE/UNAVAILABLE` 的 Checkpoint 可以进入生产 Prompt；只读诊断仅绕过 Default On 开关，不绕过来源、状态和新鲜度门禁。

## 本轮修复

### P1：中文 Live 日期被误判为 STALE

CK3 Live Probe 可以返回 `1155年11月8日`，原 Freshness 解析器只接受 `1155.11.8`，因此诊断错误返回 `LIVE_DATE_INVALID / CHECKPOINT_STALE`。解析器现同时精确接受点分格式与中文年月日格式，并保留原字符串供 UI 展示。

`Checkpoint=1155.1.1 / Live=1155年11月8日` 现在计算为 311 天，状态为 `AGING`，不会再错误阻断 Prompt Diagnostics。

### P1：Checkpoint 话题事实缺少显式优先级

稳定世界块现声明完整来源优先级：

`Live / 回应角色权威游戏资料 / 场景直接事实 > Checkpoint > Supplemental > Personal Memory > 模型推断`

话题 Game Truth 标题显式包含 Checkpoint `as-of` 日期，并要求与本轮 Live、回应角色权威资料或场景直接事实冲突时以后者为准。Live Date 只描述 Probe 直接提供的信息，不能把旧 Checkpoint 的位置、存活或头衔伪装成当前状态。

## 边界复核

- Supplemental 只从当前 Checkpoint、未隐藏且 `PUBLIC_WORLD` 的条目中按查询召回；冲突时不能覆盖 Game Truth。
- hidden Supplemental 在更新后立即失效缓存且不进入诊断或生产 Prompt。
- 手工存档只允许诊断解析，`NOT_AUTOSAVE` 来源不能进入生产 Prompt。
- 配置路径与当前 Checkpoint 来源不一致、Pipeline 非 `ACTIVE`、或 Freshness 为 `STALE/UNAVAILABLE` 时 fail closed。
- Prompt 继续按 stable world、personal topic patch、Checkpoint topic、Supplemental、current world、history 的既有顺序组装；回应角色权威游戏资料保持独立系统块。
