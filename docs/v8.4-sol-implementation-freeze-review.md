# V8.4 Sol 实现冻结审查与 UI 管线报告

本报告审查 Luna/Terra 已实现的 V8.4 世界线运行时，并记录 Sol 阶段直接修复、真实 `autosave.ck3` 只读门禁及仍未满足的 Full Freeze 条件。它与此前的“设计冻结准备度 PASS”不是同一个 Gate。

## 结论

- `V8.4 IMPLEMENTATION FREEZE CANDIDATE = PASS`：本轮发现的 P0/P1 代码问题已修复，Sol 独立门禁及既有 Luna/Terra 门禁通过。
- `V8.4 FULL FREEZE / DEFAULT ON = NO`：世界知识 Prompt 继续默认关闭；Active Playset Definition Catalog、真实 Save A/B 分支边界、启用后的 Provider/Cache 和新版 Electron UI/Watcher 人工验收尚未全部完成。
- 默认关闭时，世界线失败不改变既有 Personal Memory、Action、Letter 或普通对话路径。

## Sol 修复

### Save Reader、Worker 与 Checkpoint

- 主进程路径校验改为只读取 64-byte header、受限 metadata 和极小 body prefix，不再把 200 MB 以上存档整文件读入 Electron Main。
- 只接受 plain text 与 unified ZIP；binary、split/未知 kind 和 Ironman 明确失败，不把未知容器标成 `VALID`。
- ZIP 解压增加输出上限；Worker 增加 120 秒超时、1.5 GiB old-generation 上限、Snapshot 数量边界，以及解析前后 size/mtime 一致性检查。
- Snapshot 指纹覆盖完整 Gamestate，不再只比较首尾片段。
- Checkpoint 只有在候选及 Delta 原子落盘成功后才替换内存态；写入失败保留旧 Checkpoint 与旧 Delta。
- Delta 仅在同一非空 `playthrough_id` 且日期递增时生成；跨 campaign 不生成、不在当前 UI 视图混入旧 campaign，持久层不再以固定 5,000 条静默删历史。

### Identity、Supplemental 与 Prompt

- `characters`、姓名索引和 Definition 映射使用无原型对象，特殊 key 不再污染索引。
- 同一 Runtime ID 对应多个 Definition ID 时标记 `AMBIGUOUS_PROVENANCE`，不再显示为确定的 `DIRECT`。
- Supplemental 新增持久化 `hidden` 状态；隐藏条目立即失效缓存且不进入召回。
- Supplemental create/update/delete 先持久化候选再替换内存态，写盘失败不会制造“UI 看似成功、重启后回滚”的假状态。
- 生产 Prompt 仅接受 `VALID + ACTIVE + configured autosave.ck3 + source exact match` 的 Checkpoint；手工诊断存档、STALE Checkpoint 和错误路径均不能注入。
- Supplemental 只召回非隐藏 `PUBLIC_WORLD`，并显式声明不能覆盖 Live、GameState、角色自身资料或场景直接事实。
- PromptBuilder 将 stable Game Truth 放在 Personal topic patch 前，并把 world topic、Supplemental、current world 分成不同块；同时保留 V7 已冻结的“当前用户消息 → Turn Recall”顺序。

### Renderer → Preload → Main → Worker 管线

- 启动时若世界线尚未单独配置，而“连接”页已有 CK3 用户目录，自动推导 `<CK3 用户目录>\save games\autosave.ck3` 并完成校验与首次构建。
- 玩家手工指定的世界线路径优先；切换 CK3 用户目录时，仅当当前来源仍是旧目录默认 autosave 才自动跟随。
- Main 发布 `worldline:updated` 状态事件，Preload 暴露可注销订阅，Renderer 在 `BUILDING/ACTIVE/FAILED`、Watcher 和 Supplemental 变化后刷新。
- 首次构建成功即记录 autosave `size:mtime`，避免 30 秒后无意义地重复解析；Live log 变化单独发出 `live_updated`，不触发存档重建。多个 Live marker 按日志位置取最新日期，旧 `TEST_CHAR` 不再覆盖更新的 `TEST_DATE`。
- 文件选择或路径校验成功后立即构建 Checkpoint，不再要求玩家额外点击一次“重新加载”。
- 顶部状态徽章显示真实管线状态，不再用接口存在即显示的 `ready` 冒充 Checkpoint 已激活。
- 隐藏/显示通过 IPC 持久化；create/update/delete 失败时不清空编辑器或伪造本地成功。

## 未放行项

1. `Definition Catalog = NOT_CONNECTED`：尚未把 Base Game 与当前 Active Playset 的 `history/characters` source rows、launcher position 和 duplicate conflict 接入生产运行时。现有 `character_lookup` 只构成 direct runtime evidence，不能伪造 mod override winner。
2. `Branch = UNKNOWN_WITHOUT_SAVE_AB_GATE`：当前真实 autosave 通过，但尚未用真实 Save A/B 在本实现中证明同局更新与不同新局隔离。
3. `Prompt Default On = NO`：Shared Query Analyzer 仍未形成一次分析供 Personal/World 双路共享的正式组件，也未完成启用后的真实 Provider 缓存回归。
4. 本轮看到的截图证明旧版页面入口与 IPC 已存在，也暴露了 `ready + UNCONFIGURED` 的断管问题；修复后的自动发现、状态徽章和 Watcher 更新仍需在完全重启 VOTC 后人工确认。

因此本阶段不把 Full Freeze 或默认开启写成通过。
