## 已实现

- `knowledge-scope-resolver.js` 只以已准备的 Checkpoint 人物字段判定同 Court / 同 Realm；任何缺失关系证据均为 `INCOMPLETE`，不会推断公开范围。
- `shared-candidate-pool.js` 为同一 Checkpoint、查询和 revision 建立最多 128 条的共享安全候选池；个人记忆和 Secret 候选会移除正文、payload 与 value，缓存不保存私密文本。
- `personal-memory-policy-adapter.js` 只从 responder 自己的 Knowledge 索引逐项读取最多 24 条 memory ID，不使用全量 `queryMemories()` 扫描；输出的是受保护 `contentRef`，不是正文。
- `subjective-world-builder.js` 对每 responder 的字段候选执行既有 Character Knowledge Policy 与冲突裁决，输出最多 24 条允许事实、过滤/未知数量和最多 50 条不含正文的 reason diagnostics。硬上限为 128 候选、500 KB DTO。
- `WorldlineService.getSharedCandidatePool()` 和 `getSubjectiveWorldView()` 已接入。Self 字段与本人定向 Memory 可在自己的 View 中出现；缺乏公开/范围证明的 Checkpoint 世界候选维持 `UNKNOWN`，不会因为真实而自动公开。
- 新设置键 `subjectiveWorldMode` 固定默认 `DIAGNOSTIC`。Phase A 不取代 legacy `getPromptContext()`，不复用或改变 `promptIntegrationEnabled`，也不向实际模型 Prompt 写入新 View。Conversation 仅传递 responder / conversation / turn 可信上下文，供后续受审查的 Phase B 使用。
