# V8.15.2 同级流官官职唯一持有规则

日期：2026-10-10。目标版本：Three-Mod Character Name Compatibility 1.0.6；前版见[王国平调报告](v8.15.2-celestial-lateral-appointment-report.md)。

## 用户规则与范围

中国天朝霸权治下的天朝流官获得新的同级任命头衔时，保留新官职，旧同级官职逐一卸任并交给各自合法继任者。范围从王国扩展到伯爵、公爵、国王及帝国等级；县官职移交携带其男爵领。皇帝设定的世袭、宗藩、世族、租赁及无地头衔保持此前保护，其他帝国和军镇等其他政府不按天朝单职规则改动。

此前 1.0.5 只处理王国，多个新王国会因歧义拒绝交接，兼容层交接回调又直接禁止受任者继续排平级任务。这些限制与本次明确的单职规则不符，需要改为各等级记录实际最后获授的新官职，旧职继任者仍有同级官职时继续交接自己的旧职。

每个等级独立记录最新目标，共用一次次日复查，避免同日王国和公国授任互相覆盖。处理低于角色最高等级的目标时不降低其主头衔。只依据实际获授的任命头衔处理，不根据名称、地名或回调顺序推测尚未发生的职位；合法性、持有状态及政府均在执行前重查。

没有合法旧职继任者时，旧官职交回皇帝，不能销毁头衔或任意生成接任角色。此处的实际候任者来自游戏 `current_heir`，静态测试不证明游戏内候任算法或所有 Mod 的回调时序。

## 连续交接与循环保护

旧职继任者也有同级官职时，获得旧职会触发自己的旧职交接，不能用源角色的 pending 标记禁止继任者排队。独立 QA 已复现 A→B→C→A 的候任环：普通同阶候任虽然合法，但直接交给已走过的角色会不断触发新任命。

现在每个交接头衔携带本次链中已处理角色的路径；连续交接复制路径，同级多个新任命合并路径，不同等级各自保留。候任者已经出现在该路径中时，旧职回交皇帝；正常链仍按每个旧职自己的合法候任者继续。任命回调消费交接标记，正常新任命清除旧路径，已待处理同一目标的重复回调保留路径，复查结束也清除本人仍持有的所选目标路径；目标已经移交给另一任务时，旧任务不清除新持有人的交接路径，避免以后正常调任被历史路径误阻挡。

上述逻辑使用原生变量列表 API。已在本地游戏脚本／测试中核对列表添加、迭代、成员检查及清除语法；没有找到标题宿主变量列表的直接原生实例，官方 Wiki 获取失败。合成执行器将标题列表作为显式模拟能力，此项及原生回调时序必须在真实 CK3 中验证，不能以 AST 通过冒充引擎确认。
