## 合并规则

同一小版本合并成一册：例如 V9.1、V9.1.1、V9.1.2 统一在 [V9.1](v9/V9.1.md)，每份原文保留独立目录入口及历史阶段。跨 minor 的 V6/V7/V8 连续记录放各阶段 OVERVIEW；无 minor 的持续合同/路线放 CONTRACTS。没有版本前缀的修复按正文和同期引用归属：Real Request Diff → V8.9；AE4 勘误 → V7.9；V9 启动调查 → V9.0。

跨版本活跃合同、上游清单、素材说明不伪装成某个版本修复。327 份原文合并为35册，另13个仅有连续阶段记录的小版本提供直达索引；旧路径保留薄索引及旧章节锚点，当前导航直接进入新册，避免破坏已有引用。历史“当前版本”、设计、失败与未验状态均保留原语境。

## 完整性与维护

[manifest.json](manifest.json) 逐原文记录源提交、规范化 SHA-256、合并册、章节锚点和正文哈希。源快照为 9449b0a4bc6b0616452b31fb8c79eafeae829bf5。

校验：`node scripts/test-version-documents.js`，从固定 Git 提交取回全部原文，与合并章节逐字对照；只允许链接重定位与显式锚点插入。另核对旧锚点与当前册间链接。JSON/patch 等非 Markdown 证据原地保留。

新修复直接写入相应版本册并保留版本/日期/设计或实施状态。不要继续新增散落在根目录的补丁说明；需要更新当前验收时增加清楚标注的当前结论，不能改写历史章。`consolidate-version-docs.js` 是本次显式维护工具：默认预览，`--apply` 才写入，已合并后拒绝重复执行。旧字节备份位于忽略目录 .build/version-docs-before，不含用户数据。
