# V8.3 Historical Figure Resolver 实施报告

本轮依据 `VOTC_V8.3_Historical_Figure_Resolver_开发设计方案.md` 实现 V8.3 的人物解析 Shadow 能力。实现保持 V7 Memory、Conversation、Action、Letter、Prompt、Relationship 与 Run Command Queue 的既有语义，不将解析结果注入 Prompt，也不持久化 figure binding。

<a id="source-48c363bcc8ed--前置收口"></a>
## 前置收口

- P1-07：`scripts/test-v7.10-official-action-system.js` 现在接受已退休 `resources/app/out/main/action-system/` 目录不存在或为空；如果目录重新出现业务文件则继续失败。
- 测试同时覆盖不存在、空目录和非空目录三种 fixture；未创建 `.gitkeep`，未修改正式 Action runtime。

<a id="source-48c363bcc8ed--数据合同与校准集"></a>
## 数据合同与校准集

- `historical-data/figure-matching.js` 为 Historical Baseline 中全部 48 个 figure key 建立显式 readiness 记录，未复核人物默认 `resolverReady: false` 并 fail-closed。
- 首批 14 人进入 reviewed calibration cohort：朱温、李克用、李存勖、石敬瑭、柴荣、赵匡胤、寇准、范仲淹、王安石、苏轼、岳飞、辛弃疾、忽必烈和文天祥。
- 首批记录只保存已核验的出生年、性别、正向文化提示和来源 URL；没有为提高命中率虚构家族、头衔、职位、领地或位置提示。
- `schema.js` 校验 figure key 完整性与唯一性、readiness、出生年、性别、辅助提示、亲属关系类型、confidence policy、reviewed 和来源。Ready 记录缺少人工复核、来源、时间锚点或辅助身份信息时拒绝启动解析器。

<a id="source-48c363bcc8ed--解析管线"></a>
## 解析管线

1. `historical-figure-input.js` 对一个 GameData 只调用一次 Canonical Relationship Resolver，生成紧凑且深冻结的候选证据；只有实际存在于 `gameData.characters` 的角色可成为候选，亲属关系中出现的合成人物只用于家族证据。
2. `figure-name-index.js` 清除 tooltip/HTML、全角空格、简单标点和大小写差异，只允许规范名或显式别名 exact match 进入候选集，不使用模糊匹配或 LLM。
3. `historical-figure-resolver.js` 使用纯函数评分，分离 identity evidence 与 world-state evidence。身份硬冲突只来自明确性别不符或严重不可能的出生时间；当前头衔、职位、领地、位置和历史状态不一致不构成身份冲突。
4. 输出状态限定为 `UNSUPPORTED`、`NOT_DUE`、`DUE_UNRESOLVED`、`CANDIDATE`、`AMBIGUOUS`、`RESOLVED`。`RESOLVED` 要求分数至少 0.85、领先至少 0.15、没有硬冲突，并具备强出生年或亲属证据。
5. 历史死亡日期只作为说明性证据，不排除 CK3 沙盒中仍存活的人物；当前游戏日期无法严格解析时不回退为 `NOT_DUE`。

<a id="source-48c363bcc8ed--shadow-集成与故障边界"></a>
## Shadow 集成与故障边界

- `DynamicHistoryService` 将结果写入不可枚举的 `GameData.dynamicHistory.figureResolution`；该字段不进入 `Object.keys()`、对象展开或 JSON 序列化。
- 解析异常记录 `HISTORICAL_FIGURE_RESOLUTION_FAILED` 并返回紧凑 error snapshot，不中断既有 GameData、Campaign Identity 或 Worldline 流程。
- 组合根构造解析器失败时只禁用 V8.3 Shadow 解析器，应用继续启动。
- `worldline.json` schema 仍为 version 1；重复解析不会写入 `figureBindings` 或 `figureResolution`，也没有跨 GameData 的全局候选缓存。
- Prompt 模板 hash、block 顺序、stable/dynamic 分类和 cache anchor 保持不变。

<a id="source-48c363bcc8ed--尚未完成的人工-gate"></a>
## 尚未完成的人工 Gate

- 设计方案要求的 20–30 条人工 Ground Truth 尚未在本轮由人工逐条裁定，因此当前不能宣称达到目标 Precision/Recall。
- 真实 CK3 Save A/Save B、跨重启、读档与同名/改名/历史死亡后存活场景尚未实机验收。
- 当前工作区没有提交或推送对应远端变更，因而不宣称 GitHub CI 全绿。
- 在上述 Gate 完成前，V8.3 保持 Shadow diagnostic，不冻结为可影响 Prompt 或世界线状态的生产绑定。

<a id="source-ab5c8c576230--已修复"></a>
## 已修复

<a id="source-ab5c8c576230--p1-01windows-eol-静态测试假失败"></a>
### P1-01：Windows EOL 静态测试假失败

`scripts/test-v7.10-rc2-action-config.js` 现在统一将读取的 `main.js`、Renderer、ActionEngine、SettingsRepository 和 ProviderService 源码从 CRLF 归一化为 LF，再执行原有静态合同断言。正式 DeepSeek Action 配置、Provider 参数和 Action Prompt 未修改。

全仓 `scripts/test-*.js` 扫描确认，其他包含换行字面量的源码检查已经自行归一化，或检查的是测试运行时由 Node 生成的临时文件，不依赖 Git checkout EOL。

<a id="source-ab5c8c576230--p1-03global-last-writer-state"></a>
### P1-03：Global last-writer state

`DynamicHistoryService` 不再保存全局 `this.worldlineState`。每次处理结果绑定到对应 GameData 的隐藏 `dynamicHistory` 容器：

```js
gameData.dynamicHistory = {
  campaignId,
  campaignIdentity,
  worldlineState,
  persistenceStatus
};
```

`getWorldlineState(gameData)` 只读取传入实例；不传 GameData 时返回 `null`。连续处理 Campaign A、Campaign B 后，A 的状态仍从 A 自身读取，不会被 B 覆盖。

<a id="source-ab5c8c576230--p2-01--p2-02shadow-metadata-加固"></a>
### P2-01 / P2-02：Shadow metadata 加固

`dynamicHistory` 和兼容入口 `historicalCampaignIdentity` 均为 non-enumerable、non-configurable，只读引用，因此不会进入 `Object.keys()`、对象展开或 `JSON.stringify()`。同一 GameData 再次执行 `updateFromGameData()` 会更新既有隐藏容器，不再触发不可配置属性重定义异常。

# V8.3.1 历史人物实机校准与可视化诊断面板实施报告

本轮依据 `VOTC_V8.3.1_历史人物实机校准与可视化诊断面板.md`，在 V8.3 Shadow Resolver 上增加实机白盒诊断与人工 Ground Truth 工具。该工具不参与生产人物绑定，不修改 Prompt、Memory、Conversation、Action、Letter、Relationship、Run Command Queue、Date Producer 或 Worldline schema。

<a id="source-5c47d9c34043--resolver-p2-收口"></a>
## Resolver P2 收口

- `historical-figure-input.js` 将 Character `consort` 的字符串、数组或紧凑对象转换为 `spouse` family evidence，不修改 Canonical Relationship Resolver。
- 调整评分：强年龄 0.22、性别 0.08、文化 0.03、家族 0.06、头衔 0.04、职位 0.05、领地 0.03、位置 0.02；规范名、别名、弱年龄和亲属权重保持设计值。
- `NAME_EXACT + AGE_MATCH_STRONG + GENDER_MATCH` 现在恰好达到 0.85，不再依赖 culture 才能 `RESOLVED`。
- 安全门保持不变：领先至少 0.15、无硬冲突且存在强身份信息。同名候选间 0.03 的 culture 差异不能消除歧义。
- 排序与领先幅度使用内部未截断分数，避免高分截断到 1.0 后吞掉亲属证据的真实 margin；对外分数仍限制在 0–1。

<a id="source-5c47d9c34043--主进程诊断链路"></a>
## 主进程诊断链路

- `historical-figure-diagnostics.js` 只读取 `parseLog()` 已附着的 `gameData.dynamicHistory.figureResolution`，不二次调用 Resolver。
- 输出 schema version 1 的紧凑纯 JSON Snapshot，包含 capture、summary、48 人 rows、raw culture、当前角色字段、证据、冲突和重要候选；不返回原始 GameData、Map、函数或循环引用。
- `historical-diagnostics-ipc.js` 每次刷新只调用一次 `parseLog()`，不依赖 active conversation；30 分钟、最多 5 个 capture 的主进程缓存只用于校验 Renderer 提交的 `captureId + figureKey + verdict`。
- `historical-ground-truth-store.js` 将主进程组装的完整裁定 append 到 `votc_data/diagnostics/historical-figure-ground-truth/records.jsonl`。相同 campaign 的 copied save 以不同 captureId 保留多条记录，永不覆盖。
- 磁盘写入失败只返回 `ground_truth_save_failed`，不影响继续刷新和查看 Dashboard。生产 Resolver 不导入 Ground Truth Store。

<a id="source-5c47d9c34043--overlay-页面"></a>
## Overlay 页面

- Preload 新增独立 `historicalAPI`，只暴露刷新 Dashboard 和记录裁定两个 IPC。
- 在现有“系统优化与用量”页面增加“历史人物”Tab，不创建新 BrowserWindow，不自动轮询。
- 页面提供刷新、Ready-only、六类状态筛选、姓名/figureKey/Character ID 搜索和“下一个待核验”。待核验顺序固定为 `AMBIGUOUS → CANDIDATE → DUE_UNRESOLVED`。
- 每张人物卡并排显示史实基准与当前 CK3，包含 Character ID、年龄、性别、raw culture、信仰、家族、头衔、职位、领主和位置。
- 同时显示状态文字、0–1 分数、百分比、85% 阈值线、Identity/Auxiliary/World-State/Historical Note 分层证据、独立冲突区和歧义候选。
- 人工裁定支持 `CORRECT`、`INCORRECT`、`SHOULD_BE_AMBIGUOUS`、`SHOULD_BE_RESOLVED`、`SHOULD_BE_UNRESOLVED` 和 `UNKNOWN`。
