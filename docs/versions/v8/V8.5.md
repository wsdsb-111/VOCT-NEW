# V8.5 Luna 玩家语义展示层实施报告

<a id="source-9331012b9ff7--实施状态"></a>

<a id="source-9331012b9ff7--本阶段范围"></a>
## 本阶段范围

本阶段严格限制在 Renderer 展示边界：

- 新增 `worldline-player-presentation.js`，把来源、检查点新鲜度、身份状态、来源冲突、知识可见性、重要性、年度事件和历史人物映射转换为玩家可读文案。

- 保留本地化冲突的全部可读候选，不猜测唯一名称；不确定的战争消失事件继续显示“待核实”，不伪造结束时间或结果。
- `index.html` 先加载展示 helper，再加载既有 Renderer bundle；本阶段没有改动 Terra 的 IPC、Prompt、缓存或 Game Truth 生产逻辑。

<a id="source-b9daa84ed159--发现与修复"></a>
## 发现与修复

<a id="source-b9daa84ed159--p0诊断裁剪列表没有-ipc--dom-上限"></a>
### P0：诊断裁剪列表没有 IPC / DOM 上限

真实持久化 Checkpoint 文件约 97 MB，包含 42,312 条年度变化。“岳飞”诊断产生 42,313 条裁剪项，JSON 约 462 万字符。后端约 141 ms 返回；前端在折叠的 `<details>` 中仍立即创建所有子节点。离线同构回归记录到 **169,404 次 JSX 节点创建**，足以解释收到候选后页面失去响应的现象。

修复：

- `getPromptDiagnostics` 新增 `trimmedPage` 输入以及 `trimmedTotal/trimmedPage/trimmedPageSize` 输出；每页 50 条，页号夹紧，最后一页可达。
- `trimmedItems` 现在明确是当前页，而非完整数组；旧 IPC 名称保留。生产 Renderer 同步升级，其他消费者需要依据总数和页号读取全部记录。
- 不删除持久化 Delta；服务保留完整裁剪记录，按需复制页数据，不再复制整个数组到 IPC。
- Resolver 高级内容只在展开后构建；列表另有 50 条防御上限，旧后端超大响应也不会再次生成十几万个节点。
- 页面提供上一页/下一页。分页沿用诊断的查询，不误用输入框中尚未提交的新文本。

<a id="source-b9daa84ed159--p1本地化冷查询仍可同步阻塞-main"></a>
### P1：本地化冷查询仍可同步阻塞 Main

精确人物命中跳过反查不能保护未知名字或本地化头衔。现在文件发现与扫描由 `localization-worker-client.js` 后台 Worker 执行；同步 Prompt 只读取已完成的缓存，不等待磁盘扫描。

- IPC 诊断走异步门面，最多等待约 8 秒；仍未完成时返回 `localizationPending`，玩家界面提示稍后重试，不把未完成搜索说成角色不存在。
- 单次后台任务 30 秒超时、队列最多 32 个、缓存最多 512 项；相同请求合并，线程失败后不循环重启。
- 来源文件签名变化或显式 invalidate 会终止旧线程，丢弃迟到结果；checkpoint 在异步等待中变化时返回 `CHECKPOINT_CHANGED`。
- 本地化 revision 进入 topic cache identity；线程完成后刷新展示并失效相关缓存。未完成/冲突的证据不自动成为身份确认。

<a id="source-b9daa84ed159--p1时间相关性与可见性"></a>
### P1：时间、相关性与可见性

- Runtime/Definition ID 中的数字不再被截作年份，例如 `#96896`、`121091`、`han_12371`。
- 无效日历日期和反向年份范围拒绝召回；现在/近期查询也过滤未来日期，`dateRange` 不能绕过门禁。即便请求未来年份，事实 horizon 仍不得超过 Checkpoint。
- 已有实体的“最近发生了什么”不再启用全世界 Delta；战争问题限制对应事件类型。
- Supplemental 缺失 visibility 或 truthy hidden 不按公开事实处理。仍仅 PUBLIC_WORLD 可进入 Prompt，不引入 V8.6 权限扩散。

<a id="source-b9daa84ed159--p1缓存与-token"></a>
### P1：缓存与 Token

- 相关 Supplemental 的 importance/source 纳入结构化 revision，防止优先级变化后继续命中旧排序。
- Summary key 包含查询、实体、Live/Checkpoint 和本地化 revision；切换检查点清空 summary cache。
- topic cache 上限 8，summary cache 上限 64；不再把完整 ranked candidate 对象图重复保存在每条 topic context 中。
- 删除可裁剪候选后，固定区块仍超 1200 token 则返回无世界注入，不能仅标记超预算却继续输出。

<a id="source-b9daa84ed159--展示正确性"></a>
### 展示正确性

- 未知领主证据不再展示为“无直接领主”；只有 INDEPENDENT 才能表达独立。
- Player World Knowledge DTO 保留主头衔本地化冲突来源和 warning，不丢失多个名称候选。
- 诊断长状态文本允许在网格内换行，避免覆盖相邻值。
- 历史映射在无筛选且已有 500 条结果后只计数；不再为其余九万条建立展示对象。搜索仍覆盖完整索引。

<a id="source-ea50bf2e19e0--3-来源和全名合同"></a>
## 3. 来源和全名合同

1. 数据集只包含明确发现的 Base Game 与当前启用 Playset 来源；不得将整个 Workshop 下载集合当成启用集合。启动配置与 Launcher 元数据不一致时记录不完整状态，不猜游戏实际加载赢家。
2. 记录 base root、启用描述符及顺序、Mod ID、版本、相对文件和内容指纹。单纯读到目录或顺序不证明覆盖关系；`replace_path`、同路径覆盖、压缩 Mod 等未支持语义必须标记不完整。
3. 后台构建至少读取 `history/characters`；为全名所需的 `common/dynasties`、`common/dynasty_houses`、对应静态 localization 也纳入依赖。书签中明确的 `history_id` 与静态名称可作为补充名称来源。没有可验证路径时返回 SOURCE_INCOMPLETE。
4. 用能处理注释、引号、嵌套日期块的解析器提取外层 Definition；不得通过整文件姓名正则把配偶、父亲或注释中的其他人物关联成当前人物。可参考现有探索脚本的扫描方式，不能沿用它扫描所有 Workshop 和固定目标人物的入口。
5. 完整静态姓名直接索引。中文姓前名后的组合，仅在源文化/姓名顺序有明确支持、dynasty/house→姓氏静态本地化链完整、名字未含同一姓氏且不存在来源冲突时生成；记录组合的每个来源引用与策略版本。不得把地域型家族全称机械当姓氏，或对所有文化采用同一拼接规则。
6. 局部名“飞”不冒充全名“岳飞”。局部名、前缀和注释可作为弱线索/诊断，不能单独升级为历史身份精确匹配。禁止从 `nansong_yue_085`、DNA 字符串、文件名推测中文姓名。
7. raw key 保留于开发者数据；静态名称解析失败的 Definition 仍进入 byId，不进入完整姓名索引。多源名称不一致保留所有来源和冲突；不能选第一条或最后一条。
8. 精确名称标准化仅做确定性空白、Unicode 规范化及大小写处理；不隐式音译、模糊合并或简繁归一。需要简繁/字/谥号支持时，采用来源明确的 alias 或可审计的 override；不得合并“张浚/张俊”。

<a id="source-ea50bf2e19e0--4-索引接口与数据结构"></a>
## 4. 索引接口与数据结构

建议新模块 `historical-definition-source.js` 负责后台来源快照，`historical-definition-index.js` 负责构建和纯查询；可用等价职责拆分。具体 Worker 文件名由 Terra 决定。

```js
// 内部只读结构；禁止整份通过 IPC 发送到 Renderer。
HistoricalDefinitionIndex = {
  schemaVersion: 1,
  policyVersion: "v8.5.1-historical-index-1",
  revision: "content-hash",
  sourceSetFingerprint: "content-hash",
  state: "READY", // UNCONFIGURED | BUILDING | READY | PARTIAL | FAILED
  sourceComplete: true,
  byId: Map<definitionId, DefinitionRecord>,
  exactNames: Map<normalizedName, definitionId[]>,
  exactAliases: Map<normalizedAlias, definitionId[]>,
  diagnostics: { definitionCount, searchableCount, conflictCount, missingSources }
};

DefinitionRecord = {
  definitionId: "string", // 数字式 ID 同样使用字符串
  displayName: null, // 可验证完整名；失败时不填 raw key
  names: [{ value, kind, matchType, sourceRefs }],
  sourceRows: [{ sourceId, modId, relativeFile, line, contentHash }],
  metadata: { birthDate, gender, culture, dynasty, house, fatherDefinitionId, motherDefinitionId },
  metadataProvenance: {},
  conflicts: [],
  sourceComplete: true
};
```

上面为接口记法，不是直接执行的 JS。缺失 metadata 用 null/unknown；有冲突时不能将不同 source row 的有利字段拼成一条虚构记录。字段一致可共享证据并保留全部来源；字段不一致阻断相应证据，身份关键冲突阻断确认。

对 Analyzer 注入同步、无文件 IO 的 `historicalDefinitionLookup(name, { matchType })`，返回：

```js
{
  indexState, indexRevision, sourceComplete,
  matchType, // NAME_EXACT | NAME_ALIAS | DEFINITION_DIRECT | WEAK
  candidates: [{ definitionId, displayName, metadata, metadataProvenance, sourceRefs, conflicts }],
  candidateTotal, candidateSetComplete, reason
}
```

byId / exactNames / exactAliases 查询使用 Map。全量 metadata 留在后台或主进程只读索引，Renderer 只获得有界 DTO。若因保护上限截断候选，必须 `candidateSetComplete=false`，不能用剩下的一项宣称唯一。

<a id="source-ea50bf2e19e0--5-构建失效和主线程合同"></a>
## 5. 构建、失效和主线程合同

- 大扫描、内容 hash、解析、缓存读写均在后台完成。不能把每个 Definition 转化成一次独立的全目录 localization 查询；后台构建共享本地化索引。
- 冷启动为 BUILDING；成功后以一次原子替换发布完整 generation。缓存原子写入独立 `historical-definition-index-v1/`（应用 dataDir 下），只保存可重建派生数据；不嵌入 Runtime / campaign / Live 状态。
- 持久化 cache key 包含 base + Playset + descriptor + history/dynasty/house + localization 的内容指纹及 policy。构建前后来源不一致时丢弃该代结果。
- 后台检查来源变化；源变更、手动重新读取、CK3 路径变化可触发重建，查询时不能遍历目录。invalidate 后旧结果不得作为当前完整来源使用；旧 Worker 迟到回复、旧磁盘缓存不能复活。
- index revision 是稳定内容版本，不含构建时间、UI 文案、查询次数或候选页号。相关语义未变则不变。历史 override policy 变化同样进入语义版本。
- Worker 失败/超时不循环重启、不阻塞对话；重建失败保留直接 Runtime/Definition 查询能力。待完成状态在 UI 中明确可见。
- 热姓名查询目标 <5 ms；基准测量需记录来源规模、warm-up、至少 100 次查询的 median/P95/max。候选遍历可与命中数量相关，不能与历史文件总数相关。

<a id="source-ea50bf2e19e0--6-查询顺序与-single-pass"></a>
## 6. 查询顺序与 single-pass

对每个明确实体依次执行：Runtime direct → Definition direct → 历史完整姓名 exact → 历史 alias exact → manual override → Runtime name exact → localization reverse → weak candidates。

- `#123` 明确指 Runtime；纯数字若同时命中 Runtime 与 Definition，按方案 Runtime direct 优先，trace 记录命名空间；不能把两者同时加入结果或把 ID 当日期。显式 Definition 查询继续通过已有映射读取当前角色。
- 查询句中的完整姓名提取优先于较短子串；不能仅因 N-gram 命中了“世忠”就忽略“韩世忠”的历史候选。中文不同实体可以各自走不同路径。
- 历史分支已命中候选、存在歧义、证据拒绝或来源不完整时，下游 Runtime name/localization 不能对同一历史实体绕过确认门禁；`mentionedEntityIds` 也不能替模糊历史指代选赢家。直接指定 ID 是独立明确请求，可查询该 Runtime 事实但不自动认证其历史姓名。
- manual override 只补别名、保留已知多定义或添加可审计候选，不能删除竞争候选或绕过来源冲突。保留旧导出兼容，不能靠新增 15 人硬编码实现覆盖率。
- `getPromptDiagnosticsAsync` 在 Analyzer 前准备索引和必要本地化数据，准备/分词可以复用；数据准备未完时输出 pending。最终一次 Shared Query Analysis 供 QueryPlan、Retriever、诊断和已有消费者复用，不在异步循环里反复运行完整 Analyzer。
- 一个历史实体的拒绝不能吞掉另一个明确实体的事实；返回逐实体判定，顶层只是展示摘要。

<a id="source-ea50bf2e19e0--7-candidate--fact-冻结条件"></a>
## 7. Candidate → Fact 冻结条件

`resolveHistoricalIdentity` 增加 Definition metadata 输入；curated figure / matching 为可选增强资料。仅 worldline 通用召回取消 whitelist 门禁；不顺带改动既有 V8.3 shadow resolver 的 readiness 合同。

历史姓名确认必须同时满足：

1. 可验证的 exact name/alias、相关来源完整、候选集合未截断。
2. 现有 `definitionToRuntime` 与 `runtimeToDefinitions` 一致，且 Runtime Character 存在。重复绑定异常或相互矛盾时保留候选并阻断确认。
3. 无硬身份冲突，达到现有评分阈值和唯一性差距，具有强第二身份证据。

沿用 `IDENTITY_SCORING`：exact 0.55、alias 0.45、age strong 0.22、age weak 0.10、gender 0.08、resolveThreshold 0.85、resolutionMargin 0.15、candidateThreshold 0.65。其他既有权重直接复用，不在此阶段调低门槛。Definition binding 是前置证据，不凭空加分凑阈值。

- metadata 缺失不加分，不默认男性；生日、性别、亲属等必须有对应来源。通用人物可以被召回但因证据不足返回 REJECTED，这是合法结果。
- 源人物未来死亡、未来官职、未来作品不能作为当前 Game Truth；源 metadata 只用于身份辨认。当前存活状态和位置来自 snapshot/Live，不使用历史上死亡时间否定当前沙盒存活。
- 一份源记录关联的 name/出生不是多个独立来源的重复加分；同一项证据只能按现有项计一次。增强资料与 CK3 metadata 冲突时保留并解释，不能选最有利的一方。
- 同 Definition 多 Runtime：当前 scalar 正向索引可能丢失重复赋值，Terra 至少以反向索引交叉检测；不可检测/不可完整恢复时说明能力边界并拒绝相关异常确认，不修改旧持久化 schema。
- 只有 RESOLVED 的历史实体进入 Game Truth；歧义和证据拒绝只进入诊断/澄清数据。特别保留两个岳飞候选，不按存活、列表顺序或最高分相同者任选。

<a id="source-ea50bf2e19e0--8-coverage-与身份状态分开"></a>
## 8. Coverage 与身份状态分开

新增逐实体 `historicalCoverage`，保留旧 `identityResolution` 枚举：

| coverageStatus | 含义 | identityResolution |
| --- | --- | --- |
| SOURCE_INCOMPLETE | 构建中、源缺失、相关 source conflict、候选集不完整 | 不确认；保留已有证据 |
| NAME_INDEX_MISS | 完整索引没有该 exact name/alias | NO_MATCH |
| DEFINITION_FOUND_RUNTIME_MISSING | 索引有定义，当前绑定/角色不存在 | NO_MATCH，附详细 reason |
| REJECTED_BY_EVIDENCE | Runtime 候选存在但证据不足/硬冲突 | REJECTED |
| AMBIGUOUS | 多候选无法唯一判定 | AMBIGUOUS |
| RESOLVED | 达到第 7 节全部条件 | RESOLVED |

`VOTC_METADATA_MISSING` 作为附加 `metadataStatus`/notice，与上述状态正交；它不覆盖 RESOLVED，也不等同 SOURCE_INCOMPLETE。来源不完整优先于“没有查到”，不能声称人物不存在。普通当前玩家可独立匹配成功，历史 coverage miss 不覆盖其当前角色结果。

<a id="source-ea50bf2e19e0--9-main--renderer-交接合同"></a>
## 9. Main / Renderer 交接合同

保留原有 IPC 方法名和原始 Domain 字段，增量提供：

historicalCoverage: { status, reason, indexRevision, sourceComplete, metadataStatus, definitionCount, runtimeCount }
historicalExplanation: {

Luna 必须实现默认摘要 → 可读判定依据 → 开发者原始数据。两个详情层都懒渲染；不得因折叠但创建全部子节点重现 V8.5 白屏。

- 未知 code 有可读回退，原码仍可在 C 层追溯。

<a id="source-ea50bf2e19e0--10-cache--prompt--兼容性"></a>
## 10. Cache / Prompt / 兼容性

## 4. 未冻结项与实现边界

1. **实际 Electron UI Gate 未验收**。隔离浏览器未加载完整应用外壳、真实背景资源和 IPC，不证明实际 VOTC 不再白屏，也不证明三个主题的最终色彩/对比度达标。
2. **全量 Exact-name Recall Gate 未验收**。100 条 fixture 与 15 人真实样本分别验证逻辑和固定名单，不能替代独立人工标注的完整来源抽样；不宣称全索引 ≥95%。
3. **来源合同尚有缺口**。Base 仍主要由 Workshop 所在 Steam 库推导；仅本地 Mod、无启用 Mod 或跨库安装可能无法发现 Base，此时 fail-closed。压缩 Mod / 相关 replace_path 标记不完整，但同路径覆盖、Launcher 实际加载状态及完整 name→house/dynasty→localization 逐节点来源证明尚未完整建模。当前索引读取完整性不能作为这些语义已证明的结论，相关来源需继续核验后才冻结。
4. **索引为内存缓存**，尚无独立磁盘索引缓存；周期重建在 Worker 运行而不是每 Turn 同步扫描，但未完成长期运行 CPU/内存和持续来源切换的压力验收。Main 历史映射筛选仍有全绑定集合遍历，实测百毫秒级，不应误报所有查询都在 5ms 内。
5. **增强资料状态仍不完整**：未将所有缺失 curated 资料情形独立暴露为完整的正交 metadata coverage；通用 Definition 候选召回已不依赖 curated 白名单。未为扩大确认率臆造性别、生日或别名资料。
6. 真实 Provider/CK3 对话、长期混合查询及 V8.5 既有人工 Gate 不因本轮离线回归被追认通过。Prompt 基础默认保持关闭。

因此 Sol 给出的是“已修复项自动回归通过，冻结阻断项明确”，不是无条件发布批准。尚未完整满足来源合同的实现不能仅凭 UI 验收后自动转为 INTERNAL FREEZE PASS。

# V8.5.1 摘要 P0 / 多人入场 P2 事故审查

日期：2026-09-04。范围：结束对话、终局队列、摘要 Provider、结构化抽取、在场投影、人物文件、恢复与入场初始化。未修改用户 Provider 配置、Token 上限、游戏存档或历史身份规则。

<a id="source-e510ff2d7ad5--结论与证据"></a>
## 结论与证据

“近期完全没有摘要”并非所有请求都没发出。真实恢复目录有 request 阶段的 `truncated_final_summary_response`，也有已生成完整内容但停在 persist 的 `missing_directed_summary_projection`。截断样本确实达到配置的 4096 completion tokens；另一类样本的缺失 owner 正好是当前存档玩家，而非旧会话参与者。

这证明存在多个链路故障，不能仅凭时间接近就归因于昨日人物背景/世界线修复。更早的恢复快照也存在投影缺失错误；本轮不宣称已确定最初引入这些缺陷的版本。

<a id="source-e510ff2d7ad5--根因与修复"></a>
## 根因与修复

| 环节 | 故障 | 修复 |
| --- | --- | --- |
| 人物文件持久化 | `resolveSummaryParticipants` 自动加入 `gameData.playerID`，恢复旧会话时产生未生成的投影方向 | 结构化定向摘要只使用传入的历史参与者集合；不关闭投影缺失校验 |
| 日期 | 恢复回调用当前 GameData 日期而非原会话日期 | 回调传入 context.date / totalDays，持久化优先使用冻结值 |
| 恢复资料 | 当前 profile 覆盖快照历史资料 | 同 ID 的恢复资料以原快照字段为优先，不加入额外当前人物 |
| 终局 Provider | 整场过长/在场边界拒绝后再次整场生成，仍截断；只有最后错误留下 | 整场仍最多两次；失败后按入离场边界及消息数拆输入，最多 12 片、每片两次；已知截断/质量失败的恢复直接分片。合并后保留完整校验与同一 finalizationId |
| 在场安全 | 只按长度切片仍允许模型把临时缺席前后合为一段 | 分片先按所有 joinedAt/leftAt 边界切开，长区间再切；不裁掉来源 ID、不放宽私密/共同在场门禁 |
| 仅有系统标记的片段 | 模型为单独的入场/离场标记编造对话、引用不存在的消息 ID | 仅由程序生成的 presence 标记构成的片段直接保留原始标记及单条来源，不调用 Provider；普通片段采用 Source-ID contract v2，列出准确的消息/人物 ID 白名单，禁止重编号 |
| 入场控制 | initializeGameData 等待所有恢复网络请求后才激活会话并刷新 | 首先完成 presence 初始化、激活和通知，再后台恢复；Engine 层 single-flight 合并并发恢复 |
| 关闭游戏场景 | Run Command 关闭指令抛错可以提前终止摘要 | 记录关闭错误但继续终局摘要；不自动重发游戏指令 |
| 诊断 | MemoryTrace 白名单丢弃 error/success/attempt/durationMs | 保留这些字段，失败不再只剩没有原因的阶段名称 |

分片是正常单请求路径失败后的补救，不改变平时的单场单次提取原则。每次 Provider 请求仍受原配置上限约束，但失败恢复可能增加请求数和总费用。最多 12 片防止无限请求；超过上限或任一片失败时保留原始快照，禁止提交部分摘要。

# V8.5.2 Astra Stage 0：架构与交接合同

日期：2026-09-05。依据：用户提供的《v8.5.2开发文档-Astra四模型分工版.md》、V8.5.1 合同与 Sol 终审。本文取代 V8.5.1 中年龄评分门禁、周期完整重建和存档触发静态索引失效的相关约定；其他兼容约定继续有效。

状态：CONTRACT FREEZE = PASS；Stage 0 实施验证结果在文末记录。V8.5.2 INTERNAL FREEZE = NOT READY，最终判定留 Stage 6。

<a id="source-5a521ec90946--1-阶段边界"></a>
## 1. 阶段边界

Astra Stage 0 实现来源探测、Worker generation、缓存通知与静态/Runtime 生命周期解耦，以及内存最长姓名扫描管线。Sol Stage 1 实现身份门禁、数字命名空间和 SOURCE_INCOMPLETE 优先级；Terra Stage 2 实现 Runtime-native、DTO、世界线差异和复姓来源数据。Luna 在后端审查后施工 UI。

保留现有摘要事故修复和最近三条召回；本版本不把世界线改造与摘要文件迁移混合。内部版本仍按 V8.5.2 记录，安装包 2.0.4 与 Memory Engine 2.5 不随阶段改号。

<a id="source-5a521ec90946--2-身份合同由-sol--terra-实现"></a>
## 2. 身份合同（由 Sol / Terra 实现）

增量 DTO：`identityKind = HISTORICAL | RUNTIME_NATIVE | UNKNOWN`；`resolutionStatus = RESOLVED | AMBIGUOUS | SOURCE_INCOMPLETE | REJECTED_BY_CONFLICT | NAME_INDEX_MISS | NO_MATCH`。

每个实体包含 `subjectName`、`candidateTotal`、`historicalDefinitionIds[]`、`runtimeIds[]`、`identityEvidence[]`、`worldlineDifferences[]`、`sourceComplete`、`candidateSetComplete`。旧 `identityResolution`、coverage 和 Developer 字段保持兼容，前端不根据列表第一项代替全部实体状态。

Historical RESOLVED 必须同时满足：可验证完整姓名 exact、唯一 Definition、唯一 Runtime、正反绑定一致、相关来源完整、候选集合完整、无明确性别冲突、无 source/binding 硬冲突。未知性别中性。年龄、出生、现实死亡年、父母、兄弟、婚姻、子女、官职、头衔、地点、领地均不得决定身份或用于从多个候选选赢家。

Evidence 分为 `IDENTITY_CORE`、`IDENTITY_SUPPORT`、`WORLDLINE_DIFFERENCE`。年龄与家庭差异仅 INFO/NOTICE；数据缺失不等于存在差异，不得编造差异项。Current Game Truth 保持高于历史基准。

Runtime-native：当前存档完整姓名唯一命中且无历史 Definition 的角色可以独立 RESOLVED；历史姓名索引未收录不覆盖它。多个 Runtime 同名返回 AMBIGUOUS，不因玩家 ID、宫廷或年龄暗选赢家。显式 `#RuntimeId` 可单独查询当前事实，但不能给历史身份背书。

数字 namespace：`#121091` 或整个实体输入为 `121091` 可 Runtime direct；句中的年份/日期由 Time Parser 占用。Stage 1 必须测试真实存在 Runtime 1168 时“岳飞1168年在哪里”仍不命中它。

来源不完整优先于确定性否定：SOURCE_INCOMPLETE > DEFINITION_FOUND_RUNTIME_MISSING > REJECTED_BY_EVIDENCE > NAME_INDEX_MISS。保留已读取候选供诊断；任何被截断或旧来源的候选均不能确认历史身份。未确认实体不进入 Game Truth，其他独立明确实体仍可返回。

<a id="source-5a521ec90946--3-静态来源与-generation"></a>
## 3. 静态来源与 generation

- 静态依赖：CK3 用户目录、dlc_load.json、启用描述符及顺序、Mod 内 descriptor.mod、Base/Mod 根目录、history/characters、dynasties、dynasty_houses、简中 localization、姓名/alias policy。不含存档、日期、Live、Runtime、Delta。
- Worker 每 60 秒探测小型配置内容与来源文件清单/stat（mtime、ctime、size）。不读取历史/本地化大文件正文、不解析，不因普通探测开始/结束清空任何查询或世界线缓存。
- fingerprint 未变：NO-OP，构建次数/generation/revision 不变。文件增加、删除、重命名、修改或策略变更触发构建。修改时间不能证明内容绝对不变，ctime 纳入探测，手动强制重读作为显式重新核验入口；不保证能发现人为同时伪造所有 stat 的修改。
- fingerprint 改变后读取内容 revision 并重建；构建前后再次核对来源（包括描述符与 Playset），变化则丢弃候选代。旧代在核验期间不可作为当前完整来源输出。
- revision 只含稳定源内容/来源语义/策略；单纯 touch 后若内容 revision 相同，保留 generation 和缓存，不发 semantic updated。真正变化才原子交换并清理历史姓名 lookup/scan 与世界线 topic/summary 派生缓存。
- probe、build、lookup/scan 是独立事件。lookup/scan 完成只发 query-ready UI 通知，不清空所有 topic/summary。pending 历史结果不得进入最终 topic/summary 缓存。
- 初始构建/来源重建/探测有有界超时；Worker 故障结清全部请求、失效旧缓存，不自动无限重启。旧 Worker、旧 revision 或取消请求的迟到回复不得重新灌入缓存或返回可确认结果。
- Stage 0 不新增磁盘索引缓存；进程内静态索引复用贯穿 checkpoint，冷启动重建。完整来源覆盖语义与跨 Steam 库 Base 发现沿用 V8.5.1 已记录限制，不能把 READY 等同所有来源语义已审计。

<a id="source-5a521ec90946--4-姓名扫描合同"></a>
## 4. 姓名扫描合同

Worker 在构建索引时生成内存 Trie，键来自可验证 exactNames/exactAliases；查询只遍历内存，复杂度由输入长度、最长键长度和命中数决定，与历史文件数量无关。

`scan(query)` 同步返回已准备的有界结果，未准备时返回 pending；`prepareQuery(query, timeoutMs)` 在 Worker 准备扫描结果与必要 exact lookup。结果包含 `revision`、`sourceComplete`、`candidateSetComplete`、`matches[{value,start,end,result}]`，result 复用现有 lookup 的候选/总数/完整性。

标准化采用 NFKC、trim、大小写归一，不做音译、简繁猜测。offset 指向标准化查询。最多 3000 字符、32 个匹配实体、每实体 200 个 Definition；超限明确标记不完整，不能用截断集合确认唯一。最长的重叠姓名优先，非重叠多实体保留；不得因另一处长姓名存在而吞掉独立出现的短姓名。

主线程对 snapshot.nameToCharacterIds 建立按 snapshot 对象复用的姓名 Trie，保护完整 Runtime 姓名（如赵思昭）不被较短历史名抢占。Runtime 姓名命中只提供既有当前角色查询入口，最终 Runtime-native 状态由 Terra 落地。旧 N-gram 仅保留给旧无扫描注入者与辅助本地化检索，历史主召回用扫描结果。

Scanner 支持任意已验证长度姓名；Stage 0 fixture 覆盖司马光、欧阳修、耶律阿保机、完颜阿骨打、赵思昭。复姓/非汉文化姓名的静态来源构造由 Terra 根据可验证 dynasty/house/localization 链扩展，禁止从 raw key、注释或文件名猜姓名。

<a id="source-5a521ec90946--5-worldline-集成与缓存权威"></a>
## 5. Worldline 集成与缓存权威

- autosave 路径切换、checkpoint 重建、Live 日期或 Delta 更新只清理 Runtime/世界线派生缓存，不 invalidate HistoricalDefinitionIndex。
- CK3 用户目录变化由静态 client 的配置一致性检查负责；显式历史来源重读调用 `refresh({force:true})`，普通来源检查调用 `refresh()`，两者不等同重读存档。Stage 0 仅提供后端入口，不新增前端按钮。
- 分析输入为单一 checkpoint 对象与单一历史 revision。异步准备期间 checkpoint 变化返回 CHECKPOINT_CHANGED；revision 不匹配的历史回复返回不完整。一次最终 Analyzer 输出供 QueryPlan/Retriever/Diagnostics 共用。
- UI 展示可因 query-ready 更新，但不能把这类通知当 source generation 改变。Stable checkpoint 文本不因历史姓名查询到来而改变。
- Source changed 才 targeted invalidation；不修改 Prompt 全局 Anchor 或 Provider 设置。最终真实 Provider/KV Cache 指标另行验收，不从内部缓存计数推断。

### P0：诊断 DTO 携带完整检查点

Terra 为计算 `worldlineDifferences`，曾把 `snapshot` 与 `definitionRecords` 临时挂入历史解析结果；兼容字段 `identityResolution` 在人物解析成功时会直接引用该对象。这样会把整份检查点经 IPC 序列化给 Renderer，人物规模较大时可能造成世界线诊断白屏、卡死或长时间无响应。

现已将检查点和 Definition 记录限制在 `historicalEntity()` 内部计算参数中，公开 DTO 只保留合同规定的紧凑字段。回归断言覆盖：

- `identityResolution` 不含 `snapshot` / `definitionRecords`；
- 200 KB 哨兵数据不会出现在诊断结果；
- 单实体诊断序列化体积保持有界；
- `worldlineDifferences` 与 `identityEvidence` 继续分层。

<a id="source-9d8476a281f7--p1runtime-姓名扫描截断仍可能部分注入"></a>
### P1：Runtime 姓名扫描截断仍可能部分注入

Runtime Scanner 命中超过 32 个实体或输入超过 3,000 字符时，旧路径仍可能把前 32 个结果作为完整结果处理。现已将其标记为 `SOURCE_INCOMPLETE / candidateSetComplete=false`，只返回诊断，不写入 resolved characters 或 Game Truth。

<a id="source-9d8476a281f7--p1historical-mapping-coverage-不完整"></a>
### P1：Historical Mapping coverage 不完整

Historical Definition 已找到、但当前检查点没有 Runtime 绑定时，Mapping 现统一返回 `DEFINITION_FOUND_RUNTIME_MISSING`；若来源或候选集合不完整，则 `SOURCE_INCOMPLETE` 保持最高优先级，并同步进入 Player DTO。候选总数使用索引提供的未截断总数，不再被当前页长度覆盖。

<a id="source-9d8476a281f7--p1历史姓名展示可能回退到-raw-key"></a>
### P1：历史姓名展示可能回退到 raw key

Mapping 名称回退现拒绝带 `_`、`:`、`#` 的 CJK raw key，只接受已验证 Index 名称、查询精确命中的已验证名称、唯一已验证名称、可读 Runtime 名称或 curated alias。
