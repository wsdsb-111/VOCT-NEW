<a id="source-8348536e0bea--已实现"></a>

- 在 `WorldlineView` 的开发者诊断页新增 Entity & Kinship Inspector，按四栏固定区分：身份依据、当前世界状态、亲属关系、历史差异。

<a id="source-8ab66596e2d1--本轮关闭的问题"></a>
## 本轮关闭的问题

- 统一生死仲裁此前未覆盖 `formatStructuredCharacter()`、原始家庭人物投影与确定性世界摘要。`alive=true + deathDate` 可能再次显示“在世/存活”，缺失 `alive` 可能被摘要写成“已死亡”。三条路径现均只消费 `resolveLifeStatus()`；冲突与未知不输出精确生死。
- 年度 Delta 过去使用真值判断，下一 Checkpoint 缺失 `alive` 时可误报 `IMPORTANT_CHARACTER_DIED`。现在只有明确 `ALIVE → DEAD` 才生成确认死亡事件。
- 配偶规范化和亲属图过去把任意死亡日期直接视为已故配偶。生死冲突现在保留配偶拓扑，但不会显示“亡妻/亡夫”或精确死亡结论。
- Historical Identity 查询、亲属标签和结构化人物格式化过去仍存在跳过性别共识仲裁的旁路。现在性别冲突统一拒绝历史身份并降级为中性亲属称谓/未知性别。
- 相同父子边由两端重复提供时，较晚到达的显式 Biological/Adoptive/Step 类型可能被去重丢弃；互相冲突的显式类型也可能被隐藏。现在重复边可补充后到的显式类型，冲突时降级为 `UNSPECIFIED` 并由完整性扫描报告 `RELATIONSHIP_KIND_CONFLICT`。
- 角色选择 API 的冻结 DTO 在审查中曾因一次非必要三态扩展触发回归；该扩展已撤回，V8.7.1 精确结构兼容恢复。

<a id="source-39e478143778--本轮修复"></a>
## 本轮修复

- 将亲属图的同胞推导从“所有人物两两比较”改为按父母的子女集合展开，并建立出入边索引；重复关系冲突查询不再无限追加诊断。
- Entity & Kinship Inspector 只构建回应角色和目标人物周围最多 4096 节点、3 层的亲属邻域，并按 Checkpoint/关系 revision 缓存；超出边界返回 `RELATION_SOURCE_INCOMPLETE`，不得从部分候选中作唯一判断。
- Historical Binding 建立一次性反向 Definition 索引，不再为每条映射扫描整张表；缓存键纳入 branch/checkpoint/dataset、双向映射和性别证据，保持 256 条上限并可识别同作用域突变。
- 修复称谓唯一命中后 Inspector 仍显示“需要目标人物”、关系栏与家庭事实方向相反、显式 Target 混入查询中另一人物差异与候选的问题；“你的儿子”等自然表述与候选上限一并覆盖。
- Current Truth 的 `alive` 统一消费 Life Status 仲裁；`alive=true + deathDate` 冲突时不再输出“在世”。Canonical 与 relation-entry 性别不一致时统一 fail-closed。
- Kinship 只提高家庭事实相关性，不提高 Secret 权限；新增否定回归确认 Secret 正文不会进入家庭投影。

<a id="source-b5e7f951a36a--冻结的权威边界"></a>
## 冻结的权威边界

| 层 | 唯一职责 | 不得替代 |
| --- | --- | --- |
| Runtime Identity | 将本轮名称、显式 ID 或上下文指向 Runtime ID | 不得用历史年龄或家庭猜人 |
| Historical Identity | 以 Definition ID、精确规范名/批准别名和结构化性别确认历史身份 | 不得决定当前年龄、家庭、头衔、位置或生死 |

<a id="source-b5e7f951a36a--p0-阻断项"></a>
## P0 阻断项

<a id="source-b5e7f951a36a--s0-p0-01生死双重权威会向-prompt-输出互相冲突的结论"></a>
### S0-P0-01：生死双重权威会向 Prompt 输出互相冲突的结论

`game-data/relationship-resolver.js` 的分层取值在 canonical `alive=true` 存在时忽略较低层的 `alive=false`，但仍会单独接收该较低层的 `deathDate`。由此可生成：

```text
alive=true
deathDate=1175年1月1日
evidence.conflicts.alive=false
```

随后 `character-family-facts.js` / `character-temporal-facts.js` 因存在死亡日期输出“已故”，而 `current-truth-adapter.js` 又可依据 `alive=true` 输出“在世”。这正是 V8.8 P0 Gate 中“死人被描述为当前活人”的可达冲突链。

Terra 必须先建立统一 Life Status 仲裁：

- `alive=true` 与任一可信死亡日期/死亡总天数同时存在时返回 `RELATION_LIFE_STATUS_CONFLICT`。
- 冲突时不得输出“在世”或“已故”的精确结论，也不得计算当前年龄或去世年龄。
- Current Truth、Family Fact 和 Prompt Projection 必须消费同一个仲裁结果，不得各自解释原始字段。

<a id="source-b5e7f951a36a--p1-阻断项"></a>
## P1 阻断项

<a id="source-b5e7f951a36a--s0-p1-01relationmentionresolver-尚不存在"></a>
### S0-P1-01：RelationMentionResolver 尚不存在

`shared-query-analyzer.js` 只能解析名称、Definition ID 和 Runtime ID。对“你儿子怎么样了”进行生产形状调用时，结果为 `resolved=[] / candidates=[] / NO_MATCH`；当前依赖把回应角色的整个家庭块交给模型自行理解，无法对多个儿子返回 `RELATION_AMBIGUOUS`。

<a id="source-b5e7f951a36a--s0-p1-02已故年龄仍会使用不可信-raw-age"></a>
### S0-P1-02：已故年龄仍会使用不可信 raw age

`character-age-service.js` 在缺少出生与死亡时间时，会把 `character.age` 作为 `ageAtDeath` 返回。该值可能是当前年龄或不明来源年龄，违反“已故年龄只冻结于 birth→death；证据不足则 AGE_UNKNOWN”的合同。

<a id="source-b5e7f951a36a--s0-p1-03shadow-historical-resolver-仍以年龄和家庭参与身份判定"></a>
### S0-P1-03：Shadow Historical Resolver 仍以年龄和家庭参与身份判定

生产 Worldline 的 `historical-identity-resolver.js` 已满足新边界，但 `historical-system/historical-figure-resolver.js` 仍把年龄、家庭作为强身份分数，并把 `AGE_IMPOSSIBLE` 作为 hard conflict。该旧 Resolver 当前只服务 Dynamic History/诊断，不进入生产 Prompt，但 Luna 迁移 Inspector 前必须停用其身份裁决权或改接 Historical Resolver 2.0。

同时，`historical-data/figure-matching.js` 的 `resolverReady=true` 记录没有 Definition ID、Canonical Name 和 Production Mapping Source，不满足 V8.8 对 `resolverReady` 的新含义。

<a id="source-b5e7f951a36a--s0-p1-04缺少-branch-local-historicalentitybinding"></a>
### S0-P1-04：缺少 branch-local HistoricalEntityBinding

当前绑定来自 Checkpoint 的 `definitionToRuntime/runtimeToDefinitions`，没有包含 campaign、branch、dataset revision、checkpoint 和状态的独立绑定合同。`getHistoricalBindings()` 只从单值 forward map 枚举，能够发现“一个 Runtime 对多个 Definition”，但不能完整展示“一个 Definition 对多个 Runtime”的冲突。

<a id="source-b5e7f951a36a--s0-p1-05性别来源冲突没有统一状态"></a>
### S0-P1-05：性别来源冲突没有统一状态

`character-demographic-normalizer.js` 采用首个可用值并静默忽略后续来源；`relationship-resolver.js` 只检查被选优先级内部的冲突。Current Character 与 relation entry 冲突时可能保留一个值而不产生 `RELATION_GENDER_CONFLICT`。

<a id="source-b5e7f951a36a--s0-p1-06身份关系状态和路径-dto-尚未统一"></a>
### S0-P1-06：身份、关系状态和路径 DTO 尚未统一

现有身份路径混用 `RESOLVED/REJECTED/NO_MATCH`、`DIRECT/LIVE_CONFIRMED/CONFLICT` 等状态；关系冲突多以 `null + diagnostic` 表示。Kinship `relationPath` 目前只是 ID 数组，缺少每一步 `type/from/to`，也没有 Biological/Adoptive/Step 分类。

<a id="source-b5e7f951a36a--s0-p1-07family-prompt-仍是全量非-query-aware-投影"></a>
### S0-P1-07：Family Prompt 仍是全量、非 query-aware 投影

`buildFamilyFactBlock()` 每轮遍历并输出回应角色全部可展示亲属。它没有 Relation Query、目标 Runtime ID、歧义状态和 Top-K 投影边界，不符合“Retrieve, Don't Dump”。

<a id="source-b5e7f951a36a--s0-p1-08historicalkinship-联合缓存合同尚未建立"></a>
### S0-P1-08：Historical/Kinship 联合缓存合同尚未建立

现有 Runtime Name、Historical Definition、Kinship 和 Worldline 查询缓存彼此独立。尚无统一包含 `campaignId + branchId + checkpoint structural revision + historical dataset revision` 的 Binding/Relation 缓存键，也没有 Relation Mention cache 的 Load Boundary 失效合同。

   - 金币对照的是会话快照与后来全日志解析结果，不是同命令执行前后的成对快照。

## 实现

- `prompts/prompt-script-sandbox.js` 在执行时适配已知旧性别二选一表达式及新版 isMale/isFemale 亲属标签；不覆盖用户脚本，未知或冲突使用中性标签。
