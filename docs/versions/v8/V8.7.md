## V8.7.1 存储基础

实现 `resources/app/out/main/worldline/supplemental-store.js`：记录类型、状态、可见性、重要性、实体引用、ACL、有效期校验；创建、带预期版本的编辑、隐藏/恢复/退役、分页列表及修订查询。每次编辑保存旧修订并链接前一修订 hash；读取时验证修订链与当前记录一致性。记录绑定 campaignId/branchId，未知分支拒绝写入。

为避免多文件部分提交，将 records、revisions、派生 index 合并到 `campaigns/{campaignId}/branches/{branchId}/state.json`，采用临时文件、fsync、rename 提交；同进程同路径写操作串行，过期 revision 拒绝。索引包含记录、实体、类型、可见性、重要性、日期及 conflictKey。

测试：`scripts/test-v8.7-supplemental-storage.js` 覆盖创建/编辑/隐藏/恢复、重启读取、分支隔离、秘密 ACL、不可变 scope、路径校验、并发编辑、rename 失败保留旧状态及历史篡改拒绝；发布门禁 201 组通过。

<a id="source-651b338d2eb7--2026-09-07-生产接入"></a>
## 2026-09-07 生产接入

- `parser-worker.js` 在后台计算 gamestate SHA-256，随检查点保存；老检查点没有指纹时拒绝长期写入，要求重新读取。不会在界面线程扫描整个存档。
- `canon-service.js` 由 `WorldlineService` 持有。Campaign 由存档 playthrough token 派生，Branch 由路径/内容指纹/日期登记；客户端不能指定实际写入作用域，过期界面 token 被拒绝。
- 同路径后续内容变化需要显式确认延续；回档/同日冲突可显式创建空分支，旧分支数据保留。复制文件默认隔离；只有玩家声明重命名、指纹一致且目标从未写入时，才允许保留原分支。重命名过程中禁止新增修改。
- `supplemental-worker.js` 承担读盘、修订链验证、全文索引构造和原子落盘。主进程跨 Worker 生命周期串行调度；失败不自动重放。对话准备最多等待 1.5 秒，可选系统异常不阻止原有 CK3/Memory 对话。
- `register-ipc.js` 与 `preload.js` 接通 `listCanon / mutateCanon / getCanonHistory / confirmCanonBranch / forkCanonBranch / renameCanonBranch`。
- `world-memory-editor.js` 作为独立组件挂载于世界线，点击“打开世界记忆”后加载。支持创建、修订编辑、原子替代、隐藏/恢复、恢复自动来源、类型/重要性/可见性、授权人、作用域人物、分支/冲突提示。列表与修订历史每页最多 20 条；旧异步响应不会回填已切换的界面。
- 旧 `supplemental.json` 与旧“当前会话 / 当前检查点”入口保持独立，没有静默升级、迁移或删除。正式用户数据、摘要及 CK3 存档未在本轮测试中改写。

<a id="source-651b338d2eb7--召回权威与缓存"></a>
## 召回、权威与缓存

- 使用词项/实体索引生成候选，并补齐同 conflictKey 的相反候选，再执行分支、状态、ACL、宫廷/领地范围、时间与有效期过滤。不会每轮读盘或把全库正文灌入提示词。
- 未获授权的秘密不会进入正文或冲突说明；重要性不改变权限。同一事项不同 Canon 保守提示冲突，不随机选边。
- `currentClaim` 只有在回应角色已获准的 CK3 字段与其一致时才能通过；只输出被核对的结构字段，不把附带正文也升级成真相。常见“现在/目前/当前”等无结构证据的状态声明拒绝注入；过去 RP 经历不因当前状态变化而直接删除。此规则不是任意自然语言的完整语义解析器，真实模型的服从性仍需实测。
- 计划使用“尚未发生”的表述；未来日期不可召回。无可验证日期不默认为今天。
- 普通 Canon 默认上限 512、硬上限 640 token；在现有 `worldline-turn-recall` 非稳定尾部、当前用户消息后注入，只使用 CK3 事实格式化之后剩余的世界召回预算。
- 玩家可显式固定高/关键重要性的世界注释或政治规则。固定段最高 192 token，仍过权限、时间及冲突门禁，按会话/分支/修订/策略/回应角色缓存，缓存键不包含本轮 query；普通补充段才包含 query。固定段沿用现有稳定段 headroom 裁剪，避免挤爆上下文。
- 固定规则启用时锚点扩展版本为 `Canon V8.7`，声明获授权 RP 规则例外但不得覆盖当前 CK3。没有固定规则时原锚点字节不变；Memory Engine 2.6 标签与 2.5 数据边界不迁移。
- 记录候选数、选中数、token、修订、缓存命中、时间/可见性阻断及冲突计数；不写 Canon 正文、秘密正文或完整 ACL 到遥测。

## 使用与仍待实机确认

重启 VOTC，世界线重新读取存档后，打开“世界记忆 / 世界编年史”。若提示分支未知，按界面说明确认延续或另建分支。对话召回仍遵守原有 `promptIntegrationEnabled + subjectiveWorldMode=PRODUCTION` 开关，保存 Canon 不会擅自打开开关；界面明确显示当前状态。

尚未关闭的发布验收门禁：

1. 打包 Electron：打开世界线、编辑、重启恢复，确认完整主题与原生窗口无白屏。
2. 真实 CK3 / Provider：相关问题命中赴约约定，无关问题不带普通 Canon；秘密仅授权 A/B，C 无法得知；现时地点与 Canon 相反时服从 CK3。
3. 真实复制存档 A/B 与回档：分支不串线；真实长对话、Provider token/cache 没有异常增长。
4. 前置死亡 18 天、killer fallback、第三人称 TTL、摘要/多人对话继续无回归。

存储仍为单个原子状态文件，超长期容量压力不在本轮证明范围。串行调度保证单个 VOTC 主进程内的 Worker 写入，尚无跨主进程文件锁；验收时只运行一个使用同一用户目录的 VOTC 实例。最终 Freeze 须在以上实机门禁完成后再作结论。

<a id="source-00f0e2dc6408--2-本轮修复"></a>
## 2. 本轮修复

# V8.7.2 Terra 实施报告：Current Truth、载入边界与 Legacy 迁移

<a id="source-511012a06bbd--已实现"></a>
## 已实现

- 新增 `current-truth-adapter.js`，将可写 Current Claim 收敛为位置、生死、信仰、文化、直属领主与所在宫廷六项。普通可读事实文本继续进入知识/Prompt；机器核对只使用 `structuredValue`，并保存 `displayValue` 供玩家界面显示。
- `primaryTitle` 与 `imprisoned` 没有当前存档解析的等价生产来源，Current Claim 写入因此 fail-closed；不会再以测试夹具可构造为由向玩家宣称支持。
- Canon 写入会从当前 Checkpoint 重新取得原始值，拒绝手工伪造值；同一适配器服务 Canon 召回、World Fact 和测试 API。
- Branch Registry 新增 `loadSessionId`：已存在标识时，同路径、日期前进的 autosave 只在相同载入会话内自动延续；标识变更或缺失会返回 `LOAD_BOUNDARY_CANDIDATE`，必须继续当前分支、恢复已知 fingerprint 或新建分支。预 V8.7.2 的无标识历史条目仍兼容原有 autosave 延续。
- Workshop Mod 增加 `common/on_action/votc_load_boundary.txt`，在 CK3 启动/载入时递增持久化 epoch 并输出 `VOTC:LOAD_SESSION`。桌面端只读取该 opaque marker，不改写 CK3 存档事实。
- Legacy Supplemental 维持可读；面向玩家的旧 IPC 写接口改为 `legacy_supplemental_read_only`。公开记录可迁移为 Canon；Personal/Secret/Court 记录先返回审阅草稿。Canon 成功后旧记录才标记迁移并退出旧召回；`legacyMigrationId` 使重试幂等，防止双重注入。
