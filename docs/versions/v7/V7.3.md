# VOTC v7.3 动态称谓身份与死亡记忆生命周期

<a id="source-b48bceda8639--目标"></a>
## 目标

V7.3 将人物身份拆成三个互不冲突的层次：

1. **身份主键**：始终使用 CK3 数字角色 ID。
2. **存储显示名**：摘要目录和对话文件只使用人物本名。
3. **动态提及别名**：头衔、称号、绰号、官职和“陛下／殿下”等称呼只用于把当前文本解析到角色 ID。

因此，角色从皇帝变为太上皇不会生成第二个身份；不同历史阶段的摘要仍归入同一个角色 ID。

<a id="source-b48bceda8639--存储规则"></a>
## 存储规则

```text
conversation_summaries/
├─ 9_赵佶/
│  └─ 与官员乙的对话.json
└─ 10_官员乙/
   └─ 与赵佶的对话.json
```

- 路径不保存“宣和皇帝”“太上皇”等可变字段。
- 摘要参与者元数据保存 `firstName`、`fullName`、`primaryTitle`、宫廷职位和头衔等级，摘要模型可以把当时头衔写进正文。
- 已存在的同 ID 旧称号目录仍按 ID 读取并归为同一人物；V7.3 后续写入固定进入本名目录。

<a id="source-b48bceda8639--称谓解析与召回"></a>
## 称谓解析与召回

解析顺序：

1. 使用当前 CK3 场景中人物的本名、完整称号和实时头衔。
2. 对不在场人物，读取参与者各自摘要目录中保存的角色 ID 与称号资料。
3. “陛下”等派生称谓选择最近观察到的唯一持有人；同日并列、同名或同称号无法消歧时不匹配。
4. 得到角色 ID 后，每个 NPC 仍只从自己的摘要目录检索该 ID；身份解析不会授权读取其他人的摘要正文。

例如玩家和官员乙谈到“陛下”：若官员乙目录中最近保存的皇帝身份是 `9_赵佶`，系统把“陛下”解析为 ID 9，再从官员乙目录读取与 ID 9 相关的摘要。文件名始终是“与赵佶的对话”，不会因赵佶后来改称太上皇而拆成两个人。

<a id="source-b48bceda8639--死亡生命周期"></a>
## 死亡生命周期

- NPC 死亡动作成功后，删除该 NPC 拥有的全部 `ID_*` 摘要目录。
- 不删除其他人物目录中的死者相关文件，因为它们属于生者的记忆。
- 若 NPC 在会话中死亡，最终摘要继续写入生者目录，但跳过死者作为目录拥有者的写入方向。
- `excludedSummaryOwnerIds` 会进入恢复快照，确保程序重启补写摘要时也不会重建死者目录。

<a id="source-b48bceda8639--验证边界"></a>
## 验证边界

自动测试覆盖名称路径、头衔变化、唯一/歧义称谓、场外称谓召回、死亡目录删除及生者回忆保留。真实 CK3 中完成死亡动作后的磁盘变化，以及不同语言本地化头衔的覆盖范围，仍需实机冒烟确认。
