## 实现合同

- 新增 `resources/app/out/main/memory-system/memory4-recall-planner.js`：四种 Axis、六种 Granularity，沿现有 CK3 游戏历法解析明确年月日、中文相对年和区间。EVENT 不借用 Conversation Date，明确时间不扩到其他年份，日查询拒绝只有年/月精度的证据。首次相识只选两条路径中正文明确记载的最早可用记录，排除否定/未来措辞，不断言人生第一次。
- 按 Campaign、Owner、实体、Knowledge/Visibility、删除与 source revision、时间和状态进行门禁。索引元数据先缩小候选，最多物化 32 个 canonical 正文，再重验 hash/ACL/来源；不调用全量 Detail query。过期条目只作带状态的历史，不能回答未完成承诺；未来才获知的内容不能回到较早游戏日期。
- 所有实体共用 Overview≤1、Detail≤2；LIFE 代表 Detail≤1，EXACT_DATE 无 Overview。第三人问题只读取回应者自己的空间；人物别名包括在场者，重复别名/未解析指代不套用玩家直接记忆。无关联正文的陌生名字不以无关条目填槽。Profile 不整包渲染，只提供必要的极短认知/本轮实时关系；UNKNOWN 不等于从未相识，后续当前状态以新 CK3 回读为准。
- Legacy 同时启用，继续由当前 Campaign/Owner 投影及已验证的时间引用授权。只有正文完全由独立旧事实列表组成、且来源 ID/版本/content/ACL hash 可重验时才拆分；新转换条目只有完整保留同一来源事实才取得 coverage。部分覆盖保留其余事实，未知边界保留原叙事；墓碑保留已证明的独立事实抑制映射。来源编辑/删除使旧转换和旧覆盖失效，没有新 hash 证明的历史转换副本不能抑制 Legacy。
- 新来源 proof 存于 Memory4 sidecar `source.legacyRefs`，索引增补 ACL/importance/source/chain 元数据；旧行仍可读取，正文门禁不放宽。旧摘要与 2.5 Memory 存储格式未改变，没有强制迁移。当前 `version.js` 仍为 Memory Engine 3.0，2.6 是历史阶段标签；本轮不更改版本常量或 bundled UI 标签。
- `memory-engine.js` 只替换动态 Extra。旧直接调用默认不启用 C，生产 `Conversation` 显式启用，保留原 Memory3/Temporal 开关。Recent2、官方追忆、稳定预算、缓存锚点、IPC 和 `memory-temporal-extra` block ID 不变。
- 动态整包预算为 `min(1200, memoryEngineRemainingBudget, providerRemainingSafeBudget)`，包含 Profile、Legacy、来源与提示说明。完整 Prompt 定稿/压缩后再用实际 CHAT capabilities 计算余量，扣新增消息开销并复核；不足时舍弃整条，不截断承诺条件或传闻限定。
- 回复校验成功且实际 block/ID/token evidence 齐全后才提交 Seen 和 Focus。历史为 responder-private；来源变更、Campaign 切换、时间倒退或压缩移除后撤销旧块并释放对应键。FOLLOW_UP 限同一实体、话题与来源/支持链，最多延续三轮；无链证据不取日历下一条。仅选择或生成失败不提交。
- `memory-trace.js` 增补脱敏 C 诊断：query hash、index revision、过滤计数、候选/正文读取数、最多三个 ID、token 和耗时，不记录原问题或记忆正文。

## 剩余 Gate

重启 VOTC 后，用有当前 Campaign 绑定旧摘要及新 Detail 的 NPC 验证：二十年前/明确年日、事件与交谈时间的区别、第三人、多人不同知情、首次相识、承诺条件、成功后重复询问与“后来呢”。核对实际动态 block/Provider 输入，确认错误年份、未知人及他人私密正文未进入请求；来源编辑/删除、历史压缩后再验证。C 可开始实机复测，但不据此进入 D 或宣称 RC Freeze。

边界：旧叙事缺乏可靠事件边界时不猜测拆分；跨 Finalization 后续需明确 support/supersedes 链，不以相近日期或宽泛相同话题推断。Year/Life 派生与迁移诊断 UI 分属 D/E。
