# V8.9 主对话多模型缓存实施报告

日期：2026-09-14  
状态：代码与自动化门禁完成；真实 Provider、CK3、角色扮演和长时运行 Gate 待执行  
冻结结论：`V8.9 FULL FREEZE = PENDING MANUAL GATES`

## 1. 实施范围

本轮根据《VOCT-v8.9 改进方案》施工，范围限定在 NPC 正式聊天的 Prompt 排布、多 Provider 缓存观测、目标模型预设和诊断 UI。Action 与 Summary 的 Provider 选择、Prompt 与执行链未改；Family Fact、关系/亲属解析、Memory Engine、Worldline、CK3 Action 确认语义均保持现有合同。

- RC1：修复缓存 usage 三态，加入实际出站消息指纹、相邻请求公共前缀和 TTFT。
- RC2：正式聊天 Prompt 默认切换到 v6 稳定前缀/动态尾部布局，并保留 v5 回退。
- RC3：提供 GLM 5.3 Flash Low 与 DeepSeek V4 Flash 0731 两个可显式创建的 NPC 对话预设。
- RC4：Session Runtime Profile Split 未接入，开关默认关闭并延期到 V8.9.1。

## 2. RC1：Provider Truth 与 Outbound 诊断

`finiteNumber` 不再把 `null`、`undefined`、空字符串或非数字字符串转换为 0；`cached_tokens` 因而保留“未报告 / 明确为 0 / 正数”三态。

正式聊天在调用 Provider 之前生成 Outbound 指纹。持久化字段只包含消息位置、role、估算 Token、SHA-256 内容哈希、累计前缀哈希和 Prompt Block ID，不保存 Prompt、回复、reasoning 正文或 API Key。相邻请求以 `provider:model:requestType` 为比较键，输出公共消息数、公共前缀估算 Token、首个差异位置和首差异 Block。

诊断页固定按以下优先级解释证据：

1. Provider 原生 usage / `cached_tokens`。
2. 实际 Outbound 相邻请求公共前缀。
3. Prompt Block 的本地缓存命中归因估算。

Chat 观测同时记录 `requestStartedAt`、`firstReasoningAt`、`firstVisibleContentAt`、`requestCompletedAt`，并派生 reasoning TTFT、visible TTFT、output time 和 total latency。原有 `%APPDATA%/VOTC/provider-diagnostics.jsonl` 的 500 条、10 MB 保留上限不变。

## 3. RC2：Prompt v6 布局与回退

默认 `chatPromptV89Layout=true` 时，正式聊天使用 `VOTC_CACHE_ANCHOR_v6`，顺序为：

1. 稳定前缀与会话冻结信息。
2. 既有对话历史。
3. 当前 Runtime / 在场 / 世界状态。
4. 当前用户消息。
5. Family Facts。
6. 当前查询派生的 Memory、第三人和 Worldline 证据。
7. 最终回复指令。

关闭该开关后恢复 V8.8.5 的 `VOTC_CACHE_ANCHOR_v5` 与原有动态事实前置顺序。回归测试比较了两种布局的全部非 Anchor 消息，确认只改变消息位置；Family Facts 字节内容一致，最终指令仍在末尾。未配置 history block 的自定义 Prompt 保留旧行为。

## 4. RC3：双模型预设与路由隔离

诊断页提供“创建 V8.9 双模型预设”按钮，重复执行幂等：

- `V8.9 · GLM53F-Low`：独立 `zhipu` Provider，`glm-5.3-flash`，90,000 Context，temperature 0.7，reasoning low，`clear_thinking=true`。
- `V8.9 · DSV4F-0731`：OpenAI-compatible Provider，`deepseek-v4-flash-0731`，90,000 Context，temperature 0.7。

预设分别复用用户现有智谱与 OpenAI-compatible 配置中的凭据和端点。按钮只创建或更新预设，不自动切换 NPC Messages，不修改 Action 与 Summary override。玩家仍在原有 Provider 选择界面手动决定当前 NPC 模型。

## 5. 开关与回滚

- `chatPromptV89Layout=true`：关闭即可恢复 v5 Prompt 顺序。
- `chatPromptV89OutboundDiagnostics=true`：关闭即可停止新聊天的 Outbound 指纹和 TTFT 诊断。
- `chatPromptV89RuntimeProfileSplit=false`：仅保留后续版本配置位；V8.9 未连接运行逻辑。

回滚不需要修改 Action、Summary、Memory、Worldline 或亲属数据。已有诊断记录仍遵守脱敏与容量上限。
