# V8.4.1 Terra-3 CK3 Localization Resolver 实施报告

本阶段实现后端本地化 Resolver，不修改前端展示布局。目标是为 Worldline 实体提供可验证的显示文本，同时保持 raw identity、来源与冲突边界。

## 实现

- 新增 `CK3LocalizationResolver`，通过 CK3 用户目录的 `dlc_load.json`、启用 Mod descriptor 与 Steam Workshop 路径反推出基础游戏及当前启用 Mod 的本地化来源。
- 支持 `title`、`character` first-name key、`dynasty`、`culture`、`faith` 与 `war` 六类查询，默认读取 `simp_chinese`。
- 仅按实体类型扫描相关语言文件，并按 `(来源版本、类型、raw key)` 缓存结果；不构建全量 localization 常驻索引。
- 每个结果均包含 `localizedValue`、`rawKey`、`language`、`sourceFile`、`sourceMod` 与 `confidence`；Political Context 在原有 runtime ID/raw key 之外补充 `displayName` 和完整 localization 证据。
- 缺失 key、动态表达式、来源扫描不完整或不同静态值冲突时，`localizedValue` 保持 raw key。Mod 覆盖顺序没有独立 Game Truth 时不会猜测 winner。

## 真实来源核验

当前 CK3 用户目录有 54 个启用 Mod，按类型按需扫描而非加载全部 3,584 个简体中文语言文件。

该真实环境的首次 `h_china` title 查询扫描 119 个候选文件、约 117 ms；首次人物 key 查询扫描 237 个候选文件、约 143 ms；同 key 缓存命中约 0.058 ms。这是当前机器的只读勘测，不是发布 SLA，Sol-2 仍需审查主进程同步 I/O 边界。

真实 `h_china` 发现三条活跃来源：

- 基础游戏 `titles_l_simp_chinese.yml`：`中华`；
- Mod `2506311074` 的 `oe_titles_l_simp_chinese.yml`：`华夏`；
- 同一 Mod 的 replace 文件：`华夏`。

由于无法由存档证明最终覆盖 winner，结果为 `CONFLICT`，显示值保留 `h_china`。玩家名 `思昭` 不对应可证明的 localization key，结果为 `NOT_FOUND` 且保持原文本。两种情况均不改变实体 ID 或政治关系。

## 验证

- `test-v8.4.1-localization.js`：唯一来源、Mod/base 冲突、动态文本、unknown raw fallback、title/character/dynasty/culture/faith/war 六类解析，以及 Political Context display/identity 分离。
- `test-v8.4.1-political-context.js` 与既有 V8.4 Worldline 回归保持通过。
- 指定真实 autosave 的只读解析复验了 active Mod 来源发现、`h_china` 冲突和玩家名称 fallback。
