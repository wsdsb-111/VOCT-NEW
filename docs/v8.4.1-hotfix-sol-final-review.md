## Sol-H2：Alias 与身份边界

- `岳飞` 对两个冻结 Definition 均保留：`nansong_yue_085 → #96896`、`tangyin_yue_014 → #96895`，不静默选择。

- 同一精确中文值对应多个 raw key 返回 `CONFLICT`；前缀候选只有在当前快照唯一时才可建立 title alias。
- 修复 direct Runtime query 的 Trace：`#96896` 现在明确报告 `runtime=MATCHED`。

## Sol-H3：Localization Source Discovery

- 修复多 Steam Library：第一个 active Mod 所在库没有 CK3 本体时，继续检查后续 Mod 所在库，直到找到实际存在的 base game root。
- 缺失 descriptor、无可发现 base game 的无 Mod playset、Steam 外本地 Mod、扫描超限均返回 `INCOMPLETE_SOURCE_SCAN`，不伪装成 `NO_MATCH`。
- Steam 外本地 Mod 的已见 raw key 仅保留在诊断 `matchedRawKeys`，不会升级为确认身份。
- replace/同 key base-mod 文本冲突、同 value 多 raw key、`$...$`/`[...]` 动态值继续 fail-closed。
- typed scan 与 fallback 改为分阶段调用。真实 `涿郡` 初版逐文件回退超过 60 秒；修复后只读 Gate 为 208 ms。

## Sol-H4：Prompt Diagnostics UI

## P0 后续：世界线页主进程阻塞修复

- 实机当前 Checkpoint 含 92,306 条 `definitionToRuntime` 绑定；世界线初始页请求历史绑定时，旧实现会全量排序后才截断至 500 条，造成 Electron 主进程长时间阻塞。
- `getHistoricalBindings()` 现改为单次有界遍历：只构造前 500 条 UI 记录，同时精确计数全部绑定并保持 `truncated` 标记。页面不再执行全量数组创建或排序。
- Terra 回归增加 100,000 条 fixture，锁定总数、500 条上限、截断标志，并禁止该 UI 路径重新引入 `Object.entries()` 或 `.sort()`。
- 首轮修复后实机仍卡死，逐 IPC 计时确认 `getSettings/getCheckpointStatus/getAnnualDelta/getHistoricalBindings/getDiagnostics/listSupplemental` 合计低于 60 ms，而 `getOverview()` 超过 30 秒未返回。
- 当前上下文中的 `h_china` typed lookup 为 125 ms；真正阻断项是把已经可显示的中文玩家名“思昭”当作 character localization key，对 3,670 个语言文件同步穷举。
- 世界概览与世界知识现改用专用 `resolveForDisplay()`：非 ASCII/含空格显示文本直接使用；ASCII raw key 只查 typed 文件并硬限制 250 个。显式 Query/Prompt Diagnostics 仍使用完整 Resolver，不改变身份召回和冲突边界。
