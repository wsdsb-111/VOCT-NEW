## 已可冻结的架构结论

以下结论已有足够证据进入后续设计，不需要等待覆盖 winner 或战争结束存储凭空出现：

- Historical ID 是可选的 engine-provided identity；空值合法，禁止按姓名、生日或同名候选猜填。
- Title 采用混合对账：只有窗口内 history 明证的变更可由 GameState 重建；current-only 变化必须保留 Supplemental。
- War Start 可在 `start_date` 位于窗口且对象仍可读时由 GameState 确认；War End 不能由 S1 缺失自动推断结果，必须保留 Supplemental。
- Definition Catalog 对重复 ID 保存全部 source row、base/Mod ID、Launcher position、字段差异和 `CONFLICT`；没有受控新局或 CK3 resolver 证据时不猜 winner。
- Checkpoint 以稳定 Runtime ID 对齐人物；姓名只作为显示或候选证据，不作为主键。

这些是架构方向已明确，不等同于正式 Gate 已通过。
