# VOTC v7.7.1：Memory Engine 2.3 实施记录

## 目标

V7.7.1 在 V7.7 主进程模块化基线上升级长期记忆，不改变人物目录这一唯一可见摘要层。核心目标是消除全知摘要复制、锁定同一场对话的缓存前缀，并恢复 DeepSeek 结构化终局摘要的推理能力。

## 已实现范围

### 1. 按 `owner × counterpart` 写入

- Provider 每场会话只生成一份结构化事件集；本地继续根据发言者、在场区间、可见性和来源计算 `knownBy`。
- `perspective-projector.js` 为每个 `owner → counterpart` 独立筛选视角投影；记忆必须同时满足 owner 已知，并且主题人物或发言者与 counterpart 相关。以第三人 C 为唯一主题的事件不会复制进 `A → B` 文件。
- 无明确主题的共同事件仍可按实际参与者进入对应配对，确保多人共同议事不会因主题字段为空而丢失。
- 写入前执行泄漏与正文完整性校验；投影缺失、引用 owner 不知情/与 counterpart 无关的记忆，或正文与记忆 ID、哈希不一致时，终局进入 recovery，不报告成功。
- 结构化提取提示词明确区分 `participants` 与 `subjects`，要求不同主题人物拆成不同记忆，禁止把全部在场者机械复制为主题人物。
- 人物目录记录投影所有者、记忆 ID 列表、投影哈希、钉住及未决状态；写盘核验同时检查这些字段。
- 2–6 人自动回归要求生成 `N × (N−1)` 个视角投影。

### 2. 会话级冻结召回

- 每名 NPC 的稳定记忆、直接关系最近 2 条和钉住记忆在本场首次召回后冻结。
- 每个场外人物在首次被明确提及时，从当前回应者自己的目录建立一次快照；后续轮次复用。
- 当前话题最多选择 1 条补丁，并锁定至会话结束。
- Prompt 顺序固定为：缓存锚点与稳定资料 → 冻结记忆 → 历史消息 → 单一话题块 → 当前用户消息。当前话题不再插入稳定前缀中间。
- 每次聊天请求记录 history 前区块的聚合指纹和首个 history 位置；相邻请求只与同一 Provider、模型和回应人物比较，可直接诊断首个变化是否越过缓存稳定前缀。

### 3. 中文指代与可观察失败

- 中文别名采用最长唯一匹配，避免“李师”覆盖“李师师”。
- 当前头衔、称号和亲属称谓可作为动态别名；同一称谓对应多人时失败关闭，并写入 trace 和警告日志。
- “那个人／那人／此人”只绑定本场最近一次明确识别的第三人称角色。
- 提及状态继续使用固定大小游标，不恢复无限增长的消息 key 数组。

### 4. 摘要质量与生命周期

- DeepSeek 的 `final_summary` 与 `memory_recovery` 恢复思考模式，保持 JSON 对象响应和 4096 Token 上限；非 DeepSeek Provider 不注入 DeepSeek 专属参数。
- 新终局摘要请求只有在返回有效 JSON、非空 `sessionSummary` 和 `memories` 数组时才算成功；思考残片、普通正文或空摘要会自动重试，连续失败则保留 recovery snapshot。
- 承诺、秘密及未决事项标记为钉住记忆，不会被近期闲聊挤出直接关系冻结块。
- NPC 死亡改为写入 owner tombstone，不再物理删除其个人摘要目录；其他角色对死者的回忆保持不变，复活或读档可解除墓碑。

## 兼容边界

- 可见数据仍使用 `角色ID_本名/与本名的对话.json`，不把头衔写进路径。
- 旧人物目录仍可读取；只有 V7.7.1 新终局记录带 Engine 2.3 视角元数据。
- 玩家目录继续保存摘要，但玩家本身不执行 NPC Prompt 记忆注入。
- 本阶段未引入云向量数据库，也未重建缺失的源码构建链。
