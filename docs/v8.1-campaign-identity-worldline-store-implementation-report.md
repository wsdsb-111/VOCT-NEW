# VOTC v8.1 Campaign Identity + Worldline Store Foundation 实施报告

## 版本与范围

- 应用核心：`8.1.0`
- Historical / Worldline schema：`1`
- CK3 Workshop：`2.0.5`
- 模式：`shadow`
- 基线：V8.0 Historical Baseline 2.0

本阶段按 [V8.1 设计文档](VOTC_v8.1_Campaign_Identity与Worldline_Store_Foundation设计.md)实现 Campaign Identity、WorldlineStore 和最小 DynamicHistoryService，不实现 V8.2+ 的 GameStateSnapshot、统治者解析、人物绑定、分叉、事实有效性或 Prompt 投影。

## V8.0 P0/P1 审计

审计结果：P0 为 0；确认并修复四类 P1 数据完整性问题。

1. Historical schema 原先接受年份 `0/负数`及部分不存在的日历日期；现统一拒绝非法年份和月内越界日期。
2. Figure `historicalFactIds` 与 Fact `figureKey` 原先只验证目标存在，未验证双向归属一致；现两端必须匹配。
3. Period validator 原先只拒绝重叠，不拒绝年份空洞或缺失无界首尾；空洞可能使查询静默回退到唐朝，现要求全时间轴连续覆盖。
4. 通过启动校验的数据仍可被外部引用修改；Baseline dataset 现递归冻结，防止校验后篡改。

以上修复均先增加失败用例，再修改 validator/runtime；800–1400 legacy parity、Prompt 字节等价和完整 V7 回归保持通过。

## V8.1 应用实现

- `campaign-identity.js` 严格接受 `votc8c-[0-9]{12}`，使用 SHA-256 派生 `ck3-<32 hex>`；原 token 不写入 state。
- 无 token 或畸形 token 返回进程级 session identity，并将 `persistenceAllowed` 固定为 `false`。
- `worldline-store.js` 只接受可靠 identity，在 `votc_data/dynamic_history/<campaignId>/worldline.json` 建立 schema version 1 state。
- 写入采用同目录唯一临时文件、显式 `fsync`、关闭和 rename；失败清理临时文件。
- 已有文件必须通过 schema、campaignId、完整 token fingerprint、mode、ISO 时间及时间单调性校验；错误文件不覆盖。
- `dynamic-history-service.js` 是当前唯一组合入口。它向 GameData 附加只读 identity metadata；持久化错误记录 diagnostics 并 fail-closed，不阻断 Conversation/Letter 的既有日志解析。
- `log-parser.js` 读取 `VOTC:CAMPAIGN`，但 PromptBuilder、模板、Memory、Action 和 Letter 均不读取该字段。

## CK3 Workshop 2.0.5

Workshop 新增 `votc_campaign_identity_effect.txt`：

- 12 个存档全局变量分别在缺失时通过等权 `random_list` 选择数字 `0–9`；
- 三条 `log_gamedata_v3/v3l/v3s` 路径均在原 `init` 后输出 `VOTC:CAMPAIGN/votc8c-<12 digits>`；
- 原 `init` 字段、人物列表、Action/Letter/Run Command 脚本均未改变；
- 复制已初始化的存档会保留相同 token，作为同一 campaign 的分支；后续分叉由 V8.4 ledger 表达。

静态检查确认 12 个 initializer、120 个等权选项、三条输出路径和四个修改脚本的括号平衡。静态检查不能替代 CK3 对脚本语法和存档持久化的实机验证。
