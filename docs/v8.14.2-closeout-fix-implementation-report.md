## 修复合同

### 直接对白与昵称

- `memory4-entity-context.js` 的共享 `directSpeechSpans` 返回原文区间和 `DIRECT_SPEECH` 来源，支持中文双/单引号、直角双/单引号与 ASCII 双引号。未闭合、错配或嵌套片段不成为对白；引号前的内心、传闻、明确书写/刻字与其他说话人归属仍被拒绝。独立 QA 的纸上文字误授权红例已修复。
- `memory4-disclosure.js` 对 Assistant 只扫描上述对白；User 原有断言规则保持，mixed fail-closed。第三人头衔/特质必须唯一绑定当前角色候选，并通过原有肯定断言、来源校验、Owner/Campaign、knownBy 和可见性门禁。公共对白仅向已证明收听者公开，耳语不扩散给旁观者。
- 证据哈希仍对应完整原始 fragment，不把摘出的对白伪造成独立来源。Nickname 与所有人物姓名/昵称共同做归一化唯一性判断；昵称只帮助 Fact 目标绑定，不生成后端真名证据。

### Fact Epoch

- Owner/Campaign 的 `known-entities.json` 增加旁路 `currentFactState[entityId][factType:factKey]`：`present`、`epoch`、`epochStartedDate`、`lastObservedDate`、`legacyContinuous`；`currentFactObservedDates` 保留人物快照高水位，避免旧快照重新引入此前未建键的事实。协议 3.0 与摘要 2.5 不升级。
- 首次存在建立 epoch 1；持续存在保持编号；观察到消失保留编号；再次存在递增。没有角色 DTO 或没有该事实类型字段，不作为消失证据。只能检测被实际快照观察到的变化，不推断未导出期间发生过的丢失/恢复。
- AUTO 证据的 `factEpoch` 与当前存在状态/编号匹配才生效。`MANUAL_KNOWN` 绑定 `manualFactEpoch`，旧标记不跨生命周期；`MANUAL_HIDDEN` 的 tombstone 跨生命周期保持优先，失去普通互动证据也不删除该披露记录。
- 同一已归档 letter ID 的既有披露证据不重绑新 epoch；改用重试日期或同日重复记录也不能复活其旧知情。同生命周期来源修订仍可撤回不再有正文支持的证据，真正的新信件来源才可建立新生命周期知情。
- 无编号旧记录视为 legacy 0：只在首次观察为存在、尚未观察消失时迁入 1。`legacyContinuous` 允许这一未观察中断的首段接收较早获知日期，保持既有信件 as-of 合同；首次观察为不存在以及任何后续消失均终止此兼容授权。无 epoch 的恢复快照不暗中绑定新生命周期。
- 明确刷新入口为稳定 CK3 回读、对话开场、Finalization 快照捕获、已验证信件披露和当前人物手工标记/刷新。普通 Profile/getter、分页与归档刷新不写事实状态；点击刷新时仅主动对可信当前上下文做保守观察，不请求 CK3 Effect 或 Provider。
- 对话基底冻结 `disclosureFactEpochsByOwner`，逐 Owner 快照携带 `disclosureFactEpochs`，失败恢复原样保存/恢复，并纳入新快照来源修订哈希。新知情仍下一场生效，不替换本场冻结前缀。
- 更早快照不回退高水位；同日实时明确观察可形成新生命周期，历史/恢复同日冲突不能覆盖。Conversation 来源必须先匹配已提交的 `knownEvidenceRevisions` 再刷新，防止最终会被拒绝的快照先推进事实状态。
