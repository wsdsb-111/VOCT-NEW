## 2. Character schema观察

角色总量为 144,287，来源是 `living=37,026`、`dead_unprunable=91,490` 和 `characters.dead_prunable=15,771`。字段直接出现次数如下：

| 字段 | 直接出现次数 | 备注 |
| --- | ---: | --- |
| `first_name` / `birth` | 144,287 / 144,287 | 基础识别与时间边界候选 |
| `female` | 33,453 | 缺失不能直接等同男性，需 adapter 语义化 |
| `culture` / `faith` | 106,440 / 112,272 | 主要是数值 ID |
| `dynasty_house` | 105,346 | 可缺失 |
| `family_data` | 107,066 | 配偶、父母、子女按记录而异 |
| `alive_data` / `court_data` | 37,024 / 35,379 | 仅部分角色存在 |
| `landed_data` | 5,439 | 不能用来判断所有角色是否有 domain |
| `dead_data` | 107,263 | 只对有死亡信息的角色出现 |
| `traits` | 142,629 | 仍有少量缺失 |
| `historical_id`、`historicalId`、`historical_character_id` | 0 / 0 / 0 | 未发现直接历史身份字段 |

`alive_data.location`、`alive_data.gold`、`landed_data.domain`、`court_data.employer` 与 `landed_data.court_positions` 都存在可用实例，但字段并非所有角色都有。关系和身份适配必须按“存在性 + 值类型”读取，不能直接解构为全字段必填对象。

## 3. 人物解析相关观察

- player record 可读取 birth、gender hint、culture/faith raw ID、dynasty house、spouse、parents、children、domain、location、gold、traits 和 court positions。
- 辛弃疾记录可读取，出生为 `1146.4.28`，当前存档日期为 `1154.1.1`；它是“可从现状数据找到候选”的证据，不是 `historical_id` 证据。
- `first_name=Yuefei_name` 有 4 条记录，分布在三个 bucket，且 field set 不同。按名字建立单值 map 会丢失候选，必须使用 `name -> candidates[]`。
- 死亡角色仍可能保留 family、traits、culture/faith 和 death reason；dead pruning 不能等价为“不可见”或“非历史”。

脱敏 fixture 位于：

- `scripts/fixtures/v8.4/fixture_character_historical.txt`
- `scripts/fixtures/v8.4/fixture_multi_yuefei.txt`

## 4. Title 与 realm

`landed_titles/landed_titles` 有 20,504 条记录。一个选定的 current title record 有直接 `holder` 和 13 条 `history`：最新记录为 `appointment_succession`，上一条为 `appointment`。全局 title field union 显示 `holder`、`de_facto_liege`、`de_jure_liege`、`history`、`heir`、laws 等并非每条都有。

因此 title adapter 可以先做 `title id -> holder/history`，再由 `e_`/`k_` 等 title key 构造有限的 `realm -> ruler` 候选；不能把一个 title 的 holder 自动扩展成完整政治关系图。

## 5. War 与 history

`wars` 顶层在本样本只确认 `active_wars` 和 `names`。active entry 148 个，其中 107 个对象、41 个 `none`。对象 field union 为：

```text
attacker, battle_results, called_to_war, casus_belli, defender,
name, reached_max_score_date, start_date, variables
```

没有发现统一的 `end_date`、`result` 或顶层 `ended_wars` / `war_history`。所以“过去十年某 realm 与谁作战”不能从本样本直接回答，必须标记为 `NOT_FOUND` 或等第二个数据源。

脱敏 fixture：`scripts/fixtures/v8.4/fixture_title_history.txt`、`scripts/fixtures/v8.4/fixture_war_history.txt`。

## 6. Schema 设计输入

1. 所有 ID 在 normalized layer 保持 string，避免大整数和 key/value 类型差异。
2. 日期同时保存 raw string 和经过校验的 calendar value；无效日期必须进入 `UNKNOWN`，不能按 JS Date 猜测。
3. 角色候选采用数组，不使用同名覆盖；身份 evidence 与当前状态 evidence 分离。
4. 任何缺失 field 都要在 adapter 输出中保留可诊断的 absence，而不是填入“未知男性”“无配偶”等推断值。
5. `triggered_event` 等重复顶层 section 需要 stream parser 的 occurrence model，不能只保存最后一次。
