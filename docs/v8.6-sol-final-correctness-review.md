## 结论

Terra 已把 Character Knowledge 接入唯一的服务端生产 Prompt 路径；Sol 复审期间又关闭了两项会造成 NPC 全知或时间穿越的缺口，并把验证提升到真实 `PromptBuilder` 消息级。代码边界可以进入实机验收，但生产开关仍默认关闭，且 Electron、CK3、真实 Provider、真实 usage 与远端 CI Gate 尚未完成，因此本结论不是发布冻结签字。

## Sol 复审修复

### P0：普通人物姓名与战争被过度公开

- 普通存档人物姓名由 `PUBLIC_WORLD` 降为 `COURT_PUBLIC`；远方陌生 NPC 不再仅因查询命中而知道任意角色姓名。
- 地点继续为 `COURT_PUBLIC`；头衔持有人继续为 `REALM_PUBLIC`。
- 战争开始/结束、重要人物去世、头衔变更统一要求可验证的角色范围锚点并按 `REALM_PUBLIC` 审批；缺少角色锚点时不生成可公开事实。
- `PUBLIC_WORLD` 仅保留玩家明确标为公开且通过检查点时间门禁的 Supplemental 条目。

### P0：旧历史内容只贴标签、未执行时间门禁

- Phase B 不再复制 legacy `period.context`、`notableEvents`、`notableFigures`。
- 适配器从结构化 Historical Baseline 按检查点年份选择 period，并通过 Temporal Gate 逐项筛选事件与人物。
- 未来条目、缺少日期/活跃窗口的条目全部保守排除；1126 年检查点不会看到 1127 年靖康之变或无时间证据的岳飞条目。
- 检查点日期无效或适配器不可用时返回 `null`，由现有 Prompt 兼容路径使用 legacy 四字段；new 与 legacy 不会同时注入。

### P1：测试未到 Provider 可见 Prompt 边界

- 新回归使用真实 `PromptBuilder.buildMessagesWithTokenCount()` 组装 provider messages。
- 断言 `worldline-subjective` 恰好出现一次。
- 断言旧背景、旧未来事件、未授权帝王/头衔/年号不进入生产 Prompt。
- 断言时间边界文本和 responder-scoped 世界事实实际进入 provider 可见消息。
