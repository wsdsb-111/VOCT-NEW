## 已实现

- 新增 `memory4-profile.js`，由 Memory4 Coordinator 提供只读查询入口：按 Campaign × Owner × Entity 读取 Known Entity Index 与未删除的 Memory4 Detail 指针；只在 Legacy Bridge 已确认 Owner/Campaign、且摘要元数据明确指向该 Entity 时提供 Legacy 指针。UNKNOWN 仅表示证据不足，关系单独可确认认识；同场不升级为直接交谈，仅提及仍是 MENTION_ONLY。
- 当前关系只从 Owner 的 CK3 Runtime 关系/配偶记录按需读取；当前 alive/location 取实时 GameData 而不是可能同日已过期的年度 Checkpoint，先核对战役/日期，再经现有 Worldline `classifyKnowledge()` 门禁。缺资料、过期或跨战役则不填当前事实，不把缺失关系解释为 neutral。索引指针以 revision 缓存，实时关系/生死/地点不缓存；提供显式索引缓存失效入口。
- 关系变化检测仅接受前后两次已确认、同战役同人物对且日期有序的关系状态及 `CK3_READBACK` 已确认效果。ACK、未知前态、跨战役不能触发；原因未被可见来源证实则为 unknown。此检测结果只作为未来 Durable 提取的优先级信号，不生成事实或推测原因。
- `Conversation` 的初始读取及动作确认刷新经同一个 `parseLog`/`GameData` 路径送入 B 观察器。观察器仅比较来源文件稳定、关系块完整、战役一致的两次 CK3 debug.log 解析结果；重复解析、未完成的多行关系、日志轮换、倒退及缺失关系均不推断变化。只把本场动作确认回读中检出的变化交给 Memory4 Finalization，按 Owner 可见的原文片段提高 Durable 提取顺序；不把关系类型或未知原因写进提取文本。失败恢复快照保留这一优先级提示。
- 复查中修正了将年度 Checkpoint 当成实时关系/生死/地点前提的过严判断：年度 Checkpoint 可能早于当前游戏日；当前事实以同战役实时 GameData 及既有 Worldline 授权判断为准。关系判定还要求前后回读序号严格递增，避免把同一帧 ACK 或重复解析当成变化。

## 隔离和限制

- **未接入实时 Prompt、旧摘要生成/恢复、Recent2、现有 Legacy/Temporal Recall 或正式 Memory4 Recall**，未修改旧摘要存储格式、缓存锚点和 Provider 调用顺序。新增的恢复快照字段仅供 Memory4 消费；旧摘要生成不读取它。
- 画像只持有指针，不作为新磁盘事实源。无可信 Campaign Token 或实时 GameData 的调用将拒绝实时字段。Year/Life 指针仍为空，留待 D 阶段。只有代码/夹具层生产接线证据，尚不得宣称真实游戏关系变化实测通过。
- 2026-09-28 后续核对：关系 Action 的 `RUN_ACK` 确认路径当前不主动请求新的完整人物关系日志；既有 Action 脚本只写效果，不附带新 `VOTC:IN/new_relations` 数据。因此“观察器已接到生产解析入口”不等于“一次关系 Action 后必有新关系回读”。实机 B Gate 必须有可核验的新 CK3 关系日志；仅有 ACK、应用内反馈或同一旧日志不能算通过。该日志生产问题未在本轮 Action 选择提示修复中解决。
