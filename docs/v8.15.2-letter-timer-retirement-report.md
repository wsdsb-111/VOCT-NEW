# V8.15.2 旧信件计时管道退役报告

日期：2026-10-08。用户反馈鼠标移动轻微卡顿，并要求停用已不用的旧信件管道。本轮不把代码冗余直接等同于已确证的鼠标卡顿根因。

## 排查结论

- 新全局桥每两秒直接输出 DATE，但仍额外执行 `letters.txt` 和正式 `votc.txt`；旧 runner 即使因新桥注册而执行空字符串，GUI 状态计时循环仍存在，并在创建时设置全局 `blur`。
- App 在待投递启动、日期 stale 和 conversation-close ACK 时仍可写旧日期载体、排队 `.9998` rearm；剪贴板触发还会请求旧载体重读 payload。游戏发信选项已经执行 `log_gamedata_v3l` 输出完整资料，这条旧请求不再必要。
- 五秒只读进程采样中，VOTC 主进程消耗约 1.97 CPU 秒，相当于一个逻辑核的 39%；CK3 约 7.08 CPU 秒。不是整机 CPU 百分比，也没有调用栈/帧时间证据把这些占用归因到某个计时器。近期 App 日志未见 rearm 或 restart 风暴。

## 精准改动

1. `letters/letter-manager.js` 的恢复入口改为仅报告 `NATIVE_BRIDGE_WAITING`，不写日期载体、不排队 rearm；删除 payload 的旧 `letters.txt` 请求。同日 DATE 保留健康心跳与投递检查，只减少重复日志输出。状态面板默认检查正式 `votc.txt`。
2. 新 `votc_runtime_bridge.gui` 保留两秒周期中的一次只读 DATE、一次非对话场景正式 Run File 轮询，删除旧文件执行。对话中日期仍读取，文件执行仍归既有对话 consumer。
3. `letters_runner.gui` 删除全部计时状态、执行命令及 blur 设置，保留透明空窗口名；`votc_invisible_event.gui` 不再创建旧 runner。既有事件仍可引用惰性兼容窗口，但不会恢复旧循环。after-lobby 不再延迟启动旧 runner，保留一次 DATE 与独立载入边界。
4. App 与 Renderer 同时禁用 A1，A2 不再等待旧 A1；A3/B/C/D 的执行标记、可见结果和忙碌门禁不变。IPC 与历史诊断记录保留。

历史旧运输辅助函数及旧命令 ACK/TTL 识别保留，供已有证据安全核对，不再由生产日期/发信流程调用。没有删除或改写实际待投递信件、接受锁、队列、载体、摘要或恢复任务，也没有重寄信件。前轮信件回执、双方姓名/关系来源与幂等记忆归档保持。
