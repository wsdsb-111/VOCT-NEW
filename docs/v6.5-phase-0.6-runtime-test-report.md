## 🎯 唯一根因分析

虽然有 14 个测试案例，但根本问题只有 **4 个独立根因**：

### 根因 1: Player/NPC Runtime 独立性 ⚠️

**影响案例**: A, B, C (3个)

**当前问题**:
```javascript
const actionMessage = this.pendingPlayerActionMessage ?? placeholder;
```

**v6.5 修复要求**:
- Player message 独立评估（对 Player character）
- 每个 NPC reply 独立评估（对各自 NPC character）
- 禁止 `??` 二选一逻辑

**测试状态**: SOURCE_CONTRACT_CHECK 确认风险，RUNTIME_TESTABILITY_GAP 无法验证运行时行为

---

### 根因 2: ActionEvent[] 结构测试 📋

**影响案例**: D, E, F, G, Order, Dedupe (6个)

**当前限制**: 只能测试 `string[]` categories，无法测试：
- 独立 Event 结构
- Evidence span 隔离
- executionStatus vs resultStatus
- Event 顺序
- Event-level dedupe

**v6.5 修复要求**: Event-based 架构

**测试状态**: FUTURE_REQUIREMENT (当前 category 检测通过，但无法测试 Event 结构)

---

### 根因 3: Gold Gate 覆盖率 ✗

**影响案例**: I (直接), J (间接)

**当前问题**: "我现在把50金币交给你" 未触发 `gold` category

**v6.5 修复要求**: 提高 gold 关键词召回率（现在、把...交给）

**测试状态**: GOLD_GATE_COVERAGE_FAILURE

---

### 根因 4: 假设语境识别 ✗

**影响案例**: H (直接), J (间接)

**当前问题**: "如果我杀了他" 被识别为真实事件

**v6.5 修复要求**: Event Parser 识别假设标记词（如果、也许、可能）

**测试状态**: KNOWN_V6.4_FAILURE

## 🎬 v6.5 正式验收清单

以下是 **v6.5 重构必须通过的验收标准**：

### P0 - 核心语义修复 (5项)

- [ ] **否定死亡 + 实际受伤** (Phase 0 Case 1)
  - Stage 2 不再扫描完整原文
  - 只处理 Positive Evidence "刺伤了他的手臂"
  - 禁止 characterIsKilled，只允许 isInjured

- [ ] **否定罢免 + 实际骑士任命** (Phase 0 Case 6)
  - 只处理 "被任命为骑士"
  - 禁止 isFiredFromCouncilOf，只允许 isEmployedAsKnightBy

- [ ] **否定离开 + 实际进入** (Phase 0 Case 7)
  - 只处理 "进入了王座厅"
  - 禁止 leavesConversation，只允许 changeLocation

- [ ] **假设死亡被排除** (Phase 0.5 Case H)
  - "如果我杀了他，也许会惹麻烦" 不触发 death_or_injury
  - 假设标记词被 Event Parser 识别

- [ ] **Gold 召回率改进** (Phase 0.5 Case I)
  - "我现在把50金币交给你" 必须触发 gold category

### P0 - Player/NPC 架构修复 (3项)

- [ ] **Player message 独立评估** (Phase 0.5 Case A, B, R1, R3)
  - Player message 对 Player character 评估
  - 不替换 NPC reply

- [ ] **NPC reply 独立评估** (Phase 0.5 Case A, B, C, R1, R2, R3)
  - 每个 NPC reply 对各自 NPC character 评估
  - 不依赖 pendingPlayerActionMessage 存在与否

- [ ] **禁止 `??` 二选一逻辑** (SOURCE_CONTRACT_CHECK)
  - 移除 `pendingPlayerActionMessage ?? placeholder`
  - 建立独立 Player 和 NPC 评估路径

### P1 - Event-based 架构基础 (6项)

- [ ] **ActionEvent[] 输出** (Phase 0.5 Case D, E)
  - Stage 1 输出 `ActionEvent[]` 而非 `string[]` categories
  - 每个 Event 包含 `{ eventId, category, evidence: { text, start, end }, executionStatus }`

- [ ] **独立 Evidence Span** (Phase 0.5 Case D)
  - "刺伤了卫兵，随后离开大厅" 拆为两个 Event
  - Event 1 evidence: "刺伤了卫兵"
  - Event 2 evidence: "离开大厅"
  - 禁止单个混合 Event

- [ ] **execution vs result 分离** (Phase 0.5 Case F, G)
  - Case F: executionStatus=completed, resultStatus=failed
  - Case G: executionStatus=attempted/failed_before_execution

- [ ] **Event 顺序保持** (Phase 0.5 Case Order)
  - "拿起酒杯 → 刺伤卫兵 → 离开大厅"
  - Event 顺序严格 1 → 2 → 3
  - 禁止重新排序或 Set-based 收集

- [ ] **同 category 不同 target 保留** (Phase 0.5 Case Dedupe)
  - "刺伤第一个卫兵，随后又刺伤第二个卫兵"
  - 生成两个独立 injury Events
  - dedupe key 考虑: speaker + category + evidence + target

- [ ] **Event-level identity** (Phase 0.5 Case E)
  - Event identity 不只由 category 决定
  - 支持多个相同 category 的独立 Events

### P2 - 安全性改进 (1项)

- [ ] **High-risk actions fail-closed** (已有 Phase 0 测试)
  - characterIsKilled / isImprisonedBy target 缺失安全失败
  - 已通过，保持覆盖
