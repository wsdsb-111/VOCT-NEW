# V8.6.1 Sol Stage 1 — Prompt / Memory 兼容性合同

> 审查日期：2026-09-06  
> 输入基线：V8.6 Sol Stage 6 `CODE REVIEW PASS` 代码  
> 本阶段结论：`SOL STAGE 1 CONTRACT = FROZEN`  
> V8.6.1 总冻结：`NOT READY`

## 1. 本阶段边界

本阶段只冻结 V8.6.1 的 Prompt 顺序、Memory 兼容、全局预算、事实优先级、Secret 和失败隔离合同，不提前替 Terra 改写 `PromptBuilder`、`Conversation`、Memory Engine 或 Worldline 核心实现。

生产开关继续保持：

```text
subjectiveWorldMode = DIAGNOSTIC
promptIntegrationEnabled = false
```

在 Prompt 调序、Global Headroom 和真实 Provider Cache 回归全部通过前，不得翻转默认值。

## 2. 当前真实调用链与已确认缺口

当前 `Conversation` 先从最后一条用户消息构造 `query`，分别调用：

```text
MemoryEngine.retrieveForResponder()
MemoryEngine.retrieveTurnRecall()
WorldlineService.getSubjectivePromptContext()
PromptBuilder.buildMessagesWithTokenCount()
LLMManager.sendChatRequest()
```

审计确认：

1. Memory Core 使用 `min(2400, max(800, contextLimit * 0.08))`，Memory Turn Recall 固定为 256 Token；Worldline 随后独立检索，尚未消费统一的 `remainingContext`。
2. `worldline-subjective` 标记为 `stable: false`，但由 `insertPreHistoryContext()` 在 History 和 Current User 之前注入。查询变化会让它之后的长 History Prefix 失去 Provider KV Cache 复用机会。
3. Prompt 元数据以第一个 `stable: false` 块计算 `stablePrefixEndPosition`。当前更早的 participant、Memory 和 scene 块也可能先被标为动态，因此仅移动 Worldline 不等于整条前缀已经稳定；Terra 必须用真实块序列验证第一个动态点，而不能只检查 Worldline 出现次数。
4. Worldline 构建异常目前会记录 warning 并继续对话；此 fail-open-to-memory 行为正确，必须保留。
5. `directObservationFactIds` 当前为空数组；它不是 Stage 2 为了调序可以伪造的数据。

因此本阶段判定：V8.6.1 的 P0/P1 风险已复现，V8.6 当前默认关闭是必要保护。

## 3. Prompt 顺序合同

Terra Stage 2 必须将生产 Prompt 收敛为以下语义顺序：

```text
Stable Cache Anchor
Stable Character Prompt
Stable Memory
Frozen Direct Relationship Memory
Frozen Mention Snapshot
Stable World Context
Session Topic Anchor
Presence / Scene
Conversation History
Current User Message
Memory Turn Recall
Worldline Turn Recall
```

硬约束：

- 所有依赖本轮 `query`、实体命中、rank、Supplemental、Delta 或 responder 主观筛选结果的 Worldline 内容都必须位于 Current User 之后。
- 新动态块使用唯一 ID `worldline-turn-recall`，并明确标记 `stable: false`。
- `worldline-stable` 只能包含与本轮查询和 responder 无关、在声明缓存生命周期内字节稳定的 Campaign/Checkpoint 锚点、时代边界和 Temporal Safety Rule；不得含人物命中、位置、头衔、战争、Delta、Supplemental、Secret 或主观事实。
- 空 Worldline 召回不生成空占位块，也不改变既有 Memory 块顺序。
- Prompt 中不得同时保留旧 `worldline-subjective` 与新 `worldline-turn-recall` 正文；生产 Worldline 事实恰好零次或一次。
- `stable: true` 是可验证的字节稳定声明，不因块名含 `stable` 或 `frozen` 自动成立。缓存生命周期、responder、conversation、checkpoint 或配置变化时必须正确失效。

## 4. Memory 兼容合同

V8.6.1 冻结以下 Memory 行为：

- `retrieveForResponder()`、Direct Pair、Mention Route、Session Topic Anchor、Turn Recall、Rolling Summary 和 Consolidation 的选择逻辑不主动修改。
- Memory Store、Ranker、Recall Cache、摘要文件格式和人物目录不迁移、不重写。
- Worldline 只能使用 Personal Memory metadata 判断知情，不得复制 Memory 正文到 Worldline Prompt。
- Direct、Mention、Topic、Stable Memory 与最近 3 条摘要的 V8.6 fixture selected IDs 应保持一致；输入事实变化除外。
- Memory Turn Recall 继续紧随 Current User，且必须排在 Worldline Turn Recall 之前。
- Context Pressure 不得以新增 Worldline 为理由先删除 Memory Turn Recall 或缩小既有 Memory Core 合同。

## 5. Global Retrieval Budget 合同

Stage 2 的预算仲裁必须由组合根统一执行，而不是让 Memory 和 Worldline 各自假设拥有完整上下文：

```text
globalRetrievalBudget
  ├─ memoryCoreBudget       保持 V8.6 行为
  ├─ memoryTurnBudget       保持 256 Token
  └─ worldlineTurnBudget    仅使用剩余 headroom
```

计算必须考虑固定 Prompt、角色资料、Presence/Scene、Conversation History、Current User、回答保留量和 Provider 上下文上限。文档中的 200–900 Token 是实验区间，不是硬编码合同。

当 headroom 不足时，Worldline 按下列顺序裁剪：

```text
Supplemental
→ 低优先级 Delta
→ 降低 Worldline Top-K
→ 压缩 Worldline 表述
→ 非必要 Historical Background
→ 本轮 Worldline 动态召回为空
```

不得通过删除 Memory Turn Recall 获得 Worldline 预算。裁剪结果必须输出机器可读原因和各阶段 token/耗时，但不得把 Secret 正文写入诊断。

## 6. 跨系统事实优先级

冲突仲裁固定为：

```text
Current Direct Game Truth
> Current Self Fact
> Direct Observation
> Personal Memory
> Scoped World Knowledge
> Supplemental
> Historical Background
```

该顺序决定“当前状态”的回答，不删除历史 Memory。旧摘要中的“过去在开封”可以保留为过去经历，当前存档中的“现在在临安”必须作为当前事实胜出。时间或 Scope 证据不足时不升级为当前事实。

## 7. Secret、作用域与失败隔离合同

- Secret、Personal、Direct Observation 和所有 responder-specific 内容只能进入动态、responder-scoped Lane，不得进入 shared/stable block 或共享正文缓存。
- Renderer/IPC 不得提交 `knownBy`、Presence、Direct Observation 或授权证据；授权仍由服务端计算。
- Worldline Cache 与 Memory Cache 保持独立，cache key 必须覆盖 responder、conversation、turn、query/entity、checkpoint/source、scene/presence 与 knowledge revision。
- Worldline timeout、异常、超预算、旧 checkpoint 或无效 DTO 均降级为无 Worldline Turn Recall；Memory Prompt 和 LLM 请求继续。
- 降级时禁止回退到旧的未过滤 `getPromptContext()` 生产正文。
