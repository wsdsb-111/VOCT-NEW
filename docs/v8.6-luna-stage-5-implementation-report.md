# V8.6 Luna Stage 5 实施报告：Character Knowledge Diagnostics

日期：2026-09-06

## 结论

Luna Stage 5 的安全 Subjective DTO 与诊断 UI 已接入，满足进入 Sol Stage 6 审查的代码条件。生产 Conversation 仍只走既有 `getPromptContext`，`promptIntegrationEnabled` 未改变，Phase A 不会把主观世界写入正式 NPC Prompt。

## 已完成

- 新增服务端 `getSubjectiveResponderOptions`：只从当前 Checkpoint 角色快照提供回应角色候选，服务端搜索、最多返回 50 条，并将当前玩家置于安全默认首位。
- 新增受限 IPC / preload 管线：Renderer 只能提交 `responderId` 与查询文本；`knownBy`、在场证明、直接观察事实、Presence revision 等授权字段不接受来自客户端。
- 世界线诊断页新增“角色认知 / 主观世界”：支持选择单个回应角色，并可选第二角色做 A/B 对照；结果只渲染服务端白名单事实、可读判定、计数、检查点/验证状态和有界的过滤说明。
- Secret 只显示“因回应角色无权知晓而隐藏的数量”，不显示正文、标题、参与者姓名或 ACL；开发者层只显示 opaque `factId`、decision 和 reason。
- 保留原有 Prompt / World Recall 只读诊断、Historical Identity / Worldline Difference 和既有检查点/Worker 状态语义；这次新增 UI 未替换或删除原诊断入口。
- 补充响应式样式，适配小屏宽度及现有 parchment / ink / knight 共享主题变量；三分辨率与三主题的真实 Electron 视觉验收仍留给人工 Gate。

## 安全与兼容边界

Subjective View 由服务端继续执行 `DIAGNOSTIC` 模式、当前 Checkpoint responder 存在性和既有 Subjective DTO 白名单。Renderer 不持有共享候选池、Memory 原文或授权证据，也不能通过 IPC 自行把事实升级为 `ALLOW`。旧世界线概览、历史人物映射、Prompt 诊断和生产对话入口保持兼容。
