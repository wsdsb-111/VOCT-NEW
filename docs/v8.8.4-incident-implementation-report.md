# V8.8.4 关系与动作事故修复

日期：2026-09-12 至 2026-09-13。状态：代码与隔离测试通过；用户已确认儿子/女儿识别恢复。最新动作补丁尚未完成 CK3 实机验收，不能宣称 Full Freeze。

## 证据与根因

1. 用户实际安装的旧英文 pList 以 `sheHe === "he"` 二选一分配 son/daughter，而实时日志使用“他/她”。只改默认模板不会更新被保留的用户脚本。真实输入隔离审计得到 3 男、3 女，旧脚本执行兼容与 Family Fact 均核对通过；没有将未在场亲属插入参与者 Map。
2. 原始队列有 968 条待处理记录：旧日期探针已有写入但缺少 ACK，后续动作与结束命令积压。旧版把 null 过期时间持久化成 0，导致探针永久阻塞。临时副本恢复后待处理数为 0；检查未修改真实队列。随后用户重启实测中可看到新的 action ACK，说明原来的阻塞已解除。
3. 后续实机仍报告金币不符、好感度无效果。对应早期支付日志已被游戏场景切换清理和应用日志轮转覆盖，不能据此断言每一笔支付具体如何失败。源码审计确认以下公共缺陷：
   - Effect Writer 用全部 Character Map 索引选取 CK3 NPC 列表；该列表不包含单独输出的玩家，Map 中玩家位置会影响错误寻址。
   - CK3 `talk_window_counter` 每 0.4 秒读取 `run/votc.txt`。应用只保护“文件写一次”，没有保护“游戏读同一文件只执行一次”，ACK 消费延迟时存在重复 Effect 风险。
   - 金币对照的是会话快照与后来全日志解析结果，不是同命令执行前后的成对快照。
   - 普通 ACK 被当成效果成功；无返回文案的姿态动作在排队时显示 Unknown error。
4. 用户安装的 28 个标准 Action 与项目版本逐文件哈希一致。CK3 模组 `conversation_opinion` 的修正范围确为 -10 至 +10，并有总好感度上限；不能把没有变化一概解释为未执行，也不能只凭 ACK 说已增加 2 点。

## 实现

- `prompts/prompt-script-sandbox.js` 在执行时适配已知旧性别二选一表达式及新版 isMale/isFemale 亲属标签；不覆盖用户脚本，未知或冲突使用中性标签。
- `game-data/log-parser.js` 标记 CK3 实时亲属来源；Current Truth 在没有 canonical 人物时可使用一致的实时亲属性别，canonical 明确未知/冲突不被旁证覆盖。家庭总览不再被 NO_RELATION_INTENT 整块丢弃，最多显示 32 条并明确截断。
- `actions/run-file-manager.js` 给日期探针 30 秒有效期、尚未写入动作 120 秒有效期；兼容旧 null/0。重启时作废恢复出来的零写入旧会话动作，先保存 `.v8.8.4-backup` 原队列。不自动重放已有写入而未 ACK 的动作；有歧义的载体不能清空或跨过。
- 每条新动作的 RunFile 设置 `votc_last_action_command` 全局标记，重复轮询相同命令不重复 Effect。该机制依赖串行队列，不承诺跨回档的分布式 exactly-once；未知写入状态继续 STALLED。
- Effect Writer 在每条动作前清除旧 source/target；NPC 索引排除玩家，玩家 Scope 使用 root。必要角色不存在时不执行正文，并输出绑定失败标记。命令内记录实际 source/target Runtime ID，核验不符不得确认为成功。
- `actions/action-command-readback.js` 异步扫描日志尾部至多 8 MiB，仅接受同一 `ACTION_BEGIN/ACTION_EFFECT/<id>` 到 `RUN_ACK/ACTION_EFFECT/<id>` 内的证据。不会用另一个命令、后续月收入或切换后的会话数据确认本次支付；日志缺失、交错或证据不足返回未确认。
- 金币动作记录双方执行前后余额；按游戏精度核对两边变化，不放宽成任意增长/下降即成功。好感度动作记录指定有向关系的执行前后值；精确变化才 CONFIRMED，没有变化明确提示可能的修正/总值上限。
- 金币在 CK3 执行瞬间再次检查来源资金，不因应用余额过旧而先给收款方造出金币。完成核验后重新读取当前数据供后续动作使用，但确认结论仍来自原命令快照。好感度日志同一 source/target 的新值替换旧值，避免读取数组首条时继续使用旧好感度。
- 普通动作没有专属状态核验时保留 ACKNOWLEDGED，`success=false`、`confirmed=false`，界面明确“仅收到指令、未验证效果”。这不代表所有 28 个动作已经具备效果验证器。
- 结果在对应队列记录的 `actionVerification` 中保留状态和前后值；UI 区分排队、绑定失败、未观察到变化、状态不符、超时与实际确认。移除排队姿态动作的 Unknown error 回退。

## 兼容边界

28 个标准 Action 定义、Prompt block ID、用户脚本文件、Memory Engine 2.6 标签/2.5 存储、世界书事实及用户存档均未迁移。新增 CK3 全局去重标记由新的 RunFile 使用，不需要修改 Workshop 模组文件。应用包 2.0.x 版本与 V8.8.4 功能版本保持分离。

修改了旧测试中“重启可补执行上一会话动作”“玩家占用 NPC 列表索引”“Effect 无 Scope 防护”的断言，替换为本次更严格合同；未跳过发布组或削弱 ACK/金额验证。
